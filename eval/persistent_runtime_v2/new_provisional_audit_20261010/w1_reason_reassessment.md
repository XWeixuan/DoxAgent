# 同一 20 条 Case：W1 的 NEW 理由能否告诉 W2 哪些事实是新的？

## 结论

**能定位多数 Case 中使消息判 NEW 的一部分核心事实；不能把当前 `w1_final.reason` 当作全文逐事实的新旧标签，更不能仅凭它认定 W2 命中的事实为 NEW。** 这里区别两个问题：

1. W1 在拿到当前消息和所召回的 Event Detail 后，能否比较并指出**决定消息级 NEW 的核心差异**？在这 20 条中，多数理由做到了。
2. W2 如果只看到**原文＋W1 的文字理由**，能否判断**自己命中 Policy 的那个事实**已被 W1 判新？这还要求理由明确覆盖那个具体事实。唯一 W2 命中样本恰好不满足这一点；不能由本样本估计更大样本中的命中正确率。

本审查沿用 [第一次审查的同一 20 条原始 Case](./sample.json)，没有重新抽样。额外从远端只读导出每条 Case 冻结的 W1-R2 `event_details`，见 [w1_r2_context.json](./w1_r2_context.json)（SHA-256 `3170C0E0C2D10130F3594B07BC6645BA7D0D6416E32773E907A3BD2C7AE0D128`）和 [导出脚本](./export_w1_context_remote.py)。比较对象是保存的文章正文、W1 reason、W1 当时可见的已知事实，以及 W2 命中理由；没有重新调用模型，也没有外部核验报道真伪。部分正文是消息源保存的摘要或含推荐/评论区内容。

## 审查口径

- **A：可定位核心 NEW**：理由明确给出至少一个由原文支持、足以区分旧事实的主体/动作/状态/数值。不意味着它标出了全文所有 NEW fact。
- **B：部分定位**：理由给出某些新增内容，但另有概括、未经原文充分支持的断言、误把附带内容当核心，或没点名本案关键的 W2 命中事实。
- **C：无法作为事实级 NEW 依据**：理由没有建立明确的新现实差异，而是主要从没有加载到可比事实推断不能判 OLD。

按这个仅评价**理由作为 W2 输入的可用性**的口径，20 条为 A 14、B 5、C 1。它不是 W1 全量准确率，也不说明 A 类的未提及事实为 OLD。每行的日期是 Case 创建的 UTC 日期。

## 对“把 W1 理由给 W2”的具体判断

这能帮助 W2 **发现明显的错配**：例如 #8 的旧 tape-out 与新性能修订，#16 的旧波动率与新解禁数据，#19 的旧 RKLB 数据与新 Starship 里程碑。与现在 W1/W2 独立看原文相比，它提供了一个有价值的对照。

但当前合同只要求 W1 `reason` **简述决定消息级 NEW 的核心差异**，长度上限 1000 字符；`fact_attributions` 是对**已知** Fact 的归因，不是每个原文事实的 NEW/OLD 标注。[W1-R2 提示词](../../../prompts/persistent_runtime_v2/w1_r2.md)明定“至少一个未覆盖的核心事实”即可 NEW，并要求 reason 简述新进展；[W1 输出 schema](../../../src/doxagent/persistent_runtime_v2/schema.py)没有新事实清单。因此：

- **命中事实与理由中某条具体新增命题同义**：可以把理由作为新旧证据之一，再核对原文限定、事实状态与 Policy 条件。
- **命中事实只在原文中、理由未点名**：理由不能证明它新，也不能证明它旧。#5 说明若要求“理由必须明列”会挡下一个看起来确为新修订的命中；若仅凭“同一报告的大类新数据”放行，则没有解决原来的同 fact 问题。
- **理由用“没有加载事实”作为主要 NEW 依据**：#17 说明它不足以给 W2 提供可靠的新事实身份。

所以，**W1 有能力在许多样本中指出新核心事实；当前持久化的 NEW 理由不具备完备、逐项、可绑定 W2 condition 的事实级新旧信息。** 只把 reason 加进 W2 输入，适合作辅助判断，不能独立成为“W2 命中事实已被证实为 NEW”的判据。
