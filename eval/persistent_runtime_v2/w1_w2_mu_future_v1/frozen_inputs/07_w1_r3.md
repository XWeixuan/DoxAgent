# W1 Round 3 — Atomic Fact Extraction

你正在执行 W1 的事实编译轮。

实时判定已经完成。本轮不再重新判断消息是 NEW 还是 OLD，也不决定 Event Library 最终应该创建、合并或更新哪个 Event。

你的任务是：

> 将当前消息中需要进入后续事件记忆更新的现实信息，拆成清晰、独立、可供 Event Library 后续处理的 atomic factual candidates。

## Atomic Fact

Atomic Fact 是一个能够独立成立、只表达一个主要现实断言的最小事实命题。

一个 candidate 应让后续系统即使脱离原文章，也能理解“谁发生了什么事实”。

例如，一条消息同时确认：

- 某客户完成 qualification；
- 商业出货已经开始；

应拆成两个独立事实，而不是写成一个包含多个现实动作的长命题。

事实命题应描述现实本身，而不是解释其投资意义。

例如“该进展强化了公司的 AI 前景”属于解释；“客户已完成 qualification”属于事实。

## capture_mode

### NEW_CAPTURE

当前消息已经被 W1 判定为 NEW。

只抽取构成这次新增现实进展的核心事实。已被前面 Known Events / Facts 覆盖的旧背景不需要再次输出。

目标是完整保留真正新增的事实，同时避免把整篇文章重新拆一遍。

### AMBIGUOUS_CAPTURE

当前消息因运行编排进入保留事实通道，但其 novelty 没有被确定为 NEW。

此时提取消息中具体、独立、值得交给后续 Event Library 判断和去重的核心 factual assertions。

本轮不需要再次决定这些事实最终是不是新的。

## 如何拆分

优先保留：

- 明确发生或被确认的现实动作；
- 状态、阶段或结果变化；
- 明确的计划、指引、预测、否认或传闻；
- 对现实有独立意义的新数值或条件变化。

一个 proposition 尽量只包含一个主要断言。

如果一句原文同时表达多个可以独立变化、独立被证实或否定的事实，应拆开。

不要把背景事实、作者评论、投资判断或因果推演混入 proposition。

## proposition

用简洁、具体、可独立理解的方式表达事实。

保留判断该事实身份所需的主体、对象、产品、客户、阶段或关键数值，但不要复制整段原文。

不要生成 Event ID、Fact ID、Delta ID 或任何 Runtime identity；这些由后续程序处理。

## assertion_state

`assertion_state` 表示消息本身以什么事实状态陈述该 proposition。

按照消息实际表达的状态，从输出合同允许的枚举中选择最贴近的一项。

重点保持以下区别：

- 已经发生或已经确认的现实，不应写成未来预测；
- 计划、指引、预测、传闻、否认等，不应因为内容具体就写成 `ACTUAL`；
- 不要把消息没有表达的确定性或状态补充进去；
- 如果文本确实无法可靠映射到某个明确状态，使用 `UNKNOWN`。

对于含义相近的允许枚举，只依据消息实际表达选择，不自行创造额外语义差别。

## 时间

`occurrence_date` 和 `subject_time` 表达不同概念。

### occurrence_date

事实本身发生的日期。

只有当前消息明确提供、并能支持该事实发生日期时才填写；无法可靠确定时使用 null，不猜测日期。

### subject_time

该事实所讨论、适用或指向的业务时期。

例如：

- FY2027 Q1
- 下一季度
- 2027 年
- 某未来产品周期

这些属于 subject_time，不是 occurrence_date。

例如“公司预计 FY2027 收入增长”中，FY2027 是该预测指向的业务时期，而不是预测这一事实发生的日期。

## entities

只列出直接参与该 atomic fact、并有助于后续识别现实 occurrence 的主要实体。

优先包括事实中的核心公司、客户、供应商、机构或明确的业务主体。

不要把文章中出现的所有名称都当作 entities。

## 完成标准

输出应：

- 覆盖当前 capture mode 下所有值得保留的核心事实；
- 将可以独立成立的事实拆开；
- 每条 proposition 只承担一个主要现实断言；
- 保持消息原有的事实状态与时间语义；
- 不加入消息没有提供的新事实或投资解释。

本轮只完成事实候选编译，不再次进行新旧判断。
