## 投影前审查

逐一检查 20 例内的 32 个 canonical Event 加载记录、240 条 Facts、34 条 provisional，并核对摘要、标题、实体列表及时间字段。大 Event E4 的全部 141 Facts 也已读取。

采用统一、版本化的 `title + 全部 Facts`，不生成 Context，不发送两份摘要和 entities。不假定所有未来摘要都逐字重复：例如 BE/E114 的摘要另有 Bloom 作为主要供电方的叙述，而 F242 主要是客户账单抵扣方案。这段信息不是识别该 Event 所必需的背景，也不能伪装成 F242 的精确事实证据；保留其 Event title 和真实 F242。其余样本的摘要核心状态均有标题及 Facts 承载。未来同样按版本规则投影，不在线做相似度猜测或调用模型决定删减。

34 条 provisional 命题均有足以识别主体的名称；实体列表中的简称、报告机构或主题标签未发现必须另补一行才能消除的指代歧义。例如 INTC/E2683 没有在命题中重复 Magen David Adom 的报告机构，但地点、Intel 与伤亡事实身份完整。AMD/Helion 的主体、机架、产品及发布时间均在命题/subject_time 中。

原有 `_wire_cell` 会合并空白，不能无损表达正文换行；本轮使用独立反斜杠转义。Fact 日期不回填 Event 日期，90 个空 subject_time 保留空格位，11 个 SAME 保留。原消息及内部完整 Event 对象保留。

正文实际清理仅命中 5/10/12 例的 Tom's Hardware 分享栏及 20 例的精确 feed 导航。第 12 例紧邻分享栏的已识别目录随模板去除；正文中再次出现的评测章节完整保留。第 20 例保留日期、11:16 AM EDT、标题及事实正文；不删除紧邻标题的时间行或混有标题的 feed 计数行。其余来源的新闻背景、行情数字、更新声明、版权说明未扩大清理。

## 质量结论

- 20 例优化隐式组与原输入成功回执 verdict 一致 16/20，与历史 Qwen 一致 19/20；同优化输入的标记组一致 19/20。它们是判定一致率，不是准确率。
- 全部优化首轮及标记组 20/20 通过 Schema、Event/Fact 范围校验。未发现由丢失 Fact、时间、状态、主体或正文导致的可确认误判。
- 不能宣称“质量无退化”：11 的 OLD 有漏判风险；8/15 的多股核心范围、13 的归因事实、20 的引用完整性均应进入提示词回归。此次仅实现输入优化，不修改判断标准或自主重写 gold，不把模型切换扩成生产上线。
- 补测 2 的 NEW 与同输入首轮 OLD、13 的新/标记翻转证明单次小样本存在生成波动。性能和成本下降不等价于这些语义问题已解决。
