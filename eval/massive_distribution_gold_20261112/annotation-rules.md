# Massive Distribution 本轮 GOLD 标注合同

权威依据：用户本轮请求、`docs/massive-distribution-business-and-regex-debugging-guide-20261112.md`，以及既有 `docs/by-distribution-gold-annotation-rules-v2-20261028.md` 中不与本轮冲突的业务尺度。本轮只标注，不开发/应用规则，不调用 Decision Model。

## 决策单位与标签

以冻结新闻的 `title + summary + body` × 目标 ticker 为单位。逐篇读完完整有效输入；不要联网补写事实，不把标题筛选层当 GOLD。多 ticker 共享一篇文章时分别判断；同类事实保持同尺度。

每对输出：`pair_id`、`ticker`、`label`、`category`、`reason`、`mixed_topics`、`confidence`。

- `label`: RELATED / IRRELEVANT / INSUFFICIENT。
- `category`: DIRECT / INDIRECT / INDUSTRY_BACKGROUND / IRRELEVANT_TEMPLATE / INSUFFICIENT。
- DIRECT、INDIRECT 对应 RELATED；INDUSTRY_BACKGROUND、IRRELEVANT_TEMPLATE 对应 IRRELEVANT；INSUFFICIENT 对应 INSUFFICIENT。
- `reason`: 中文，指出原文的实质事实，以及目标业务联系或排除边界。INDIRECT 必须说明可解释的竞争/客户需求/供应/技术依赖/政策等联系，不只写“产业链相关”。
- `mixed_topics`: boolean，正文存在独立且有实质意义的多条新闻时标记，不把导航、公司名单和免责声明算独立消息。
- `confidence`: HIGH / MEDIUM / LOW；有事实但边界存疑时用低置信标签，不把边缘争议一律写信息不足。

## 判定原则

1. 目标公司/核心产品的实质事件，以及同类产品市场的供需、价格、产能、技术、经营、政策、采购、竞争变化，可以相关。无需点名目标 ticker。
2. Massive 全市场稿件多，尤其要区分“新闻主体及独立正文事实”和“公司介绍、覆盖公司名单、报告广告、赞助名单、关键词模板”。仅在市场报告的公司清单看到目标公司，或把 Coherent Market Insights 误作 Coherent，不能判相关。
3. 不按体裁排除：市场报告若确有对应产品市场的独立数据、趋势或技术事实，仍可相关；融资、诉讼、投资者通知、正式活动、研究及早期计划也可能相关。实际针对目标公司/同类竞争市场的诉讼事实或期限，不因为招揽文案重复就自动排除；单纯大名单模板及无实质联系的提及应排除。
4. 间接联系需要原文事实支持，处于容易解释的业务近邻；不把任何 AI、云、能源、半导体、量子、国防文字推成全产业链需求。不要求证明目标厂商拿单、显著影响、方向、交易价值、新颖性或项目已兑现。
5. 保留既定业务边界：具体大规模算力采购/租赁、数据中心新建扩容及项目风险可构成计算或供电/互连需求的近邻；不能把一般 AI 应用发布、无用途的融资、泛政策或单件器材广告自动等同于实际算力项目。不得新增“必须列设备订单/CPU厂商”门槛。
6. 技术变化看原文改变的具体产品路线、资源要求、部署方式和关键依赖；普通算法或应用提效不能自行上升为全部硬件需求。
7. 仅在有效内容确实不足以判业务时用 INSUFFICIENT；这些输入已具备留存 FULL/SHORT_FULL 标识，但标识并不能保证所有正文内容都足以判断。坏正文、纯跳转/验证页等不能臆测事实。

## 执行与保存

- 只使用 `gpt-6.1-terra`、high reasoning，无模型降级，无再次派生子代理。
- 生产正则命中结果、原词表、标题抽样分层和既有其他 GOLD 对标注者隐藏。输入包只含完整证据、目标及ID；包中split仅作数据归属，不改变尺度。
- 完整阅读后逐对写标签，分批保存并核对 ID；不要用关键词程序、另一个模型或只读标题替代 GOLD。程序仅用来分页读取、保存既已作出的判断、检查完整性。
- 每包输出 `annotation/labels-NN.jsonl`。中断可以续写同文件；重启前检查已完成ID，避免重复/覆盖。所有包均须完整交付，不能只给“量大未完成”的最终回复。
- 不向主代理发送验证集具体文章、标签、理由或坏例，只报告进度及文件完整性；开发集也只需回报统计。主代理负责最终包装及单独隔离两集。
