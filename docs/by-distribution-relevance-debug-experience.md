# By Distribution 相关性调试：共享经验

这是唯一的调试经验账本。一次 ticker 级调试用一个 session，正则和 Decision Model 的多轮 attempt 都更新同一条记录；不另建每轮、每 ticker 的经验 MD。具体文章、行业判断和候选表达式保留在对应输出目录，本文保留可迁移的一般经验。

## 初始资料：有问题，必须批判阅读

起点是用户提供的 [旧监测词作者资料](C:/Users/WEIXUANXIE/Desktop/message-bus-monitoring-terms-authoring.md)，仓库亦有 [旧副本](message-bus-monitoring-terms-authoring.md)。它产出的规则质量并不稳定，不能作为正确性证明；以下只提取仍有效的部分。业务相关性以 [GOLD v2](by-distribution-gold-annotation-rules-v2-20261028.md) 为准。

保留的起点：

- 从真实新闻的稳定业务用语出发；强信号可直接匹配，模糊词补最少的消歧条件。不要给每个强词都加“订单、价格、产能”等事件条件。
- 公司及竞品需要区分多元业务；一般商业词不能独立承担相关性。上下游联系看原文业务关系，不靠枚举整个产业链公司。
- 优先短而可读的 literal/regex；每个新增表达式应有实际语料或重复坏例依据。注意 Unicode、空白归一化和子串误匹配，不能把英文单词边界机械套到其他文字。
- 从 FP/FN 中提炼可复用的修正；单篇异常文章不应变成一长串特判或黑名单。
- 模型定义表达业务范围及最近的混淆边界，而非翻译另一份关键词清单。

明确删除或修正的旧要求：

- **不固定产出英文、繁中、韩文。** 按本次实际启用绑定和来源声明计算所需语言；回放仍遵循正式实现的“入口语言规则＋已有英文规则”。旧示例中的三语 YAML 不是当前硬要求。
- **不把消费评测、行情、分红、纪念或通知按体裁整体排除。** 看有效正文事实；独立的混题消息可以召回，页面导航标题不能冒充实质正文。
- **不要求严格经济传导证明、显著影响、信息新颖或已兑现。** 这是 Recall-first 初筛，不提前替研究/交易模块筛选。

## 结合现有实现与 GOLD 的补充

- 正则和模型是补充放行关系；模型不能撤销正则误放。两块要独立测 P/R，不能把合并后的召回率当某个模块的能力。
- 先固定输入、来源语言和基线版本，再研究偏差；正文版本、来源上下文或生产词表变了，差异未必来自本轮改动。
- 不把未运行、接口失败、缺分数、准入拒绝或 `INSUFFICIENT` 当负例。接口故障先修复或重试同一候选；不能靠遗漏失败项抬分。
- 标签有疑问时另记待复核，不在调参过程中为了过线改 GOLD。
- 开发阶段只看调试集。验证反馈限定在 SOP 的一次额外修正；其余候选冻结后才统一验证。验证参与最终择优后，其分数是选择参考，不是无偏泛化成绩。
- 共享经验只记录一般方法，不写验证集具体文章、答案、关键词或行业补丁，避免向下一次开发传播验证答案。

## 复盘记录写法

每轮调试集跑完后，由 Codex阅读指标和坏例，整理“误差机制 → 可迁移的修正原则 → 是否被本轮结果支持”，再用脚本 `note` 更新本 session 的同一段。下一轮可以增补、合并或删改结论；指标表自动保留所有 attempt，最终形成一条合并复盘。不要把仅出现一次的现象写成已经验证的普遍规律。

同一时刻只让一个编辑者更新本文件，避免并发覆盖；无需引入调试状态机。
