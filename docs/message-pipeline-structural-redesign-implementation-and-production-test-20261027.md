# 消息管线结构修复实施与生产实测（2026-10-27）

## 当前交付边界

按《结构性排查报告与架构优化方案》实施。此文件先记录实现与验证，正式发布、固定观测窗口及实际指标将在本轮继续追加；以下离线测试不能证明生产已达到99%周期覆盖、10秒交付或80%真实正文。

## 已实施的结构改动

1. 新增正式 `v2-message-collector`，复用现有适配器、单元定义、物理请求限流和 Site 身份，不再由 Bus 的业务 writer、接纳收尾或 Read 水位驱动网络启动。端点/查询/必需频道各自调度；共享源的相同物理单元共享请求，其消费者保留同一真实 request ID。容量按当前物理请求需求计算，没有固定9 ticker阈值。
2. 小型 `acquisition.sqlite3` 保存单元 checkpoint、配置代际、薄当前状态、逐周期证据与待交付增量，不装通用 NativeContent/CDC。空/未变列表不创建业务 capture；语义指纹包含来源、绑定、条款和接纳版本。未知发布时间首次建立后稳定保存。已验证页面先持久化，随后分页失败不抹掉真实列表证据，也不把它冒充完整分页覆盖。
3. 采集与 Bus 至少一次交付：Bus 的 capture 唯一接纳键、现有接纳/分发任务同事务提交，随后确认采集账本。确认前崩溃可重放；未确认的变化增量不能被新列表覆盖。旧 checkpoint、去重、正文复用和 ARTICLE_ONCE 保留。
4. 移除接纳空闲循环每秒扫描/清理历史；新采集历史在独立小账本按索引读候选、32键短批删除并限定总时间。旧大库技术历史保留，不在线整库重写/VACUUM。显式发布迁移替代多个角色运行时DDL。
5. 轮询技术表退出业务CDC；Read按薄 transport header 越过已退休技术历史，保留业务事件顺序和完整归档路径。源卡直接读取独立薄 head，标注观察时点，采集距今取最旧必需频道；不以RSS掩盖浏览器频道。业务消息依然按真实 Stream/Read 时点验收。
6. Site普通请求及恢复/接替检查的同步 Registry I/O 进入线程工作单元，取消不能提前释放必要所有权门禁；ACCESS_RESULT/CAPTURE_CONSUMED有界异步批写，队列/丢弃数可查看。API入口统一monotonic预算；登录、挑战、维护独占及旧代际 fencing 保留。
7. BODY瞬时写竞争在任务边界恢复；队列年龄不再冒充下载超时。恢复/预算/存储延期保留具体续作阶段，缺失或零恢复间隔不再每秒重走HTTP；续约只更新租约列。实际claim token/status变更仍拦截旧执行。新正文走独立前台候选索引，旧文重检最多一个槽，独立小预算补充更新并对持续失败退避；共享和ticker正文更新保留原消息修订、不重复触发已消费消息。
8. 可延期研究/初始化新工作与非实时维护按CPU、内存及I/O压力延后；持久化运行Owner不增加新准入门禁。生产有在途W3时不重启Worker；相关新策略是否已经部署会单独列明，不能把本地代码当成生产生效。
