# P4 留存规则重新审计（2026-10-13）

用户要求：不保守、不过度设计、不过度防御；远端低价值内容直接删，不用备份。P1–P3 按原方案完成，随后执行本方案，替代原 P4。

## 修订后的 P4

1. **低价值直接退役。** 旧维修快照、完成施工的 shadow、失败施工临时文件、无依赖的本次试验镜像，在完成结果验收后直接删除，保留小型操作收据。无需先备份这些副本。旧备份只在确认不是当前业务路径、没有进程/容器依赖、对应维修已经完成后退役。正式业务原件不因“低价值”的笼统标签删除。
2. **备份在生产入口收尾。** 成功的正常迁移将一致性数据库快照压缩并逐流核对 SHA，校验后删除未压缩副本，只保留最新一套该入口管理的压缩回滚备份；下一次迁移成功后删除此前已完成的同类备份。失败/未完成迁移不清理，非该入口登记的目录不扫删。日常同版本重启沿用已有 schema-current 快速路径，不再备份。空间估算采用含 WAL 的实际 SQLite 页数及会复制的 content/native/receipt 文件，默认施工余量由 20 GiB 调整为 2 GiB；压缩若不足 1 GiB 余量即停止并清掉本次未完成压缩文件，保留源快照。使用 SQLite backup，保留一致性与恢复契约；不引入备份数据库、通用资源治理框架或人工确认门。
3. **日志在创建时限额。** 初始化修复和消息源修复的 Docker 创建入口使用现有生产策略 json-file、20m、3 份。现有运行容器自然在下次正常重建时采用，不为立即省几百 MiB 中断研究。正式服务当前已有轮转继续使用。
4. **镜像收尾限定到发布拥有的资源。** 本轮施工的中间镜像在最终镜像验证后按精确 ID 退役；运行/退出容器引用、Guardian 动态镜像与模板、可读新 receipt-packs 的回滚镜像保留。不装每日全局 image prune，不把 Containers=0 当成唯一删除条件。
5. **复用现有容量报告。** 将现有只读 storage_report 补齐实际备份入口。P2 的 GC/transport 服务继续承担技术历史生命周期；不另装 Codex heartbeat、低收益高频巡检或笼统任务磁盘配额。

D 盘保留已经校验的正式恢复集。此前已经制作的拒绝历史归档不因新指令重复搬运；后续同类确定低价值的重复终态技术记录直接按窗口回收。没有为它们安装自动转存任务。保留长期业务原文仍需容量规划，本轮不以自动丢业务历史解决。

## 验收

旧快照删除有明确路径、理由、实际字节与无句柄检查；迁移成功/失败分支有针对性验证；新容器启动参数出现轮转选项；线上 GC/transport 与业务继续运行。区分代码已经部署与现有容器尚未正常重建的参数生效范围。一周自然业务增长验收仍待后续观察。

实施结果：旧维修副本实际直接删除 9,890,166,609 bytes；Migration/Transport R9 和 Guardian R2 已窄发布。Linux 实库 fixture 完成压缩、校验、恢复及旧成功集退役 smoke。Guardian 实际创建容器 smoke 揭示原基线没有 Docker CLI，已用专用 Dockerfile 补齐 Docker 27.5 CLI/插件，复测真实容器 json-file/20m/3 参数、退出和收尾通过。动态研究 agent 镜像及活跃 Worker 保留；现有 Worker 的轮转参数等待正常重建生效。没有为了测试执行额外全量迁移备份。详见 [执行记录](disk-repair-execution-20261013.md)。
