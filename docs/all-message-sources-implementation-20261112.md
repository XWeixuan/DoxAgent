# 全部消息源目录实施与验收

## 交付范围

- 全局目录 `/message-bus/sources`，复用唯一全局顶栏；全局入口与消息总线视图入口均可进入。
- 全部登记源保留，包含停用、未订阅和测试源；按全局/有序 L1 分区，每源一张卡。1262px、1559px 均三列，无页面横向溢出。
- 静态分类位于 `src/doxagent/message_bus_v2/source_catalog.json`：105 源、附件 V5 的 13 项 L1。主方式、备用方式分别维护，列表和正文分别展示；订阅、启停与分发模式直接使用现有事实。已纳入并行会话 b246dc753 的 Bloomberg Latest HTTP-only 实现。
- 抓取方式、阶段、分发方式、适用行业和全局/行业属性均本地筛选；同维度多选 OR，跨维度 AND。备用方式需显式勾选纳入筛选。行业筛选保留通用源，多行业源只出现一次。
- 卡片展示最近成功、当天新增、平均端到端耗时、真实抓取延时、P95 端到端耗时、实际刷新间隔、正文补全成功率。无样本保持缺失；不适用正文补全不显示 100%。
- 全局审计入口统一为“收益 / 成本审计”；调整其控件、指标与表格排版，不改变成本/收益计算。

## 数据口径和资源边界

新 GET `/api/doxagent/v2/message-bus/source-catalog` 不创建视图、不要求 view_id；首次进入、离开后再次进入及手动刷新各发一次请求。无自动重试、分钟刷新、焦点/重连刷新、后台续期或逐消息源 HTTP。刷新失败保留上次卡片。

1. 对每个真实订阅复用文章配额：首次发现时间 24h 内至少 5 篇取该窗口最近最多 20 篇，否则取最近 5 篇；一次 SQL 批量定位，每绑定最多读取 20 条 metadata。复用 article_sample_keys 与 current_identity，不扫描正文或历史。聚合后不再按消息源截成 20 条。
2. 正文按 source + canonical article 去重；端到端/真实抓取延时保留各 Ticker 的实际发布观察，直接合并原始样本求均值/P95。当天新增累加当天既有 bus_messages 桶，同文发布到不同 Ticker 分别计数。
3. 最近成功取各订阅最大成功时间，不冒充全部正常；状态分别汇总运行/休眠/禁用/异常/未知。实际刷新间隔合并各订阅已有逻辑轮次间隔与样本数，不将不同 Ticker 同时完成当作 0 秒轮询。
4. 配置、绑定、文章事实及当天桶使用同一 Read 连接，采集头和轮次复用同一 Acquisition 连接。运行状态复用原 source_status，IR/SEC 策略不变。状态计算只取当天交易日事实，优先复用 Runtime 已存日历，不为目录计算前一交易日及全周期边界。
5. 无新表、索引、持久化聚合、后台任务、采集写入、模型调用或历史回填。API 沿用查询池，目录使用既有 detail_seconds 预算。原内部只读 MCP 令牌路由范围未扩大。

维护流程见 [消息源分类维护说明](message-source-classification-maintenance.md)。未知新源仍显示在“未标注消息源”，不自动猜测行业/抓取路径。

## 验证证据

- 后端定向 38 项通过：目录聚合、零值/缺失、共享正文去重、Ticker 样本加权、历史 FULL 无 status 的兼容、路由鉴权、无 view_id、严格参数、原消息总线配额及绑定/OpenAPI 回归。
- 浏览器 10 项通过：目录 3、成本审计 2、收益审计 2、消息阅读稳定性 3。覆盖 1262/1559、分类组合、备用路径、跨行业、停用订阅、手动刷新失败保留、首屏失败与空列表区分、虚拟时间推进/焦点/重连不发请求、离开再进入重新取数。
- 前端 schema 生成、TypeScript 与生产构建通过；新增 Python 文件 Ruff 通过，diff 无空白错误。新增 UI 组件使用已有 radix-ui，无新依赖。
- 生产数据只读预发布探针：105 源、285 订阅；完整 cold 0.858s / hot 1.276s；tracemalloc 临时对象峰值约 7.18 MiB；JSON 约 153KB。开启 tracemalloc 的请求会变慢，其 5.13s 不当作普通请求耗时。探针无生产写入，数据为当时快照，非持续 SLA。
- 浏览器使用固定 fixture 验证显示和交互；生产规模探针验证真实数据、合同和读取成本。两者不冒充已登录生产浏览器端到端验收。
