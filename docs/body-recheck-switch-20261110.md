# 正文 recheck 总开关：实现与业务审查

日期：2026-11-10（北京时间）。依据用户提供的 `body_recheck_current_state_survey_20261110.md`。

## 开关与边界

`DOXAGENT_CONTENT_ENRICHMENT_RECHECK_ENABLED=false`，默认关闭；在生产 `.env.v2` 改为 `true` 并重建相关后端进程即可重新启用。沿用现有配置系统，不增加 UI、API、表或任务状态。

关闭的是任务语义 `work_kind='recheck'`：普通定时扫描、同一未变化列表的到期重入，以及新旧队列中已排队/租约到期的普通复查。旧任务和检查时间保留，暂停期间不领取、不清库、不伪造成功/失败。停用前已发出的访问、已下载且待提交的有效结果允许按现有所有权/版本检查正常收尾。

首次正文补全、同轮网络/预算重试、`content_update` 和站点/域名恢复后的 `capability_resume` 保持原逻辑。后者在访问层也可能显示 `work_class='recheck'`，因此不能以该标签必须归零作为验收。关闭时不再把普通复查错误转成新的恢复复查；已有恢复续作仍保留。

## 实现

- Settings → Message Bus factory → Repository 传入单个布尔值。
- LiveRepository：阻止普通定时/列表重入；所有领取路径（包括过期租约）排除 recheck，恢复续作可继续。
- 旧管线：关闭到期 pump；领取时同样排除普通复查，包含过期运行任务。
- 旧正文缓存：关闭时，兼容且输入提示不变的 FULL/SHORT_FULL 不因半小时复查时间到期而重新下载。语言、权限范围、输入变化及订阅预览质量保护仍有效；正文取得时间不刷新。

## 业务审查结论

1. 采集目标间隔、新闻入场时效、原发布时间、去重身份和交易执行逻辑均未调整。
2. 开关只阻止可选重复工作，不阻断首次抓取和同轮重试；明确内容更新仍可推进版本与投递。
3. 关闭不增加 revision、不重置已发布/不相关判定、不重放既有消息，已有完整正文继续可读。
4. Live 投递以已有 result_ref 为条件，不依赖普通复查执行完成，因此暂停旧 recheck 不会因其 FETCH_DUE 状态阻断已有结果投递。
5. 跨源与跨 ticker 复用保留权限/语言约束，不把已知旧正文当成当前新发现的新闻，亦不把不完整正文升级为 FULL。
6. 预期能力损失：没有标题/摘要/原生内容等明确更新信号的正文静默修订，不再定时发现。属于本次暂停的明确取舍。
