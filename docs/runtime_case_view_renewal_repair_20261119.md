# Runtime Case 列表快照续期修复（2026-11-19）

## 根因

生产浏览器实际捕获到 `快照已过期，请手动刷新`，调用栈位于页面上下文刷新的
`Promise.all`。不能因独立新建视图的接口能正常返回，就判定用户打开的旧页面没有问题。

Runtime 有两类视图：页面/链路图最初固定的视图，以及每分钟刷新指标、Case 列表后产生的独立视图。
原通用刷新函数只知道“原页面视图 → 新页面视图”的映射，却会在发布新上下文前，
重新请求所有活跃模块。Case 列表若已切到另一分钟视图，该视图不会被替换成新视图。
它过期后请求返回 `VIEW_EXPIRED`，`Promise.all` 整轮失败，新上下文也无法写入前端缓存。
先前为空的列表便可能一直停留在旧空快照；手动刷新和自动续期都会受影响。

这是前端刷新依赖错误。某个 ticker 当天恰好没有数据，不能解释其他已有 Case 的 ticker 也不显示。
本轮确认后端当天 ONDS/RKLB/SNOW 分别能返回 5/8/5 条 Case，前一天各 ticker 均能正常返回记录。

## 最小修改

- 为 `usePageContext` 增加可选的 `refreshReads: false`，仅 Runtime 使用。
- Runtime 续期/手动刷新直接发布新上下文，再由指标、链路图和 Case 列表各自按照新 query key 读取。
  不再把旧分钟视图请求成功作为刷新前提，一个模块失败也不会阻止其他模块换到新上下文。
- 保留并发刷新时的上下文版本检查，不覆盖更晚完成的刷新。
- 其他页面沿用原行为。统计周期、Ticker 筛选、真实空结果、分页范围、导出快照均未被放宽。
- 不新增 API、数据库读写、持久化或轮询；一次完整刷新仍是上下文及原有模块的必要请求。
