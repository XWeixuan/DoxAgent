# 对冲整数配仓与共享预算优化方案

日期：2026-11-05（北京时间）。状态：方案，尚未实施。

本轮仅更新本文档，不修改交易代码、账户额度、ticker 配置或生产任务，不重试 INTC 旧意图，不提交订单。

## 1. 目标与本轮决策

目标：在整组资金、整数股和合理对冲比例的约束下，优先形成可成交的组合，消除固定分腿金额上限造成的额外拒绝。

统一规则：

1. 目标配比沿用用户根据 ticker 相对于对冲指数的 Beta 确定的数值。执行容差统一为**固定 ±10 个百分点**，独立于目标配比；初始规划和主仓成交后的对冲计算使用同一口径，不叠加相对容差或双重容差。
2. 保留主仓理论额度上限，防止把未使用的对冲预算转给主仓；取消对冲腿独立固定金额上限。
3. 对冲可以使用主仓整数取整、较好成交价或部分成交后留下的整组余额；两腿始终共享同一笔授权预算。
4. 先在允许范围内争取更多主仓股数；主仓股数相同时，选实际比例最接近目标的对冲股数，再以较少对冲股数打破平局。
5. 对冲开启时，初始计划仍要求主仓、对冲各至少一股。固定 ±10 个百分点是本轮最终容差，不额外叠加“半股容差”，不自动降级为无对冲开仓。
6. 主仓已经成交后，对冲因价格、整数股或执行异常无法完成，继续保留主仓及原退出责任，不强平主仓，不借机增加主仓。

第 5 条明确了前序讨论中降级方案的取舍：本轮采用“合理范围内成交”，不把偏离目标超过 10 个百分点的组合也算合格。预算真的不足或整数比例确实无解时，仍可合理拒绝；不承诺所有信号都能下单。

## 2. 勘察结论与修改依赖

### 2.1 已确认的问题

- `planning.integer_pair()` 同时约束总预算、固定主仓上限、固定对冲上限和严格比例。主仓留下的余额无法补足对冲，存在总预算足够且比例合格但仍被拒绝的情况。
- `repository.reserve_attempt()` 在主仓成交后仍读取旧 `plan.hedge_cap`，可能因对冲报价上涨几美分拒绝整股对冲，即使实际总预算有余额。
- `planning.hedge_quantity()` 使用相对 ±10%，与初始规划的容差必须一起改；只改其中一处会留下第二道拒绝。
- `groups.advance()` 目前把各腿超出旧分腿上限的金额累加到组预算。共享预算上线后如不改这里，合法使用主仓余额的对冲会被误算成额外占用，影响其他交易名额。
- 当前无解失败只留下原因码，缺少原始预算、报价和整数候选摘要，难以精确复盘。

现有整数搜索与原业务约束的独立穷举结果一致，尚未发现原算法漏解。本次修复对象主要是约束设计及关联资金核算。

### 2.2 复用的执行架构

沿用：Runtime 意图 → 持久接收 → 账户资金授权 → MAIN ENTRY → 撤单与成交对账 → HEDGE ENTRY → 原退出生命周期。

配仓继续是纯 Decimal 数学函数；预算和 attempt 在既有数据库事务中核定；订单仍走现有提交、等待、撤单、对账和恢复路径。无新增服务、表、定时扫描、后台可行性监控或优化求解器。

必须一起修改的依赖：

| 位置 | 本轮修改 |
|---|---|
| `src/doxagent/trade_execution/planning.py` | 统一固定 ±10 个百分点；按共享余额搜索；成交后增量对冲计算 |
| `src/doxagent/trade_execution/repository.py` | 保存组可用预算与费用保留；HEDGE 按主仓实际成交和整组余额授权 |

## 3. 金额与比例口径

定义：

| 符号 | 含义 |
|---|---|
| G | 本次交易组获得的授权预算，包含既有费用保留 |
| F | 按现有规则计算并冻结的费用保留 |
| B = G − F | 两腿可使用的名义金额预算 |
| r | 用户按 Beta 确定并配置的目标“对冲名义金额 / 主仓名义金额”；执行端不重新推导 Beta |
| Pm、Ph | 当前规划价格，沿用现有积极限价、价格档位取整与参考价来源 |
| M、H | 主仓、对冲仓的正数名义金额；卖空也取正数，不用卖空收入冲减预算 |
| δ = 0.10 | 固定比例差，即 10 个百分点；不乘以 r |

合格比例：

```text
|H / M − r| ≤ δ
等价于：|H − r × M| ≤ δ × M
金额下界 L = max(0, (r − δ) × M)
金额上界 U = (r + δ) × M
```

例如目标 20%，实际允许 10%–30%；目标 29%，允许 19%–39%；目标 66%，允许 56%–76%。各 ticker 的容差均为上下各 10 个百分点，不随目标配比变化，也不作用于 ETF 股价。

金额非负，因此 r≤10% 时下界按 0 处理，但对冲开启时仍要求实际对冲数量为正，不能因为 0 落入数学区间就跳过对冲。上界不机械截为 100%，因为用户按 Beta 确定的目标本身可以大于 100%。

主仓理论上限继续为：

```text
main_cap = B / (1 + r)
```

这是本轮保留的预算分配规则。对冲理论金额 `B − main_cap` 只可作为解释字段，不再作为 HEDGE 的硬上限。

初始规划检查 `M + H ≤ B`。主仓 ENTRY 终结并完成对账后，对冲可用总额为 `B − M_actual`；已成交对冲金额从这笔余额中扣除。此处 M_actual 是本交易组 MAIN 的累计 ENTRY 成交名义金额，不随行情浮盈亏变化，也不包含个人持仓或其他策略持仓。

费用仍按现有账本归属和规则核算。F 是既有估算保留，不宣称实际佣金必然等于 F；本轮不建立新费用预测模型。

## 4. 首次整数规划

### 4.1 可行域与选择顺序

在以下条件下寻找正整数 qm、qh：

```text
qm ≥ 1，qh ≥ 1
M = qm × Pm
H = qh × Ph
M ≤ main_cap
M + H ≤ B
|H − r × M| ≤ δ × M
```

选择顺序为：qm 最大 → 对冲金额与 r×M 的差最小 → qh 更小。它不会为了追求比例完全相等而放弃允许范围内更大的主仓，也不会用“花完预算”替代比例要求。

### 4.2 轻量算法

```text
从 floor(main_cap / Pm) 开始，逐个减少 qm：
    M = qm × Pm
    L = max(0, (r − δ) × M)
    U = (r + δ) × M
    low  = max(1, ceil(L / Ph))
    high = min(floor(U / Ph), floor((B − M) / Ph))

    若 low > high，检查下一 qm。
    否则，在 [low, high] 内检查最靠近 r×M/Ph 的相邻整数，
    选偏差最小者并返回；无需穷举所有 qh。
所有 qm 均无解时，返回真实的初始组合不可行结果。
```

使用 Decimal 和整数上下界，包含比例边界，不引入“忽略几美分”的浮点 epsilon。合理成交靠共享预算和允许比例实现，不能靠暗中超预算。

复杂度 O(主仓最大股数)、额外内存 O(1)，只在订单规划时执行。先采用可审查的线性下降搜索，不增加缓存、异步求解或后台循环。

**不得直接复制旧算法的跳跃减股公式。** 旧算法中的对冲金额上限固定；新算法的 `B−M` 会随 qm 减小而增加，旧跳跃可能漏掉更大的可行主仓。

必须覆盖的反例：B=$1,400、r=40%、Pm=$100、Ph=$222，允许范围 30%–50%。10＋2 超预算，10＋1 比例过低；正确最优是 **9＋2**，总额 $1,344、比例 49.3333%。套用旧跳跃思路、用当前对冲股数上界与新下界计算跳步时，可能从 10 直接跳到 7，漏掉 9。

### 4.3 首次规划失败

区分：主仓理论额度不足一股、整组不足以形成两条正整数腿、比例范围内没有整数解。保留既有结果分类需要的原因码，并在诊断摘要中明确子原因。

初始无解仍不发任何一条腿，释放本次未形成持仓的名额。不得只因比例无解而持续等待价格变化、复活旧意图或临时关闭对冲。

MAIN 后续重报价继续沿用现有数量目标和剩余额度处理，不因对冲余额扩大而增加主仓目标；报价变化、部分成交后是否仍能对冲，由下一节按真实成交重新计算。本轮不增加“每次 MAIN 重试必须重新通过双腿盘口”的准入条件。

## 5. 主仓成交后的对冲

### 5.1 释放条件与预算

保持 MAIN ENTRY 终结、原订单状态与实际成交已确认后才释放 HEDGE。主仓实际零成交时，不创建对冲委托。

在现有 `reserve_attempt()` 事务内，从自身有效成交账本重算：

```text
M = 主仓累计实际成交名义金额
S = 对冲累计实际成交名义金额
L = max(0, (r − δ) × M)
U = (r + δ) × M
R = B − M − S
```

R 是可再投入的名义金额，不是券商卖出所得现金。真实账户资金/保证金约束仍同时适用。不能用展示用浮盈或 IBKR 合并净仓推导 M、S。

每次后续对冲尝试使用最新规划价格 Ph，原对冲订单先完成撤单与成交对账，再计算增量。

### 5.2 增量股数

- 若 `S > 0 且 L ≤ S ≤ U`：已进入合理范围，完成对冲 ENTRY，不为了更接近精确目标继续补单。S=0 不能认定为对冲完成，即使低目标配比的 L=0。
- 若 `S > U`：不再增加对冲，记录实际比例超过上限；保留已有仓位及退出归属。本轮不新增反向卖出再平衡。
- 若 `S < L` 或 `S=0`：计算允许新增的整数范围：

```text
low  = max(1, ceil((L − S) / Ph))
high = min(floor((U − S) / Ph), floor(R / Ph))
```

范围内按新增后 `S + q×Ph` 最接近 `r×M` 选择股数，平局选较少股数。

若 low>high，或预算已经不足，则本次剩余对冲无法合格补齐；记录具体原因及当前实际比例，结束该对冲 ENTRY，不强平主仓，不将未完成对冲标成成功。实际发出的未完成订单仍先撤单对账，已有部分成交继续保留退出责任。

这是一条顺序执行策略，不能保证主仓价格改善、部分成交、对冲价格变化后始终存在有效整数解。方案消除人为固定分腿上限，不掩盖真实无解。

### 5.3 部分成交与异常边界

沿用最多三次 ENTRY 下单机会、每张默认等待 5 秒、主动撤单和撤单确认机制。已经实际提交的对冲仍按既有规则有限重试；已满足范围则提前完成。

不把规划阶段的无解当作已发订单，不凭空消耗三次委托机会，也不因此新增无限制规划重试。主仓已有部分成交时，即使最终配比未达标，其自身退出义务始终成立。

若主仓迟到成交或成交更正导致 M 变化，继续使用现有组推进与对账机制处理。对尚未终结的 HEDGE 按新 M 计算，旧在途订单先处理 resize/撤单；已终结 ENTRY 不因新规则自动重开。实际偏差进入诊断与原退出责任。

## 6. 组预算占用必须同步修正

### 6.1 正常占用

交易组从获得授权至原生命周期结束，继续占用其原授权 G；不因为 MAIN 部分成交或对冲尚未提交，就把余额借给另一个 ticker。CASH 两名额、每名额最多当日策略权益一半的规则不变。

`grant_usd`、`reserved_open_usd` 等 job 字段只表示组内执行额度与剩余估算，不能在组预算 G 之外再重复加到资金占用中。

### 6.2 额外占用

对于新配仓策略，`groups.advance()` 不再使用“MAIN 超 main_cap ＋ HEDGE 超旧 hedge_cap”累加超额。

只按整组有效 ENTRY 名义额判断：

```text
extra = max(0, M_actual + H_actual − B)
accounting_budget = G + extra
```

HEDGE 合法超过原理论分配额、但整组仍在 B 内时，extra 必须为 0。这样不会产生虚假占用、误挤占第二个 CASH 名额。

上述 extra 是对真实成交、迟到成交或更正造成的实际占用记账，不是扩大授权。任何新增委托仍只能使用原 B 的剩余额度；实际已超授权时不追加 ENTRY，继续处理对账和 EXIT。

MARGIN 卖出限价不能约束实际最高成交名义金额，卖空成交可能高于估算价。继续按实际正数名义额记录占用并使用既有保证金检查；不把空头所得当作新增策略资金，不扩展复杂风险模型。

## 7. 数据、版本与展示

### 7.1 新记录

在现有 execution/plan payload 增加少量字段：

- 新配仓策略版本（例如 `allocation_policy_version=2`），在新 execution 接收时冻结。
- `hedge_tolerance_pp=10`、G、F、B、主仓上限、规划数量和名义金额。字段明确使用“百分点”单位，计算时 δ=10/100，不再与 r 相乘。
- 最近一次规划诊断摘要：主仓/对冲规划价、参考来源与时间、比例上下界、整数候选边界、实际或预计比例及失败子原因。

失败摘要必须在“创建 attempt 前失败”的分支也保存；每个 job 更新一份最近摘要即可，不存逐 tick 历史、不新建审计表。不能把重建的历史报价标成当次原始输入。

新 plan 不继续用名为 `hedge_cap` 的字段表示固定硬上限；对冲上限按实际主仓成交动态计算。旧记录的原字段保持可读，不批量改写历史。

### 7.2 生效范围

新策略版本只赋给上线后新接收的 execution。已有执行组继续按创建时的策略版本完成 ENTRY/EXIT；缺少新版本字段的历史组按原语义读取。只保留一处必要的历史读取/计算分支，不提供新的 LEGACY 交易入口或前端模式开关。

INTC 本次旧 execution 与所有终态失败 intent 保持失败，不回放、不重新入队。已有持仓账户、资金归属和退出配置不变。新规则不影响 EXIT 所需读取与恢复。

### 7.3 前端最小改动

不增加容差滑块、策略模式选择或新页面。若现有页面有相对容差帮助说明，统一更新为“固定 ±10 个百分点”，不简写为含义不明的“±10%”；在现有 case/执行详情中使用已有详情区域显示原因摘要、目标比例与实际比例。

`EXECUTION_ACCEPTED` 仍只表示接收成功；规划失败要显示“预算与整数股约束下无合格组合”及关键数字，不显示成券商拒单或已完成对冲。

## 8. 示例与其他 ticker 的影响

### 8.1 INTC 旧例仅作离线回归

采用此前历史盘口重建的示例规划价，不声称是当次未保存的精确原始输入：B=$473、r=29%、Pm=$60.09、Ph=$57.83。

新比例范围 19%–39%，主仓理论上限仍约 $366.67。6＋1 比例过低，6＋2 超预算；5＋1 与 5＋2 都合格，其中 5＋2 距离目标约 9.4956 个百分点，略小于 5＋1 的约 9.7522 个百分点。按“主仓最大、同主仓时比例最接近”排序，最优为 **5＋2**：

```text
主仓：5 × $60.09 = $300.45
对冲：2 × $57.83 = $115.66
总计：$416.11 ≤ $473
比例：38.4956%，在允许范围内
```

这里“最接近”只在主仓股数相同的候选中比较，不表示优先牺牲主仓股数来逼近目标。这笔旧交易仅用于回归，绝不触发真实补单。

## 9. 实施顺序与必要验收

1. **先冻结业务样例。** 写入初始规划、成交后对冲、预算占用的独立期望，避免测试复制旧固定分腿约束。
2. **修改纯规划函数。** 统一固定 ±10 个百分点，共享预算、选择顺序、Decimal 边界及无解分类；用独立穷举校验。
3. **修改事务授权及组占用。** 保存 G/F/B 和策略版本；主仓后动态余额；同时修复 `groups.advance()`，不可拆成两次不兼容上线。
4. **接入执行与诊断。** 沿用状态机、撤单对账、重报价、三次 ENTRY 和 EXIT 恢复；失败发生在 attempt 前也保存摘要。
5. **做必要回归与 PAPER 验收。** 先完成确定性回归，再在正式实施阶段安排新的、仍有效的 PAPER 测试任务。新单必须属于测试任务，不回放生产旧意图。
6. **统一 review 后部署。** 发布包含规划、repository、groups、executor 的一致版本；核对运行代码与新策略版本。Live 上线验收以只读配置、版本、账本和自然新意图为依据，不能据此自动提交真实测试订单。重要代码修改追加根目录 changelog。

必要验收矩阵：

| 类别 | 必须证明的行为 |
|---|---|
| 整数规划 | 总预算内、主仓上限内、两腿正整数、距离目标不超过 10 个百分点；主仓最大，同主仓时比例最接近 |
| 独立搜索 | 新预算约束下的独立穷举与实现一致；包括动态对冲余额增加时不漏解 |
| 边界 | 恰好预算上限、恰好比例上下界通过；真正超出一分钱不被 epsilon 放行 |
| 真实修复样例 | 上述 INTC、MU、两美分、9＋2 四组结果正确 |
| 部分成交 | MAIN 只成交部分时按实际金额计算；主仓零成交不发对冲；HEDGE 已成交金额不重复计算 |
| 对冲补单 | 已有正数对冲且在范围内立即完成；低于范围只补剩余；已超过上限不追加、不触发新再平衡 |
| 容差单位 | 不同 r 均上下各 10 个百分点；r≤10% 时即使 L=0，零股/零金额对冲仍不算完成；目标超过 100% 不被机械截断 |
| 资金占用 | HEDGE 超理论分配但总额不超 B 时不增加组预算；两 CASH 名额不串用；费用与未完成订单占用不丢失 |
| 订单恢复 | 在途/撤单未知时不重复发单；重启后不重新领取预算；仍最多三次 ENTRY |
| 账户与方向 | CASH 正股/替代资产＋买入 ETF，MARGIN 买入/卖空组合；空头收入不增加授权；个人仓位不参与配比 |
| 原退出 | 对冲未完成、部分成交和原组状态都保有正确退出归属；EXIT 不受新比例准入限制 |
| 新旧版本 | 新组固定 ±10 个百分点，旧组不被无声迁移；旧 FAILED 不复活；已有持仓退出继续 |
| 诊断 | 无 attempt 的失败也能读到当次预算、参考价格、范围、候选和明确原因 |

本次方案修订后，已在内存中按固定 ±10 个百分点运行数学原型，并与独立穷举比较 **1,875 组输入，全部一致**，覆盖 1%、5%、10%、10.01% 等低目标及超过 100% 的目标；INTC 最优 5＋2、MU 最优 1＋3、新 9＋2 反例和成交后两美分示例均已重算。这只验证方案算术，尚不代表生产实现、撤单恢复或 PAPER 成交验收通过。

## 10. 整体 Review 与范围

- 解决固定对冲额度、相对容差随目标变化、主仓成交后重新配比、预算重复占用四个关联问题；统一采用 r±0.10，不再用相对容差乘数或双重容差。
- 无条件扩大额度、初始零股对冲、容差外降级、持续动态再平衡均不纳入本次方案。
- W1/W2/W3、REALTIME 延迟保护、交易意图过期、禁交易日期、盘口门槛、订单类型、等待时间与重试次数、退出策略核心不变。
- CASH 两名额、独立策略资金、已结算现金，MARGIN 最小开仓与保证金检查、账户隔离和持仓归属继续生效。
- 数据只加到现有 payload，计算只发生在现有订单规划/对账时，前端仅必要说明和详情，不增加常驻服务器任务。
