### 1. 全量连读→内层截断→外层再截断→补读，是确定的公共低效路径

**53/53 首批工具返回带截断标记，107/442 批有截断标记；51/53 多批读取控制合同。**原生抽查直接确认，不仅是分类器推断。

RKLB 代币化股票 case `case_9d52460dac224be88de14e65465eb520` 首批一次 cat AGENTS、task、schema、Skill、Reference。原生返回同时带有 `original token count: 46835` 和 `24028` 两层截断标记：命令输出先按内层限额截断，外层 exec 又截断。下一批改用 Python 打印 task 字段，再读 schema/Skill/Reference，仍有截断标记。

这条因果链的文件/调用证据明确：不是仅凭“读了两次”便认定模型忘记。首批许多必要内容没有完整送到下一轮，补读在当前协议下部分是恢复行为。提高输出限额会把更多全文送入后续每轮，不能作为唯一修复。

宿主 `sdk_runtime.py` 的通用引导仍要求先读 attempt 的 AGENTS/task；W3 Template 又已经加载公共指令、Case user prompt 已含任务数据。因此下一轮优化需要同时对齐宿主的 W3 专属引导和 Skill，不能只用低优先级提示词要求 Agent 忽略既有引导，也不能改掉其他治理节点的读合同要求。

### 2. 局部文件很快，昂贵的是定位、修补和多轮消费

典型路径是先 find/ls，再读 index，再 grep D1/D2，猜 JSON 字段后再次读 Unit。9 个 Case 有工具输出错误线索，包括 3 个 SyntaxError、文件不存在/目录误读以及一个 timeout 词；这些是候选，未全部等同于业务失败。

人工确认的 RKLB 代币化 case 有一次真正的 JS `SyntaxError: Unexpected string`，外层仅 109 ms；修正语法后再次发出同组查询。下一 usage 锚点距错误返回约 2.749 秒，不是 provider 纯推理耗时。因两段代码的引号不同，现有“完整代码 hash 相同”没有识别它；**0 个 exact-repeat 候选绝不等于无重复往返**。

## 下一轮优化顺序与边界

1. **最高优先：修复控制消费协议和双层截断。**W3专属引导承认已冻结/继承的公共指令，不重复 cat 整份Skill/AGENTS；首批只确认必需任务/输出契约，Reference与研究按问题定位切片。输出预算同时覆盖命令与外层exec，目标是控制定位合并为一批、恢复性补读和首批截断归零。保留文件全文、版本pin、Schema验证和异常时按需重读，不通过删数据或仅调大输出上限“解决”。
2. **高优先：业务收敛与增量研究。**明确对象不相关或决定性拒绝已成立时停止次要补搜；同主题已有可信研究时只核实当前增量、身份和时间有效性。必须保留可能改变结论的原发/传导核实；不加“搜索最多N次”、统一超时NO_TRADE或盲目跨Case复用。
3. **并行小修：减少手写复杂JS和文件结构猜测。**给出稳定路径、局部目录和正确调用样例，避免目录当文件、字段猜测及引号错误。先修确定的失败往返，不重建工具平台、不解析/改写任意生成JS。
4. **次优先：单独验证最终综合/输出阶段。**尾部锚点p90=47.621秒，需检查重复论证、写作负担和max档位的必要性。当前全是NO_TRADE，缺alpha/HIT对照；尚不足以把所有Case换模型/降档，也不能承诺改输出就必然省47秒。
5. **完善观测语义。**将“提到行情/Policy”与“真正调用provider/读取资产”分层；在保留hash的同时用实际工具参数结构形成语义签名，区分语法失败的未执行调用与真正重复研究。模型间隔继续保留前后业务关联与unknown，不把它强行分摊成研究耗时。

下一轮验收继续使用自然流量，按路由/模型/研究版本与业务结果分组；HIT、真正意图和行情链路必须补齐后才评价这些路径。对历史alpha/badcase可另作质量对照，但不能代替本轮实时Web的耗时样本。

## 观测成本及关闭结果

53条原生起点均找到，无截断扫描、非法行或行数上限命中；53 job全部ACK。初版4条job引用缺失的问题已保留为历史边界，独立回执完整；补修版49条引用由原终态保存。原始回执与中间快照保留，不重写为“修复后的历史”。

最终仅提交数据、分析脚本与文档，不重建/部署，不修改业务库、模型、Prompt/Skill或交易逻辑。本轮有效关闭以及自动化PAUSED分别留证。
