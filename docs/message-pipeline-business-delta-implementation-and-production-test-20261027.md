# 消息管线业务增量与 I/O 优化：实施及生产实测

日期：2026-10-27（北京时间）。对应方案：`message-pipeline-business-delta-io-and-latency-optimization-plan-20261027.md`。

## 1. 实施范围

- 列表进入持久化前计算业务输入指纹。相同未完成输入只有一个 leader；后续物理请求保留独立回执并关联处理结果。已判定旧输入在写 payload 前过滤，只保存新输入和实质变化。指纹保留来源/绑定/词表/接纳版本、日期依据及未知业务字段，仅去掉明确的请求追踪噪声；未完成、不完整分页及 CLOSED_SWEEP 不被误当作完成。
- per-unit checkpoint 分表写入，单个 unit 的 checkpoint 不再跟随其他 unit 重写；定向读取只展开目标 unit。兼容聚合保存仍会读取同绑定 unit，尚有进一步减读空间。Owner 保留完整 checkpoint；CDC 只传健康、计数、必要端点摘要及正文任务小字段，正文内容仍由 Owner 完整保存。正文对象按内容复用，变化的时间戳包装不再复制正文。
- 修复 L2 续作旧 token 重放：只领取未完成交付、重新移交所有权、心跳续租，已终结交付不重复判定。READY 分发独立补槽；正向 L2 结果立即发布，其他 ticker 独立收尾；去掉 L1 已确定正向后的默认实验模型调用。判定、现行配置核对、发布、交付回执合并为一个有 fence 的业务事务。
- BODY 上报后台收尾、清理有界低频执行，容量告警合并为一笔事务并节流；保留新正文优先和原 CRAWLER/BODY 容量，不扩大浏览器全局页数。
- 修正陈旧 due 的当前时隙归属，历史缺失周期仍计入分母；已有 on_page 回执后不再追加无物理响应的空 terminal capture。保留 Cache-Control/Age 等响应证据。
- 修复 generic publisher 在 scoped runtime 下原站导航误拒绝：验证公网 URL 后，只允许原 hostname 及 www 规范变体；无关域和私网仍拦截。保留既有身份、出口、风险恢复和付费权限。
- Site command 快照按真实 profile/catalog revision 缓存；idle 扫描批量取 scope，公开 publisher 空闲生命周期缩短至 180s；不重启 Chrome Supervisor。Reuters 单独、显式配置源/Site 上限 2 和 1.5s 请求节奏，沿用已验证同身份容量 2，不全局放大。
- 缺失语言采用来源语言，显式原语言优先；兼容旧 FULL 正文 key 复用。短付费预览不可凭字数判 FULL，长完整正文的普通订阅页脚不一概拒绝。
- Message Bus UI 独立读取状态/指标/来源列表；当日计数一次分组查询替代每源请求；重采集诊断按需打开。固定水位和 MVCC 仍保留。

业务约束：保留 ARTICLE_ONCE、实质更新修订、原始正文、checkpoint、失败/延期/在途证据和真实必需频道。不关闭 WAL/fsync，不直接改业务数据库配置，不批量清空历史队列。

## 7. 实测中发现、修复及发布的机制

### 7.1 恢复、完整性及台账

1. 旧token毒续作正常收尾，监测快照中续作积压清空，没有手删L2_WAIT或放弃业务判定。
2. L2临时错误此前仍会被交付收尾为NOT_RELEVANT，错误决策唯一键又会挡住后来的成功结果。现改为ERROR决策、既有PENDING/lease时点延后60s、释放续作槽；成功结果可纠正错误记录，确定性输入超限明确FAILED。19项回归通过；本窗口未自然触发provider停机，恢复有效性以故障注入测试为依据，没有批量历史重跑。
3. CDC触发器不会随镜像自动升级。20:50:42 UTC显式调用已提交的`SourceOutbox.migrate()`安装薄投影，保留原触发器定义至`/data/bus/migrations/business-delta-capture-50d6b021.json`，没有整库重编码/回填。脚本在`scripts/ops/install_bus_delta_capture.py`，默认预览、`--apply`执行。
4. generic scoped runtime原站导航不再错误拒绝；PCGuide真实原失败文章浏览器已返回200 HTML，进一步发现商品卡Read more被当正文未展开。移除明确商品/作者/联盟卡后，同一公开文章走HTTP约2.8s取得10,376字主文，FULL，真正Continue Reading回归仍拦截。此为定向回归，不计入自然cohort分子。
5. 抽检确认On3一条928字短付费预览被推荐列表凑长误标FULL。HTML/Reader共同识别带订阅报价的短预览、Reader截断Recommendations、旧预览不作为FULL缓存复用。76项正文关联回归通过。21:34:37 UTC通过Owner事务纠正该确认key及对应Raw/Standard当前完整性状态为PARTIAL，保存原正文和原发布审计，新增CORRECTED审计，**无新Stream、无再次发布**。原始尝试标签仍是当时记录，不能篡改成“当时抓取失败”；当前cohort按纠正后的Owner状态计。

### 7.3 POWER证据补丁（观测截止后的离线发现）

固定数据中两个共享FEED各59份capture没有request_started_at，而同URL的生产者有真实请求，合计117周期无法证明。`EnergyHttp`创建子任务时继承了第一个消费者的ContextVar列表，其他消费者只拿到响应、没有拿到trace。

## 8. Reuters及仍未达标的根因

Reuters0覆盖是本窗口最大真实缺口，不能被其他源均值遮住：

- 主身份保留的挑战文档时间早于本次发布；备用在20:47:10恢复后，20:48:44再次受阻，约94秒内复发，其间仅证明3个自然查询。
- 后续恢复探针明确返回401/STILL_BLOCKED；部分在QUEUE阶段约5s就超时、request_sent=false；一次solver记录BROWSER_OR_PROXY_UNAVAILABLE。它同时包含真实访问限制和恢复控制路径问题，不是单纯Bus并发不够，也不能将所有QUEUE超时算作网站拒绝。
- 源/Site已显式调整为2、Site最小间隔1.5s；主身份配置2，备用因probation/维护未强行扩容。全局仍8/BODY2；此窗口没有验证Reuters同身份2并发稳定工作。
- 没有重置cookie/profile、切换身份/出口或清掉挑战状态来制造成功。现有恢复继续保留现场。需要先恢复这两个已验证身份的控制/出口及真实查询能力，再谈全局99%；24个QUERY约占6%的应执行周期，当前能力受阻时全局99%在数学上就不成立。

正文剩余失败按采集源：AviationWeek5个缺订阅；Google6个分别为恢复等待、403、已纠正预览、空提取、订阅及风险组合耗尽；Investing1个无可用认证profile；lakehouse1个空提取；Yahoo1个403。Google只是发现渠道，应继续按最终publisher定位。没有从分母删除这些站点。

**下一步优先动作**：
