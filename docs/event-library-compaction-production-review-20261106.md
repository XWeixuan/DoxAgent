# Event Library 精简：远端十 ticker 业务评估与阈值依据

快照：2026-11-06 00:53:14 北京时间；诊断日期 2026-11-06。配套 [架构与旧退役机制勘察](event-library-compaction-recon-20261106.md)。所有数量指真实 active revision 指向的 Published 版本，不使用初始化目录、最大 E# 或数据库历史 revision 行数代替当前对象数。

## 1. 评估口径与限制

本轮通读十个 ticker 的 **2,558 个 Event 的全部 title/date**；对 MU、INTC、BE 额外完整读了 15 个代表性 Event 的 **751 条 Fact**。重点包括六个 Fact>=50 的 Event 全部条目，以及若干财报、行业主题、分析师反应、政策事件。

标题筛查是当前工作集效用的初筛，不是 Canonical 事实真伪裁决，也不是已批准删除清单。本轮未重新外查原始来源，报告引用的 title、金额、日期、模型/政策名称均是库中记载；**不背书这些陈述对现实世界的真实性**。仅凭标题也不能确认某项诉讼已结束、某个 forecast 已被正式撤销。

对每个 title 给一个互斥的主筛查理由，完整明细见 `eval/event-library-audit-20261106/title-screening.csv`：

- `EXPIRED_STAGE`：旧日程、已过去的市场/预期快照、明显应与后续阶段对照的条目。表示优先检验是否吸收/覆盖，不是已经证明全部失效。
- `LOW_VALUE`：例行、宣传、小额人事/持股/软件更新等，相对缺少独立估值影响。
- `LOW_RELEVANCE`：存在行业联系，但对该 ticker 的因果链较长，需读详情确认是否具有独特约束或直接敞口。
- `RETAIN_OR_DETAIL_REVIEW`：未被本轮标题初筛选为精简候选；并不等于最终永久保留。

下文给出“优先复核”=前两类之和，以及“扩展复核”=再加 LOW_RELEVANCE。**两者都不是精确可删除率，也不是统计置信区间**。尤其扩展集含仍可能有价值的信用、供给、竞争和政策信号，不能全部机械退役。分类是研究判断，计算脚本只复算指定 ID，不使用关键词自动决定退役。

## 4. MU 的业务结构

MU 的核心主线应是 DRAM/NAND/HBM 供需与定价、SCA/长期采购、客户消耗、产能/良率/技术路线、资本开支、竞争供给、法律和劳工扰动。当前大量周边 AI 事件的独特信息对这条主线有限。

### 优先复核例子

- E2 财报日程，已有 E207 实际财报；E441 webinar 日程，已有 E472 技术披露；E86/E334/E335 等劳工日程，应与 E475/E496/E497/E525 的后续状态对照。保留未解决的劳工实质风险，不必保留每个日历节点的前台识别条目。
- E67 25股出售、E280/E281 各29股董事报酬、E451 职业活动、E566 供应商奖项、E573 员工志愿活动：通常不值得各占一个长期 W1 识别位置。
- E44/E45/E46/E47 等旧交易日波动、E99 投资者看多、E108/E111/E118 投资者做空：可保留具有独特冲击的事件主因或一个市场 episode，没必要无限保留所有短期表态。

### 扩展复核例子

- E150 模型发布、E154/E155 安全/听证、E165/E167/E170 事件调查/规则、E186/E234 产品可用性：对 MU 没有明确采购量、内存架构、算力部署或支出约束时，通常相关性偏弱。
- E151/E520/E602 同一 AI 客户上市文件多个阶段：算力承诺、融资持续性有意义，但模型风险、治理权、创始人控制等所有细节不必逐项进入 MU 当前事实集。
- 各地区数据中心、各服务器配置、网络/电源/封装供应商的小型合作：应审查有没有直接影响 MU 的产品内容量、份额、订单或供给约束。仅“AI 产业链”不足以长期保留。

### 应保留的反例

E207 财报与当前指引、E442 现金流/客户押金、E9/E116/E409 的长期客户承诺、E472 路线、E302 诉讼和解、E312/E497/E525 劳工风险后续、E547/E595 等竞争供给：即使旧或与某个已知主题接近，也可能仍定义当前经营现实。

结论：初筛显示约18%的较直接优先复核空间，放宽到外围关联则约49%进入审阅范围。不能把49%当成已确认无用；MU 压到400有机会，但需要细节审阅，压到200–300证据不足。

## 5. INTC 的业务结构

INTC 的核心是 DCAI/CCPG 经营、服务器供给、Foundry 外部客户与亏损、18A/14A 良率与 PDK、EMIB/Foveros 包装、资本开支/流动性、关键合作及事故/监管风险。

### 低价值长尾最明显

- 多家 OEM 的单款 notebook、mini-PC、NAS、地区上市：E118/E121/E132/E134、E288/E290–E293、E348/E350/E352、E399/E402、E419–E421、E593/E595/E602/E604、E674–E677、E705/E706/E715/E716、E724/E752/E753 等。
- 驱动、BIOS、工具兼容更新：E130/E138/E299/E365/E378/E428/E487/E509/E535/E553/E624 等。除非导致大规模安全/产品风险或新的商业能力，不适合各自长期保留。
- 未证实 SKU、命名、性能跑分、热限制传闻：E297/E357/E429/E476/E512/E519/E533/E557/E657/E658/E671/E696/E722/E749/E750。应优先收敛到有效产品路线；明确撤回的传闻需保留否定/历史补查，避免重新识别成新品事实。
- 会议安排、培训、讲话、奖项或泛应用案例：相较于订单、产量、良率、客户承诺，独立研究价值偏低。

这些小事件使“与 Intel 有直接文字关系”与“对 Intel 当前投资现实有独立影响”混在一起。单看 relevance 过滤，无法解决这一层膨胀。

### 间接关联与应保留事项

外围模型安全/产品发布、光通信/内存厂商日常动态、地方数据中心及泛 AI 融资可缩减。但不能误删 Arm/NVIDIA/AMD 对服务器 CPU 份额的实质威胁、先进封装客户、foundry 竞品产能与工艺节点，也不能因事故发生已过数周就删 Fab28 的产出/复产/法律影响。

保留例子：E630/E651 财报和披露、E633/E703 事故后经营与复产、E634/E743 PDK、E635/E647 产品/出货、E683 客户合作、E751 包装路线，以及 E51 等仍生效的资本结构信息。

结论：优先复核277个（36.7%），扩展到476个（63.1%）。相比 MU，INTC 的第一批例行长尾退出空间更明确。最终400–500的工作集有现实依据；直接压200需要牺牲相当多仍有潜在价值的产品/制造/竞争记忆。

## 6. BE 的业务结构

BE 的核心是合同/出货/客户验收、GW 制造能力、现金转换/客户押金/供应承诺、Oracle/Project Jupiter 与 Nebius 的交付/许可/燃气、电力短缺背景、替代技术竞争、项目融资和当地准入。

### 明显优先复核

- E37/E143/E145 的1万美元捐赠、E70 球衣赞助、E79 校园巡演日程。
- E27/E109 财报安排已被 E160 实际结果覆盖。
- E35/E45 证券诉讼原告招揽：保留 E15 等正式诉讼实质，逐个过期招揽不必保留。
- E5/E7 政界人物买股、E28/E32/E34/E44/E46/E69/E91/E151 等旧股价快照、旧券商目标/例行持股变化。

### 需要细节判断

GE Vernova/Siemens/燃料电池竞品/800VDC 等包含替代路线信号，但各自财报指标和每个小型项目未必都改变 BE 的可服务市场。Oracle 融资是大客户兑现风险，不能因其为第三方事件而统一删除；项目资金落实与融资计划可考虑只保留最新控制状态和关键风险转折。

E263 地方投票、E266/E267 州政策、E270 Vineland 许可/交付风险是当前实质性信号。旧 E31 Project Jupiter force majeure 虽然9月发生，仍有2月2027燃气时点与争议，不能按30天删除。

结论：优先74个（26.8%），扩展131个（47.5%）；200个左右的初始目标比强行100个更有依据。BE 没有特别严重的单事件 Fact 尾部，主要问题是 Event 选择。

### 9.1 有稳定 ID 的重复例证

- MU E4：F71/F78（同日“涨价超预期并延续至明年”）；F160/F177（同日 SK hynix HBM 领先）；F166/F170（同日无未承诺供给）。F297/F317 的中国 AI 芯片涨价也高度重合。F121 与 F95 的 DRAM 四倍预测需先核对口径/归属，再决定是否合并。
- INTC E630：F2026/F2032 都是 AI PC 收入增长35%；F1981/F2037 都是 DCAI $7.3B / +78%；F1974/F2040 都含 GAAP EPS $0.60。重复部分可合并，但 F1974 的净利润与同比信息不能随其中一项整条丢失。
- INTC E45：F319/F327/F336/F344/F345 重复 Ohio 租赁/JV 选项；F326/F328/F331/F334/F349/F350 重复探索/无协议；F317/F340/F343 重复技术保护审查。
- INTC E16：F104/F144 重复外部 Foundry 收入 $293M；F100/F142 重复 $5.8B；F102/F128/F133 重复 capex>$20B。不同发生/披露日期需要留在审计，避免把后续确认的时间吞掉。

这些例子证明 Fact 层也需要清理，但不能从15个目的抽样事件外推“全库有X%冗余 Fact”。本轮未对其余7,180条 Fact 逐条标注，因此不给全库 Fact 删除率。

### 9.2 同一个 Event 中发现的质量疑点

MU E207 的 F926 表述下季收入 $60–63B，高于 F919 本季 $54.23B；F976 却称“下季 sales 和 gross margin 略低于本季”，其中 sales 与前述数字不一致。F940 的26个协议、F942 的36个协议，也需要核对范围或版本。MU E115 的 F689（$190→230）和 F794（$1,400）等目标价存在明显口径/单位/版本疑点。

这些只能判为“需原文裁决”，不能在没有来源核实的情况下认定某条为错误并删除，更不能由清理 Agent 选一条看起来顺眼的值。新节点需要独立的 `NEEDS_ADJUDICATION` 结果，防止把事实矛盾藏在成本精简中。

MU 优先集只有123个；即使全被确认退出仍有573个。压到500还需要确认一部分弱关联条目；400接近其扩展候选空间。INTC 优先集277个，如果全退出剩477个；500更接近第一批空间。BE 压200基本对应优先候选规模，但不能把“76个配额”变成强制退役76个。

统一压到100/200没有本轮证据支持。不同 ticker 的业务复杂度、采集覆盖、首次初始化内容和生命周期不同，不能把新 CEG 的64当成所有库应收敛的样板。importance=true 的比例又偏高（MU559/696、INTC518/754、BE224/276），单靠该 flag 也压不出合理预算。

### 10.2 可供首版讨论的起始值（尚未配置）

- **数量触发：ACTIVE/工作集 Event >600；初始软目标500。** 当前主要触及 MU/INTC。若希望更积极，可再讨论400，但应先看完整详情审阅和准召回放。
- **时间触发：首次生成或上次完整成功精简后14天。** 适用于 BE、SNOW、COHR、NBIS 这类数量不高但噪声明显的库；30天成本更低但积累更久。14天是基于当前形态的启动建议，不是经过实验得出的最优间隔。
- **输入体积：记录 Known Index 实际 tokenizer 的 token budget。** 可先以约30k输入 token作为额外容量告警/触发讨论值；本轮40.5k/37.9k为代理 tokenizer，落地时需按 W1 实际模型统一计量，不能直接拿代理值控制生产。
- **Fact：单 Event >=50进入完整详情精简复审，>=100可优先排队；不设自动压到20/30的硬配额。** 二者是审阅优先级，财报可因独特信息充分而保留全部。全库 Fact 总量暂不制定强制目标。
- 目标必须允许 `TARGET_UNMET`：保护仍有效信息，列出差额和理由，完成有效审阅后按约定冷却；不能无限调用 O2 直到它凑够删除数。

注意“600→500”是温和启动配置，不保证达到最终成本目标。以当前全索引平均密度，500个仍可能接近25–30k代理token；MU 要显著低于20k可能需要工作集选择与 summary 更精确，而不是只调整 Event 上限。

## 11. 对开发的直接影响

1. 分开处理 Event 选择、Fact 冗余、主题边界和质量疑点，分别给结果/理由；不能把它们都包装成 `retire`。
2. 保留历史检索和稳定 ID。旧闻重报的去重能力是精简前后准召评估的重点，否则退休了有效旧记忆会增加误判 NEW。
3. 新 O2 任务需要看到 D1 业务主线和当前研究约束，否则“AI产业链有关”会再次变成无限保留理由。
4. 对每个 Event/Fact 写审阅结果，跨批汇总后再定全局状态；模型不得直接改生产数据库。
5. 将退出对象数、退出索引token、Fact去重、保留原因、待裁决数、保护事项、目标差额分别记账；完成=激活与验证通过，而非输出了一份清单。
