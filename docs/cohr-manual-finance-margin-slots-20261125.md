## MARGIN预算规则

```text
E = DoxAgent已分配本金 + 累计已实现净盈亏（含策略费用，最低0）
N = 可配置最大同时ticker数
每ticker预算上限 = E / N
新组可授予额 = max(0, min(E/N - 同ticker已有组预算,
                         E - 全账户已有组预算))
```

- 移除1.5E并发名义预算规则；策略自身账本决定E，个人盈亏及券商总净值不增加策略额度。
- 主仓与对冲共享一笔组预算及费用预留，ETF不另占名额。整数股与比例容差、先主后对冲、实际保证金/WhatIf检查及原订单状态机不变。
- 空闲名额不转移；主仓只按分配后的计划执行，不拿未成交对冲预算追加主仓。
- 同ticker多个策略组共同受该ticker上限约束，不能通过不同Case重复领取完整名额。
- N在新执行记录接收时冻结；已授予组预算、主/对冲计划及退出不重新划分。配置调整不改旧组、不强平；旧组占用仍计入新组的账户/同ticker余量。
- MARGIN既有周期在后续新授予时使用最新已实现策略额度；授予事务再用当前账本限制上限，避免报价跨越费用到账或本金调低时用旧额度超配。不增加券商请求，复用短SQLite事务及现有资金账本。
- 最低有效开仓比例保留原25%，计算基准随预算单位改为名额额度；否则N达到4时，固定“账户25%”阈值会因手续费预留导致所有名额必然失败。仍拒绝不足一股/比例不合格的整数股组合。
- CASH保留现有已结算USD现金、策略现金及名额约束；没有新增卖空或透支能力。

本金$4,000与有效额度E不是同一数字。真实样本补账后累计已实现净亏损为`-$107.845435`，E及无仓时策略现金/总资产为`$3,892.154565`，N=2时每名额上限`$1,946.0772825`，然后再扣费用预留。不能为了显示每组恰好$2,000而抹去历史净亏损。

当已有组因配置调低/后续亏损超过新的上限时，不追溯缩仓；只拒绝没有剩余额度的新授予。名义预算合计约束在新授予事务执行，不承诺通过自动平仓让历史已冻结预算随每笔费用持续重算。

修改`trade_execution/capital.py / repository.py`及新增`manual_finance.py`；收益页沿用原UI/接口，只修`revenue_audit/ledger.py / projection.py`及`v2_read/pnl.py`的读模型。管理修复脚本只做账本与配置，不调用券商订单接口。复用既有canonical组件发布，无新服务、表、轮询、个人成交追踪系统或额外正常订单前置券商检查。

高危场景检查：

| 场景 | 结果/约束 |
| --- | --- |
| 相同人工平仓重复应用 | 注记和资金配置幂等，lot/jobs不变；没有重复收益/佣金 |
| 错账户、合约、方向、数量、时间或证据冲突 | 拒绝；不因ticker相同猜测归属 |
| 人工退出已经记录为策略成交 | 拒绝再附加相同成交家族，防双计 |
| 个人COHR买入 | 不进入指定调整的financial_close；不减策略lot、不改个人持仓 |
| 新旧组并存、N调低、额度调低 | 旧预算不动；新组受剩余额度及ticker数约束 |
| N=1/2/3/4/8、价格大于名额、一股预算边缘 | 定向执行验证；禁止0主仓/非零对冲或无效整数组合 |
| 两个并发ENTRY、同ticker重复Case | 复用原原子预留；合计不超额度、不借空闲名额 |
| MARGIN带对冲SHORT主仓 | 双腿名义额在同一名额内，比例及整数股检查保留 |
| 新授予前资金变少、旧cycle未刷新 | 授予事务用当前策略账本限制上限，不用旧cycle超配 |
| 已FAILED EXIT/迟到成交/重建 | 不触碰原持久闩锁及受控恢复规则；前轮保护回归保留 |
| 收益页当前资产及完成状态 | 完整投影链路验证两腿0股、completed=true及现金＋有符号持仓估值 |
