# 全部消息源卡片重构与退出清理

## 阅读层级

卡片保持三列，采用六个连续阅读层级：

1. 标题 + 右上角健康摘要。名称更醒目，可显示静态简称、悬停查看完整名称；右侧展示最近轮询成功/部分成功/失败、配置目标间隔及订阅状态汇总。成功依据最近轮询结果，不用“运行中”冒充成功；休眠保留最后结果并单独显示休眠数量。无结果为暂无记录。
2. 来源介绍 + 入口。保留源逐项说明媒体/机构身份及监测的栏目或业务内容；入口展开不发请求。
3. 双列采集路径。列表抓取与正文补全分别展示主方式，备用方式使用下行层级；分发和行业不再与抓取标签堆放。
4. 独立 Ticker 订阅。标签按五列整齐排列，超过十个可展开，禁用关系仍有标识。
5. 七项运维指标。业务含义、采样和聚合不变；仅布局调整。底部左右两个属性锚点分别呈现分发方式和全局/行业适用范围。
6. 可展开异常区。位于卡片底部，仅异常时出现；正常卡片不留空占位，展开详情内部有界滚动。

正常源先按全局及行业排列，随后“已停用或未使用”，最后“测试消息源”；多行业、筛选规则及首次进入/手动刷新策略延续，无新增轮询或动画。

## 分类与退出依赖

- Calcalist 改为航空航天、国防与安全科技；AWS Platform Marketplace 改为软件板块。
- 生产只读勘察确认 105 个登记源。批准退出 20 个：19 个已经合并的旧栏目处于停用状态，GlobeNewswire Search 仍有 10 个启用订阅。具体来源/替代关系见 `retired_sources.REPLACEMENTS`，不按“停用”状态泛化删除。
- GlobeNewswire Massive 是另一个测试源，不将它宣称为 Search 的正式接替覆盖，也不擅自迁移十个订阅过去。
- 既有 hard_delete_source 默认会重试 Raw 并强制发布缓冲，不能直接用于本次退出。新增 flush_pending=False 参数复用原控制面删除与审计流程，本次不补发、不重试历史 Raw；原默认删除语义由回归继续验证。
- 删除当前源定义、全部订阅（含 tombstone）、poll_states/poll_unit_states、缓冲及默认 profile 引用。取消当前 FETCH_DUE/FETCHING/COMMIT_DUE 与 WAIT_BODY/PENDING/L2_DUE 工作，清除它们的 claim。新建登记拒绝退役 ID，初始 manifest/profile 不再列出 Search。
- 采集器通过既有配置 DELETE 修订在刷新时撤销计划、关闭逻辑单元；不为这次清理引入新任务。原发布提交时的当前 binding 检查会拒绝已删除绑定的迟到结果。BODY recheck 的已有有界查询增加源定义存在条件，已删除源不会被重新安排正文任务。
- 历史 Raw、Standard、正式消息、正文、Live 文章及已发布分发、审计/源修订、采集回执保留。跨源复用正文和历史去重依赖这些事实；不做历史清库或 VACUUM。旧列目的解析/迁移常量保留兼容用途，但不再存在活动注册。GlobeNewswire 网站策略仍被 Massive 正文复用，不能按 Search 名称删除整站策略。

## 数据与性能

目录 API 只从已经批量读入的源、绑定及 SourceStatus 组装 poll_counts、configured_intervals_seconds 和 short_name，不增加 SQL、连接、表、索引或持久化。目标间隔缺失则显示缺失，不默认猜成 60 秒。七项指标的 SQL 和采样范围不变。

退出是一次性指定清单操作。仅扫描当前配置及用现有状态索引定位活跃工作；不读取正文、不重算历史，也不调用模型。可重复执行；执行前预览清单，执行后核对源/绑定/默认配置及采集计划。
