## 2. 实现范围

- `ownership.py`封装动态残差及可恢复等待/确定归属错误；`exit_guard.py`封装持久闩锁与展示摘要；`management.py`封装组管理请求及回执。均属现有执行模块，无新增服务或独立订单系统。
- `repository.py / groups.py / executor.py / worker.py`接入提交守卫、lot重建保护、临时等待分流和无新单权限的旧attempt维护。
- `ibkr_session.py`只补openOrder回调conId；退出原因schema、CLI、Read投影、TypeScript契约和Case卡同步适配。
- 使用既有runtime_values保存锁及管理请求/回执；新增同账户合约attempt表达式索引，避免正常归属查询扫描全账户历史attempt。
- 增加定向回归、受控组件发布脚本及changelog；未混入工作区其他W3/回测修改。

管理命令位于现有trade_execution CLI，参数以`--help`为准：`group-exit`、`group-resume-exit`、`group-exit-status`。管理提交成功表示退出意图已应用，**不代表已成交**；回执和策略成交仍须分开检查。受控恢复的evidence_refs与人工操作确认由获授权操作人提供，系统做范围、版本、余量、同步及未明单检查，不声称自动判断用户真实意图。

## 6. 运维边界与结论

正常交易继续低延迟动态归属；严格恢复仅针对已终态FAILED的EXIT。后续如需提前退出，先确定完整组ID并获用户授权；如需恢复FAILED，必须独立核对历史成交和人工操作，不能用P=A-S自洽替代证据。已人工结清且lot正确时不重复修账、不重新发单。

回滚不可直接换回会自动恢复FAILED的旧Executor；应先停止发新单、保存锁/回执/实际成交，再使用保留提交保护的修正版本。任何回滚不能删除策略真实成交、手工调整或管理审计，未知原单仍须核对。

本轮开发、定向测试、部署和限定只读验收已完成。尚未进行新入口的真实券商成交验收；这是本轮禁止LIVE订单测试的授权边界，不将fake broker结果冒充实盘成交证明。
