## 剩余高占用

清理的剩余边界有现场依据。Read 无明显空闲页；跨池同 SHA 只有约 9 MiB 可直接合并；Runtime 已引用内容和当前/历史分支需要保留准确版本，选版压缩样本没有收益；W3 registry 已 DELETED 的线程与 SDK 当前 state 的交集为 0，无法据旧数量直接再删一整池。Research 的完整发布正文、CDC 与 W3/Read 加工副本需要先落地读写兼容和源头减量，再按 owner 解除引用，这部分不能靠当前路径直接删除而维持现有读取契约。SDK 普通日志已实际压缩，继续删近期普通日志的边际收益较低。

因此本轮没有把达到约 50 GiB 描述为已完成，也没有宣称 17.43 GiB 能长期覆盖增长。进一步大幅回收的主项仍是源头减量发布后，Research 发布正文副本、Runtime 历史过程保护和 Read 重复投影的存量收敛。独立保留的准确业务证据与有效恢复责任需要在相应读取入口完成适配后退出。

生产 SQLite、有效 Registry/浏览器身份和回滚、正式研究原件、仍被引用的 Native 内容继续保留。Read 约 17.85 GiB，核查时 `freelist_count=0`。Acquisition 有约 3.62 GiB 可复用页，属于数据库内部余量。此次没有在线重写这些主库。资源生命周期源头改造的生产发布独立于本次恢复。
