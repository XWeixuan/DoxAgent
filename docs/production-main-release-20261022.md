# 2026-10-22 main 统一发布

本轮获授权统一发布 main 已完成开发，包括其他会话的改动。产品代码、提示词格式、测试、开发文档及选定评测脚本/结论纳入 Git；原始运行日志、SQLite、临时镜像归档、凭据不纳入。

## 召回节点容灾

W1R1、W2R1 主调用仍为 OpenRouter Haiku 5.5 high、google-vertex/global，显式缓存默认 1h。OpenRouter 鉴权、余额、限流、超时、连接/流失败或截断输出时，立即以相同冻结业务输入、提示词和输出 Schema 切换百炼 qwen3.8-flash low，保留各节点原超时（W1R1 120s、W2R1 180s）。不并发请求两个 provider，不将首调用费用隐藏。

切换状态持久化，每次实际请求单独留 provider/model/耗时/token/费用回执。备用 provider 使用现有结构化 Responses 路径和独立有限修复预算，恢复时不再回到已失败的主 provider；成功的轮次复用已记录输出。主调用失败回执已落盘但切换状态尚未落盘的中断也可恢复。输出语义/Schema 校验错误仍按原机制修复；取消、停机和租约控制不被吞掉。不会自动重跑历史终态失败 Case。

## 验证与发布边界

专项验证包括两个召回节点的故障切换、首请求付费回执、故障切换中断恢复、成功重放、取消与输入错误不切换；以及 CPU/Bus/Calendar、W1R2、W3 回测、Vertex 离线回归。测试事实视图 fixture 随代码提交，不依赖本机未跟踪 eval 数据。

使用远端既有 storage_release 生命周期，由精确提交构建不可变镜像，保留 canonical Compose 环境、命令、数据卷和 Secret。先暂停生产任务入口并有限排空，在持续在途时允许中断，由现有停机/租约机制恢复；生产入口最后恢复。镜像健康、实际代码身份与 primary/fallback 配置均需上线后检查。部署回执保存在远端 releases 私有审计目录，不能用仅 Git 更新代替镜像验收。
