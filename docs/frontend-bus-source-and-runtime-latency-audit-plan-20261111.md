# 消息源卡片与运行状态延时：指标口径及轻量修复方案

日期：2026-11-11。状态：**待实施方案**。本文件从历史工作树的排查方案提炼，保留通用业务规则、实施步骤和验收要求；生产个案、原始取证及部署明细另存本地归档。本次迁移没有修改指标实现或发布生产。

## 1. 当前行为与需要修正的部分

- 消息源卡片的“20”是最近最多20个已结算轮次，不是必须凑满20条消息。均值、P95、正文补全率有1个有效样本即可计算。
- 空轮和重复文章不产生新文章样本；端到端统计还要求消息正式发布。短轮询窗口内没有新文章时，空值是合理结果，不能伪造0或把旧窗口数值当作当前值。
- 一轮判定按REALTIME Case的W1/W2相关调用整体壁钟区间计算，包含重试等待，排除W1 R3以及首次调用前的排队。保留公式，补充说明。
- 当前二轮指标收集全部W3阶段并取终态整体区间，会混入后置运营、跨阶段等待、CLOSED Case及无成功决策的失败终态。应改为实时交易判定区间。
- 交易阶段内部真实重试、恢复等待和结果提交延迟必须保留。不能只取最后一次成功调用，让长尾从指标中消失。

## 2. 消息源卡片

保留现有近最多20轮窗口、一个批量dashboard请求和分钟刷新，不扩大历史查询范围。

| 指标 | 计算与展示 |
| --- | --- |
| 平均端到端 | 有效已发布新消息耗时之和 / 消息数；n=1也显示 |
| P95端到端 | 升序第ceil(0.95*n)条；n=1等于该条，同时展示实际n |
| 正文补全率 | FULL/SHORT_FULL文章数 / 有BODY记录的eligible去重文章数；展示分子/分母 |

- 有1篇失败文章时，正文率为0%，不是无样本；0/0表示窗口内没有文章样本。
- 没有正式发布的新消息时，端到端指标提示“近20轮无已发布新消息样本”。无有效轮次窗口时提示“暂无可核对轮次”。
- 复用已有coverage.expected、e2e_samples、body_total等字段，不新增逐源诊断查询。
- 不按当前正文更新时间或当前时刻伪造首次轮询锚点，不回填历史轮次账本。
- 不采用“向前找够20篇”的方案；它会扩大用户要求保留的取数范围。

## 3. 二轮交易判定口径

建议卡片名称为“二轮交易判定延时”：

```
样本：REALTIME，存在正式w3_trade_decision及decision_completed_at
起点：同Case最早trade_decision attempt.first_started_at
终点：正式decision_completed_at
单Case耗时：终点 - 起点
页面均值：单Case耗时之和 / 有效Case数
```

首次模型调用前的W3排队不在此口径内，提示中须明确这一边界。交易阶段内部失败、重试和恢复空档保留；终点包含业务提交，后置运营不参与。

缺phase、缺正式提交时间的历史记录保持缺失，不用全部W3结束时间或最后更新时间推算。0秒是有效值；时间倒置视为无效锚点，不截成0。不截尾、不改成中位数，也不把未决策失败Case混入成功决策耗时样本。

一轮继续使用原公式；Case明细继续提供既有交易/后置操作和SDK时间，不新增顶层指标体系。

## 5. 有界历史修正

- 消息源指标不做回填。
- 二轮新口径先处理明确的当前业务日和上一业务日；按ticker/trading_date索引取Case ID和标量，每批100–200个，attempt按parent索引读取。
- 仅对已选ID缺失的decision_completed_at做Runtime源主键批量读取；实际缺失则保持缺失，不读正文或冻结模型大文档。
- 贡献按Case身份替换，重复执行不累加；短事务、小批次，不在页面GET中回填，不持有源库长读事务。
- 不自动扩成7天、30天或ALL全历史扫描。尚未补齐的旧周期明确提示，不与旧口径桶计算环比。
- 使用一次性、有明确日期和批量上限的修正脚本即可，不增加常驻任务或持久化回填系统。

## 6. 验收

1. 消息源0条、1条、2–19条均按实际样本处理；1条消息的均值/P95可显示，1篇正文失败显示0%，4/6显示66.7%。未发布文章不能伪造端到端样本。
2. 无计划、刚启动不足20轮、休眠冻结窗口及窗口内无新文章分别验证，不扩大窗口。
3. 一轮W1/W2并行、W2 R3、W1 R3排除及重试边界保持原行为。
4. W3交易已提交、后置运营数小时后完成时，二轮值不随后置阶段变化；交易失败后数小时重试时，该等待仍计入。
5. 决策已提交、后置运营PENDING/FAILED时立即产生决策耗时样本；仅失败未决策的Case不计成功决策样本。
6. 缺锚点不猜；0值有效，时间倒置缺失。验证attempt先到/Case先到、重复CDC回放、snapshot重建和日期归属一致。
7. API桶与同口径抽样Case重算一致；记录查询数和耗时，确认没有新增源库全扫描、逐源网络请求或大文档读取。

## 7. 资源约束与范围

消息源GET不增加数据库读写。Runtime KPI GET仍只读桶；投影仅为受影响Case计算小attempt列表；不加载全ticker历史或增加常驻Case缓存。

本方案只包含卡片解释/样本展示、二轮业务边界修正及两天有界修正。真实调度恢复和性能长尾需独立定位，不能用缩短指标区间代替修复。
