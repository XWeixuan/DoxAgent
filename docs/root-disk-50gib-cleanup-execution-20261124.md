## 实际清退范围与边界

主体执行 19 个批次，处理 **4,854 个工作区目录、2,711 个运行家族**，其中 4,842 个目录包含实际输入文件。合计移除 **2,582,147 个输入文件**及相应空目录。删除时按最后一个硬链接核算文件块，连同目录块的账本为 **49,913,057,280 B（约 46.49 GiB）**。它与整盘净增分列，不能相加。

| 对象分类 | 目录数 | 退出依据 |
| --- | ---: | --- |
| 有已发布成果的终态家族输入 | 4,695 | 正式 bundle 存在；发布及同族最后完成超过 24h；全部 Worker owner 终态；无仍待执行的当前 Runtime owner |
| 无发布成果的废弃终态输入 | 159 | 同族全部终态超过 72h；不是当前正式 D3 run；无在途/待恢复的当前 Runtime owner；只退过程输入 |

实际白名单为这些 owner 的 **`context` 和 `attempts/*/input`**，包括大型材料、导航页面与重复模型输入。保留 `published`、`artifacts`、`output/final`、Jobs 最终结果、用量、错误和 audit；Canonical Research、PolicySet、Case 冻结证据、Event SQLite、交易/持仓、浏览器身份、Codex 会话与有效镜像没有作为本轮主体删除对象。

每个 owner 在文件操作前，用 Worker writer 重新检查同族 queued/running Job，并提交现有 `workspace_retirement:` 栅栏，防止旧 run 被重新提交；终态时间读取和文件删除均在 writer 外进行。目标路径限制在真实工作区根下，拒绝链接逃逸；硬链接仅移除输入侧名字。运行目录内保留 `audit/storage50-input-exit-20261124.json`。

这项取舍明确退出旧维护任务的**原地续跑与完整输入重放**，保留正式业务语义和最终成果。后续需要重新维护时使用新的 run 和有效状态，不能继续依赖已退役输入。

## 本次暴露的退出缺口

大体量输入副本既存在于成功发布家族，也存在于失败、取消及重基后不再属于当前 Task 的旧 run。**有正式产物不等于过程输入已经退出；缺少发布/当前 owner 记录也不等于输入天然需要永久保护。** 这些数据主要服务于当次模型执行，长期保存完整材料与导航树的成本明显高于后续使用价值。

近期 O3 关闭和输入减量已截断该类新增；本轮完成的是历史存量收尾。未来独立恢复 O3 时，应让失败和被替代 run 同样有有界退出责任，不能只覆盖成功且仍能匹配当前 Task 的 owner。本次没有为此扩大产品代码改造。

本回执证明达到本轮 **50 GiB 可用空间**目标；持续净增长和五个正常交易日的长期收敛验收仍按原治理方案单独衡量。
