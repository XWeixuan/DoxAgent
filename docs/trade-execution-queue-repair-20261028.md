# 交易执行器调度与旧意图鲁棒性修复

2026-10-28。依据[近一周审计](trade-execution-case-audit-20261028.md)实施；生产目标仅为 `v2-executor`，账户模式保持PAPER。

本次修复“维护出错导致整轮订单队列统一退避”的传播路径。审计证实Runtime存在SQLite写锁争用，但未唯一定位长期持锁者；本次不把执行器改造描述为已经根治所有Runtime写锁来源。

## 实现

- 订单扫描、推进先于维护调度；心跳/健康、连接与空闲恢复、资金周期、开仓期限、失败退出恢复、成交事件、验收分别以固定的少量异步任务运行。每类最多一个在途操作，只有自身失败才退避。ticker之间保留独立推进；同ticker维持先结清未决订单，再处理退出/新开仓的顺序。
- 心跳写入和连接维护离开主事件循环；执行账本常规事务最多等待SQLite写锁0.2秒，SDK线程原始事件持久化保留既有等待窗口，不为减少延迟而丢弃成交。事件应用仍与执行器同步在同一事件循环，避免并发drain造成游标回退。SQLite争用不再计为券商故障，也不消耗开仓三次失败预算；异常后的SUBMITTING/未知订单按原身份继续对账。
- 无失败EXIT的空闲恢复扫描只读，不再为每轮空扫描申请写锁。账户断线仍按2/5/10/30/60秒、之后约每分钟恢复；不新增连接或ticker级重连风暴。broker缓存创建加互斥锁，防止维护线程与主线程同时创建相同client身份。
- 未完成ENTRY新增**300秒上限**，从交易意图`released_at`起算，覆盖接纳前的排队；无该字段的旧记录用持久化execution.created_at。不是按消息首发时间计时。达到300秒永久记录`ENTRY_QUEUE_AGE_EXCEEDED`，保留真实失败次数；重启及重复接纳不能复活。发单前的事务内再次检查，覆盖取报价/对账期间越界。PREPARED但未发单的attempt作废；已发单、部分成交或未知订单保留取消/对账，成交继续生成EXIT义务。语义日到期和原三次真实失败保护继续适用。
- 每10秒记录`execution_scheduler/health`：基于原定scheduled_exit计算退出逾期，而非用不断刷新的重试due_at掩盖延迟；包含job ID、逾期/年龄秒数、attempt次数。退出逾期60秒或ENTRY年龄达到300秒时输出`execution_jobs_stalled`业务告警，心跳不能替代该检查。

5分钟是本次对短线消息开仓排队采用的明确产品默认值；若等待开市或故障恢复超过该时限，将放弃该意图。这不改变持有仓位的退出恢复规则。不开新配置面板、队列服务、数据库或趋势指标。

## 验证

新增故障回归覆盖：真实SQLite写锁下有界返回且不计券商失败；六类维护故障时到期EXIT仍进入执行；心跳持续失败时自有持仓完整卖出、仅一张退出订单且手工基准仓位不变；其他ticker继续推进；超龄零尝试ENTRY、接纳前延迟、原子发单边界竞争、未决/部分成交的取消对账及重启不复活；空闲恢复无需写锁；业务逾期告警。

相关测试 **77 passed、3 skipped**（58.54秒）；3项SDK适配测试因本地缺少`ibapi.order_cancel`跳过，相关适配器本轮未修改。Ruff及git diff空白检查通过。远端镜像将做实际环境导入检查及运行核验。证据目录：`eval/execution_queue_repair_20261028/`。
