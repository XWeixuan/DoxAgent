## 2. 已实现的业务口径

### 消息总线

- 首次发现的滚动24小时内至少5篇：取该窗口最新最多20篇；不足5篇：取历史最近5篇；历史不足5篇按实际量。先确定文章集合，再计算正文及延时，不向更早历史补成功样本。
- 卡片正文率、平均/P95端到端耗时及真实抓取延时共用这一集合。正文分母包括等待/失败，沿用明确不适用的排除规则；端到端只统计已首次正式发布、具有合法发现/发布锚点的文章。
- 真实抓取延时为可信原文 Publish Time 至首次正式 Bus 发布；分钟精度解析为00秒；DATE、RELATIVE、未知及旧投影默认EXACT不授权取样。精度链路已修复，缺失历史精度不伪造、不全库回灌。
- 顶部端到端和真实抓取均值按消息加权，排除当前 failed 源；partial、休眠不直接当失败。卡片保留该源样本，便于观察。
- 顶部6项、源卡片7项。周期新增、逻辑轮次覆盖率、源状态及刷新间隔保持原有业务口径；文章指标说明为滚动文章取样。
- 保留统计分钟刷新与消息流独立的机制；浏览器回归确认错误及视图续期不清空已加载消息、不丢展开状态和阅读位置。

### 运行状态

- 一轮原整体区间口径保留，但单Case超过600秒时同时排除秒数及均值分母。
- 二轮改为该Case第一次实际发送 trade_decision SDK回合请求至合法成功回合的原始SDK完成时间。排除Fork、Operations、CLOSED及未成功形成交易判定者；NO_TRADE是有效判定。SDK原始完成为秒精度，起点按相同精度计算。
- 二轮均值只纳入0–600秒；原始完整耗时另存于Case摘要/详情/导出。大于180秒产生 `LONG_W3_DECISION` 标签、KPI及列表筛选，超过600秒仍计长研判。
- Policy命中/相关均为Case数量，复用有效Policy结果；两个数量允许同时命中；有观测且0例显示0，没有可测样本保持未记录。
- 移除顶部二轮研判数量、事件发现数量；增加长研判耗时与非模型调用延时，共8项KPI。
- 非模型延时：Runtime接纳至交易判定出口事务COMMIT返回，减去这一区间内全部客户端模型在途区间的并集。包含重试及W1 R3在终点前的区间，排除Operations；并行区间不重复扣除。成功提交但不下单的确定性出口也可统计，不截极端长尾。
- 新终点 `decision_effective_at` 搭载既有Effect完成回执，旧业务 `Case.decision_completed_at` 不改含义。失败/取消缺可靠模型区间、缺提交后锚点的Case不冒充0，不使用重启/恢复时刻补原始时间。
- 正常SDK完成、完成回执恢复都保留原始计时；失败尝试至少保留首次实际发送值。未知结束不猜测，因此有关Case可能仍没有非模型样本。

## 3. 数据读取与写入的实际改动

1. 每次现有Bus dashboard请求批量传源ID，源索引内各取最多20个ID，再按现有 `current_identity(kind,ticker,id)` 关联delivery、正文和消息。顶部/卡片共享一次计算，无逐源HTTP、逐篇网络请求或全天文章COUNT。
2. 原方案的34GB Read表表达式索引构建在55秒预算内未完成并回滚。改用紧凑 `article_sample_keys` 定位表，只含ticker、文章ID、source和首次发现时间及必要索引；不是新增文章副本或历史账本。
3. 一次性初始化只遍历当前delivery种类的索引范围，1000行keyset批次，8MB缓存、低优先级。最终单连接处理17,854条元数据，8.869秒完成，移除临时检查点；没有后台回填任务。
4. 后续locator仅在既有Read投影事务中随发生变化的delivery更新；首次发现和源归属未变时UPSERT不产生变化。删除同步删键。统计贡献更新不维护locator。
5. 生产EXPLAIN发现优化器曾选择较宽的current_parent索引，已显式指定既有current_identity；最终要求delivery为完整 `(kind,ticker,id)` 定位，BODY/message同样主键关联，无临时历史排序。
6. Runtime GET仍只读现有指标桶。投影仅对受影响的单Case读取其小attempt/Effect集合，计算区间并集、标签及sum/count贡献。模型和生效锚点附在既有回执/Turn/Effect，不新增计时服务、常驻任务或逐节点表。
7. 没有复杂历史回填、模型重跑、券商调用或交易状态修复。发布中的标准镜像清理沿用既有工具，未执行全机prune。
