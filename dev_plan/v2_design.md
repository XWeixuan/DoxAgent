# DoxAgent V2 视觉设计语言

更新日期：2026-09-07。总体语言与状态语义作为 V2 设计约束；Overview 已作为 Golden Page 落地并完成首轮浏览器验证，其他页面的 composition 继续按其内容需求设计。

PRD 决定功能和信息需求，本文决定总体视觉语言；具体 UI composition 可根据实际页面效果优化。V2 为 Greenfield Rebuild，不继承 V1 组件或视觉实现；保留本文明确指定的品牌色与 Logo 字体。工程边界见 [Frontend Foundation](workflow_v2/DOXAGENT_V2_FRONTEND_FOUNDATION.md)。

#### 1.3 视觉风格与设计方向 (Visual Direction)

* **核心风格：** 临床分析极简主义 (Clinical Analytical Minimalism)。
* **视觉目标：** 呈现冷静、理性、精密的监测与研究系统。整体保持专业、透明、克制，以清晰的信息层级为核心，并通过少量柔和的主题色减少传统金融终端的机械感。

#### 1.4 色彩规范系统 (Color Design Tokens)

整体采用冷静的中性色作为结构基础，以殷红和仿生粉构成品牌识别和关键交互层。

* **Background — Clinical White `#FCFCFC`：**
  全局主背景。相比纯白保留轻微灰度，降低视觉刺激，同时维持高信息密度界面的清晰度。

* **Structural — Slate Gray `#868686`：**
  作为结构色基准，派生分隔线、边框、网格等用途的语义令牌。正文、次级文字与装饰边框分别校准，不将同一灰度直接应用于全部场景。

* **Brand & Interaction — Sentient Crimson `#A14066`：**
  核心品牌色，用于 Logo 关联元素、主要操作按钮、关键标题及高优先级交互，是界面的主要视觉锚点。

* **Theme Accent — Biomimetic Pink `#F191CE`：**
  辅助主题色，用于 Focus、Selected、局部边框、轻量背景和少量强调效果。使用应保持克制，不作为大面积高饱和主色。

品牌、交互、业务状态、数据系列使用独立语义令牌，不由页面直接按颜色名决定含义。品牌殷红不等于错误，Selected 不等于业务成功，图表系列颜色不等于健康等级。

#### 1.5 排版、材质与空间构成 (Typography, Material & Layout)

* **Primary Typeface — Satoshi：**
  Satoshi 作为拉丁字符主字体，以 Regular / Medium 为主。中文明确使用可读的 fallback 字体栈，如 PingFang SC、Microsoft YaHei、Noto Sans CJK SC、sans-serif。正文与关键数据不依赖 Light 字重；数字采用适合比较的等宽数字特性，技术标识按需使用等宽字体。字体本地托管并保留许可信息，加载失败不阻断阅读。

* **Logo Typeface — Sansation Light：**
  Logo 保持现有 Sansation Light，不随全局字体调整。

* **Luminous Effects：**
  发光效果只用于少量关键风险、异常或特别强调的节点。保持柔和、局部，不作为常规状态标签的默认样式。
  异常首先通过文字、图标和局部提示表达；发光不能替代状态说明。

* **Thematic Borders：**
  Selected 或特殊容器可使用 `#F191CE` 的 1px 细边框。该颜色对 `#FCFCFC` 的对比度约为 2.11:1，不能作为唯一键盘焦点标识；Focus 使用更深的语义令牌或具备足够对比度的复合轮廓。

* **Micro-Radius：**
  输入框、卡片、按钮及容器统一使用约 `4px–8px` 的轻微圆角，保持克制，不使用过度圆润的 SaaS 风格。

* **Glass Panels：**
  允许在部分数据卡片和功能面板使用轻微半透明与模糊效果，但必须优先保证内容清晰度和边界感，避免大面积使用 Glassmorphism。
  默认数据表面保持实底和稳定对比；玻璃效果不影响长正文、表格和密集数据阅读。

#### 1.6 状态视觉系统 (Status Visual System)

V2 重新建立统一的状态视觉系统，不直接继承现有页面中的零散状态样式。

状态颜色、Badge、图标、边框、背景和强调层级应根据实际业务状态重新定义。

新的状态系统必须：

* 保持本文指定的品牌主色系与整体视觉语言；
* 不依赖单一颜色表达状态；
* 在全局组件中保持一致；
* 避免为每种状态引入新的高饱和颜色。

##### 状态维度

| 维度 | 表达范围 | 规则 |
|---|---|---|
| 生命周期 | 待开始、进行中、完成、暂停、停止、失败 | 暂停/停止为中性状态；运行完成不代表交易已成交 |
| 健康与质量 | 正常、降级、阻塞；COMPLETE/PARTIAL | 独立于生命周期；质量注解不能直接覆盖初始化父状态 |
| 数据可用性 | 空、未生成、未记录、不适用、部分可用、读取失败 | 不混为“无数据”；仅确认零值显示 0 |
| 业务路由与结果 | ARCHIVE、W3、TRADE、事件发现、成交、失败等 | 路由是去向，结果是已发生事实；一个 Case 可有多个结果 |
| 模式与方向 | 消息监测、Paper、Live；LONG/SHORT | 使用明确文字与分类符号，不借成功/失败色暗示评价 |
| 交互 | Focus、Selected、Hover、Disabled | 独立使用交互令牌，不改变对象业务状态 |

各领域使用有类型的映射，共用表达原则，不采用一个按字符串猜测所有状态含义的函数。相同 PARTIAL 字样可能表示发布质量、资源可用性或指标覆盖，必须保留所属语义。

##### 语义色族

| 色族 | 用途 |
|---|---|
| 中性灰 | 待开始、暂停、停止、历史、未生成、不适用 |
| 低饱和冷蓝 | 正在执行、处理中 |
| 克制的绿 | 已完成、运行正常 |
| 琥珀 | 降级、部分覆盖、暂估、需要关注 |
| 错误红 | 真实失败或阻塞；与品牌殷红明确区分 |

此处只冻结语义方向，具体前景、背景、边框色值在组件验证时确定。所有状态以文字为基础，配合图标/形状；颜色不作为唯一识别手段。未知状态不能默认映射为成功。

##### 组合与局部反馈

- 运行中与降级、初始化完成与质量注解可以同时成立。
- Runtime 完成与交易尚未成交必须区分；实际部分成交可与后续阶段失败共存。
- 消息监测模式下仍可能有此前 Paper/Live 交易继续，不把旧交易误标为当前模式的新释放。
- PARTIAL coverage 保留已知值并以局部注解说明范围；佣金未齐使用暂估语义，不能伪装完整金额。
- 刷新保留同范围旧内容，局部失败就地提示；首次加载、空集合和未生成产物分别表达。
- 不增加常驻 SSE 状态、最近刷新时间或额外 Audit status 卡片；影响实时更新的连接异常才局部提示。
- 上升/下降不自动等于好/坏：收益、成本、延时分别按指标语义解释；LONG/SHORT 不等于成功/失败。

#### 1.7 可读性、可访问性与动效

- 普通文字目标对比度至少 4.5:1，大字至少 3:1；识别必要控件与状态的非文本标识至少 3:1，纯装饰边框不承担信息识别职责。
- 键盘焦点清晰可见；选中、失败、禁用、展开等状态具备可访问名称与语义，不依赖 hover 才能理解。
- 动效仅表达正在发生的操作、局部变化或有依据的计时，遵守 prefers-reduced-motion；不让装饰动画暗示 workflow 正在运行。
- 本地持续时间与轮询倒计时只依据已取得的服务端事实推进，不产生额外网络读取；暂停、窗口关闭或调度未知时不伪造倒计时。
- 视觉验收覆盖中文长标题、长正文、表格、未知/部分数据、键盘操作和窄屏；Overview 的网格与状态组合由 Golden Page 验证，其他页面不机械套用。

#### 1.8 Overview Golden Page 实施基准

实施入口为 [frontend/v2](../frontend/v2/README.md)，令牌与样式以 [styles.css](../frontend/v2/src/styles.css) 为源。实时状态与周期指标在桌面紧凑并列，以轻底色和分隔线区分；按可用宽度重排。启动表单在中等桌面横向排列，让监控表格获得完整宽度；窄屏切换成纵向标的卡片，六步进度使用两列排列。

| 状态语义 | 前景 | 轻背景 |
|---|---|---|
| 中性 | `#68616F` | `#F2F0F4` |
| 进行中 | `#42668B` | `#F0F5FA` |
| 正常 / 完成 | `#317357` | `#F0F7F3` |
| 降级 / 覆盖不足 | `#94631B` | `#FBF5E9` |
| 失败 / 阻塞 | `#B13A35` | `#FCF1EF` |

主要辅助文字使用 `#707078`；不直接把浅结构灰用作小字号文字。Overview 的常规标签与表格文字以 14px 为基准，主要内容和控件 14–16px，小型状态标签可为 13px。状态始终包含文字与图标；收益 Paper/Live、交易执行/触发分别表达。环比上升使用 `--change-up: #A14066`，下降使用 `--change-down: #28678A`，均保留方向箭头；颜色只表达方向，不作好坏判断，成本下降不借用成功色。

首轮验证覆盖桌面、窄屏、部分数据、空列表、局部失败、只读、初始化中和初始化失败，以及键盘和 WCAG A/AA 自动检查。该视觉基准不代表真实后端数据与交易功能已完成联调验收。

#### 1.9 用户自用看板约束（2026-09-08，后续页面必须遵守）

- **信息有用途才呈现。** 用户熟悉业务，PRD 未要求且无实质用途的说明性、装饰性、宣传性文案或组件一律不加。移除环境标签、V2 徽标、眉题、口号、装饰页脚、重复说明；保留字段名、必要操作、真实错误、权限限制、数据缺失/覆盖和结果反馈。
- **空间服务于读取。** 标题精简、组件间距紧凑均匀，不使用大量空白或低密度大卡片填充页面。允许通过图标、语义色和 UI 结构强化信息区分，不用额外文案增加装饰。
- **业务决定交互。** Overview 是导航入口，已可访问的标的整行非控件区域均可跳转；行内控制独立操作，键盘仍可使用原生链接。初始化中的标的不开放跳转，不因视觉改动放宽业务约束。
- **可读性优先。** 字体适当放大，表头与内容按列对齐；不能以微小字体换取表面整齐，应调整结构与断点。验收覆盖用户批注的 1262px、906px 和手机宽度。
- **品牌克制。** 本轮移除自创图形标志和 V2 徽标，仅保留可返回 Overview 的 doxagent 字标。以后如需图形标志，使用用户指定的 DoxAtlas 资产，不再自行创造。

执行约束同时记录于 [frontend/v2/AGENTS.md](../frontend/v2/AGENTS.md)，供后续开发直接遵守。此节优先于本文此前与之冲突的宽松装饰建议。

#### 1.10 桌面页面重做规则（2026-09-08）

本次以桌面端为交付边界，使用 1262px 和 1559px 桌面宽度检查；此前手机端条款不再作为本轮要求。实现补充样式位于 `frontend/v2/src/refinement.css`。

- 主导航：全局顶栏的 logo 在左，ticker 选择器位于其右侧；logo 唯一承担返回 Overview 的导航。页面导航居中，使用图标、细分隔线、轻底色与明确选中标记。事件库位于交易策略之后、消息总线之前。
- 阅读：D1 限制正文行宽，章节可折叠；元数据压缩为对齐的字段行。D2 将内容索引放在元数据之前，用不同结构区分 State 表格、Realization Factors 和 Potential Gaps；少量数据也不留下占半行的空卡槽。
- 内容层级：页面范围与内容范围分开组织。策略 KPI 在 Shell 与列表筛选上方；正文标题、条件与历史变更入口有明确从属关系。
- 事件位置索引：常态为右侧短线，悬停或键盘聚焦展开标题，选择后定位原事件并展开；索引仅覆盖已加载列表。
- 消息：固定可用高度的流框，内部滚动和续页；筛选置于流框工具栏。正文按需展开，消息源健康状态独立列。页面模式和日期范围不在同一位置纵向堆叠。
- 运行：采用接收、并行判定、二轮研判、结果四组位置关系；节点与边的数字分别表达，边计数有背景底片。路径绕开未经过节点，选择节点后提供统计、Case 列表与逐次尝试详情。语义颜色不能替代文字。
- 审计：六项紧凑指标、Token/成本双轴趋势、占比与节点表。单日用单组柱，多日用曲线；未知点不连线、不补零，Codex 不映射美元费用。

简洁要求删除无用途信息，但不降低组件、排版、反馈和交互的完成度。实际 V1 页面只用于辨认可读层次和操作组织的优点，不作为 V2 业务或视觉模板。
