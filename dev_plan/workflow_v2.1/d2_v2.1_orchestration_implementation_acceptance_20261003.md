## 2. 恢复与过程工件

- V21 Worker artifact_key 使用 `v21/shells/<hash>/<stage>`，隔离旧阶段身份。
- 原始成功 turn artifact 保留完整 envelope；checkpoint.stage_outputs 保存其 ArtifactRef。先保存成功输出指针，再提交 canonical/sidecar，最后推进 stage。指针不代表效果已完成。
- 冻结 Scan 位于主 run 的 `context/document2/discovery/<hash>/open_discovery_scan.json`，并交付 Shell workspace 的同名 context 文件。
- Selection、累计 late additions、resolution 位于 `artifacts/document2/shells/<hash>/`；主 bundle 以 `discovery:<seed name>:<kind>` 注册，不正式发布。
- late additions 以 `(unit, name)` 累积，同键用最新完整记录替换。研究中间轮 resolution 同样保留、更新；最终轮必须自行返回全部 DEEPEN/late 的闭环，不借累计结果补造遗漏。
- 恢复回放该 Shell 实际使用的成功输出，重建 canonical 及累计 sidecars；成功输出 SHA/类型损坏停止恢复。O0 已记录成功工件损坏同样不静默重跑。
- 最终 destination 可为最终 Unit/Factor/Gap 或邻接 O0 Shell 的 Unit；当前 Shell 已删除的旧 Unit 不能假装仍是有效目标。允许真实结构调整与 destination=null 的自然语言取舍。

## 4. 本轮验收边界与后续接口

内部显式调用入口为 `Document2RunRequest(document_schema_version="document2.v2.1", ...)`，或 Pinned/Pilot 同名参数；缺省均为 `document2.v2`。正式 handoff、workflow identity、repository 协议不变。

本轮依据既定分轮验收，只完成编排与离线合同。生产 prompt/skill 原字节保持不变，新增 Discovery skill 路径仍是预留资产；离线测试只在临时 asset_root 中使用 fixture。真实执行缺失资产时报 `D2_DISCOVERY_ASSET_MISSING` SYSTEM，不生成空 Scan 或默认 PARK。

真实研究语义联调、生产 Discovery 资产和其他新 schema 的 prompt 对齐、消费者适配及启用按约定另轮进行。新版结果保持 staged，不进入现有 current 消费链。
