## 2. 关键运行约束

`codex_document3_v21_runs`、`codex_document3_v21_tasks`、`codex_document3_v21_draft_ids` 是任务/冻结/首次身份真值；`codex_document3_v21_staged_sets` 保存主 JSON、Projection 和交接 manifest。NodeAttempt/ThreadRecord 继续承担审计与会话定位，不另作重试预算真值。配置使用混合或 Postgres repository 时，新编排的耐久状态仍使用配置的本地 SQLite；上游 repository 只读。

版本 reservation 计入旧发布、所有预留、新 staged/base 的最大版本，允许间隔；同 ticker/version 与 run 唯一。发布前冻结 version、published_at 和 F/coverage 摘要；四文件生成、正式副本校验、staged 提交的故障均可恢复，不再次研究或另换版本。staged 不修改旧 current/history/journal/visibility，不调用 O4 或启动消费者。

Worker 输入来自已冻结来源与宿主接纳账本。恢复使用接纳原稿/显式 ID 的工作副本，不按标题或文本 hash 猜 Policy 身份。修改只读输入是局部终态失败；有有效文件但 Worker 回执失败时，接纳已写成果，不以业务内容触发无限重试。结构完整不等于经济正确：宿主仅做引用、身份、文件可消费性和集合完整性修正。

MAINTAIN 必须指定 staged v3 base。无实际 feed/delta/显式维护时返回 NOOP 和 base 版本，无需资产或 Worker；有 Trade/BADCASE/gap 等维护材料时即使无新 Event 仍 dispatch。仅 as_of 改变不发版；真实 Event 元数据改变可发版。缺 patch 为 DEGRADED 且不提交；明确 retire/空处置可以发布空集。patch 未提供 remaining_gaps 时继承 base，显式空列表才关闭；坏 gap 记录不能隐式关闭原 gap。

## 3. 真实入口与外部资产

原 prompt/skill 不修改、不删除，也没有复制旧 Compile 作为新版业务 fallback。真实新节点要求提供已有的外部 UTF-8 资产文件。`--node-assets-manifest`（别名 `--node-assets`）读取 JSON 对象，例如以下占位路径，需替换为实际外部文件：

```json
{
  "role": "C:/external/d3-v21/role.md",
  "common": "C:/external/d3-v21/common.md",
  "discovery": "C:/external/d3-v21/discovery.md",
  "planning": "C:/external/d3-v21/planning.md",
  "build": "C:/external/d3-v21/build.md",
  "integration": "C:/external/d3-v21/integration.md",
  "maintain": "C:/external/d3-v21/maintain.md"
}
```

INITIALIZE 只要求 role/common/四个初始化节点；MAINTAIN 只要求 role/common/maintain。缺项在派发 Worker 前报资产依赖错误。首次运行冻结资产内容/hash，resume 使用已冻结版本。这里不提供或验收业务 prompt 文本。

```powershell
uv run python -m doxagent.workflows.codex_document3.cli initialize --orchestration-version v2.1 --ticker MU --as-of 2026-10-04T00:00:00Z --document2-run-id <published-d2-run> --node-assets-manifest <external-assets.json>
uv run python -m doxagent.workflows.codex_document3.cli maintain --orchestration-version v2.1 --ticker MU --as-of 2026-10-04T08:00:00Z --base-policy-set-version <staged-v3-version> --node-assets-manifest <external-assets.json> --maintenance-feed <feed.json>
uv run python -m doxagent.workflows.codex_document3.cli resume --run-id <d3v21-run-id>
```

新 initialize 的 D2 可省略，可显式指定 `--source-global-run-id` / `--event-library-version`。额外材料用重复 `--additional-material <local-file>` 或 `--materials-manifest <json-list>`；manifest 是文件路径/工作区 artifact 描述列表，完整冻结和校验由 preparer 完成。maintain 另支持 `--delta` / `--explicit-maintenance`，`--base-policy-version` 为 base 参数的短别名。

Python 入口为 `build_document3_orchestrator(settings, orchestration_version="v2.1", node_assets=manifest)`，再调用 initialize/maintain；恢复调用 `resume_v21(orchestrator, run_id)`。PinnedRunner 校验版本匹配，新身份使用 `d3v21-` 前缀及冻结输入；旧 run 不可绑定新版。Pilot 显式选择 V21 后读取新版 task/state/交接指标，不从旧 Shell worklist 推测新版完成度。
