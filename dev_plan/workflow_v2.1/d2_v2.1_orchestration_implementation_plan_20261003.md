# Document2 v2.1 局部编排重构实施方案

日期：2026-10-03（Asia/Shanghai）。依据：`d2_v2.1.md`，包括新增 O0 §§38–42；代码定位见同目录 `d2_v2.1_code_reconnaissance_20261003.md`。

本文件是一版可执行的开发方案，本轮尚未实施业务代码。

## 1. 已确认范围与本方案的固定决策

问答已完成，按用户答复执行：

1. 本轮完成 D2 编排、schema、冻结交接、恢复及离线契约验收；真实研究语义联调与启用留到后续 prompt/skill 改造轮次。
2. **严格只改 D2，O3/W3/Read/API/前端消费者适配另轮。**

因此本轮改动是当前 `codex_document2` 的增量重构。O0 的节点链、来源分支、并行与评审角色不变；O1 每个 Shell 在现有四轮前增加 Discovery 的两个 Turn。沿用当前 Worker、Workspace、Repository、durable substep、模型配置、并发控制、artifact/citation 和发布机制。

不修改 `prompts/` 下任何文件；不把研究方法塞进 Python 生成的 prompt、context 指令或 schema description；不引入新调度器、新 Agent、新数据库表、新 workflow/lane、新审批流程或经济语义规则引擎。不改 legacy `workflows/document2/`。

其余实现决策固定如下，不再增加问答：

| 决策 | 具体做法 |
| --- | --- |
| Workflow identity | 保持 `codex_document2_v1` 和 DOCUMENT2 lane，不升级全局 workflow version |
| Published business version | 新增原生 `document2.v2.1`；历史 `document2.v2` 保留原解析类型 |
| 新版执行选择 | 在内部 `Document2RunRequest` 加 `document_schema_version`，默认 `document2.v2`；v2.1 由离线测试/直接 D2 调用显式选择 |
| 普通启动入口 | 本轮不修改 dashboard/initialization/scheduler，现有默认继续 v2；不新增对外新版启动 API |
| 新版 staged 发布 | 测试可覆盖完整 Publish；本轮 v2.1 bundle 不成为 current，不写生产库或运行生产研究 |
| O0 identity | 正式 Shell/Unit 只用 name；保留必要的临时 review handle，来源限定 candidate_ref 由编排派生 |
| name 作用域 | Shell 在 Document 内唯一；Unit 在 Shell 内唯一；研究对象在所属 Unit 内唯一；Discovery 以 Shell+Unit+name 定位 |
| O1 返回 | Discovery 分别返回过程对象；四个研究回合统一返回完整 canonical_shell + 本轮 late_additions + 本轮 resolution 的结果 envelope |
| Scan 冻结 | 利用现有不可变 `context/` 和 SHA256，不修改共享 WorkspaceStore |
| 候选审计 | 程序只检查真实身份/引用/覆盖完整性，经济取舍理由由模型输出；不制造默认 resolution |
| Thread | 保持当前新线程执行，所有业务资产显式注入；不建立 hidden-thread continuity |
| 历史兼容 | 保留旧模型 module/class 名；不把旧 thesis、Factor、Gap 机械升级为新版研究成果 |

分版本仅用于旧执行/冻结记录的兼容与新版暂存。只有一个编排器和一套持久化路径，不复制第二套 workflow engine。后续启用新版时无需另起平台，只需完成资产/消费者改造并调整默认选择与 current 行为。

## 2. 本轮完成后的实际流程

```text
既有 Input Preparation
  ↓
既有 O0 来源分支并行 Candidate Discovery（新版输出）
  ↓
既有 O0 Synthesis（新版 provisional topology）
  ↓
既有 C1/C3/C5 Domain Review（新版 topology 输入）
  ↓
既有 O0 Finalization（name/scope/boundary/horizon/ref seeds）
  ↓
Per Shell，保持既有 semaphore：
  Discovery Full Scan
    → 冻结 open_discovery_scan.json
    → Discovery Selection
    → State + Expectation Baseline
    → Realization Factors + Materiality Context
    → Potential Gaps + Possibility Space
    → Research Finalization + Discovery Resolution
  ↓
既有 Assembler/Publish：新版正式 JSON + 引用 manifest + 摘要
```

不同 Shell 仍并行；同一 Shell 六次调用严格串行。Scan/Selection 不合成一个 Turn。过程资产不进入正式 Shell，也不加入 Published D2 的研究内容。

## 3. Schema：保留旧类型，增加少量明确的新类型

### 3.1 文件安排

在现有 `src/doxagent/workflows/codex_document2/schema.py` 增加 `...V21` 类型，保留所有旧 class 名及其字段语义。复用 `AgentModel`、`ContractModel`、typed StateValueData、SourceRole、ValidityState、InputManifest、citation/artifact 等公共类型。

不新建通用版本注册框架，不使用 validation_alias 把 proposition 当成 scope。旧模型继续用于旧读取、旧 invocation、旧测试与普通 v2 路径。

### 3.2 O0 新版结果模型

CandidateDiscoveryResultV21

Synthesis 仍以一个保留 candidate_ref 定位主要候选；其他来源的重复候选在 unassigned 中记录合并理由，沿用当前 disposition 方式。保留 why_material/ref，避免现有 provisional schema 丢失原候选依据。

`candidate_ref` 由编排按 `<SOURCE_ROLE>:<candidate.name>` 派生，例如 `C3:商业Foundry`，不要求模型另生成 candidate_id。它只用于输入/过程产物；正式 Seed 不含 candidate_ref、shell_temp_id、feedback_id。分支同名冲突通过有限格式重试修正，不自动给名称加序号；跨来源同名仍保留为独立来源候选交给 Synthesis 判断。

Domain Review 保留三个原角色和原 feedback 结构。**本轮不在代码中实现 Reversal/Open Catalyst/Multi-path/Thesis Leakage 检测，也不新增五个布尔验收字段。**

### 3.3 O1 与 Published 新版模型

```text

  units: list[ExpectationUnitV21]

  name / mechanism / current_status / materiality_context / scope_boundary / ref

```

正式新版完全移除 proposition、core_question、boundary_rule、所有旧业务 *_id、structural_role、observability、possible_occurrence、expected_revision、recognition_criteria。旧字段只存在于保留的 v2 类型和内部兼容运输结构。

数组采用空列表默认值，不因没有 Baseline、某个 source role 或某类 Gap 就填 UNKNOWN。Ref 采用 `list[str]` 默认空列表；现有 strict_json_schema 仍要求模型输出这些键，允许输出 `[]`，不要求一定有来源。

`Document2DocumentV21` 的正式 envelope：

```text
schema_version = "document2.v2.1"
workflow_version = "codex_document2_v1"
document2_run_id

ticker / as_of / input_manifest

```

保留 run/source identity 是现有来源绑定，不新增业务 ontology。`ShellOutcomeV21` 使用 `shell` 表示名称，并保留 status/failed_stage/failure_kind/error；artifact_id/error_code/seed 作为已有故障诊断 envelope 保留。Seed 使用 V21 Seed。不能因为需求 schema 示意较短而丢掉失败 Shell 的标题与定位。

内部 `Document2Bundle` 继续复用现有结构和 HandoffV1。`ShellOutcome.shell_id` 可作为内部运输键保留，其值为新版 Shell name；将 seed 类型扩大为旧 Seed 或 V21 Seed，生成正式 V21 时明确转换成 `shell`。不升级 repository 表或 handoff 协议，不把这个内部键泄漏进新版 shells。

## 4. Discovery 与研究回合的过程契约

### 4.1 Full Scan

```text
OpenDiscoveryScanV21
  shell: str
  units[]
    name: str
    candidates[]
      name / change_hypothesis / relevance / live_basis / ref
```

无 Candidate ID，无数量配额、排序 score 或行业 taxonomy。允许一个 Unit 的 candidates 为空；要求输出列出所研究 Seed 的各 Unit，空列表表达确实无输出，不以空列表自动判经济研究失败。

### 4.2 Selection

```text
OpenDiscoverySelectionV21
  shell: str
  selections[]
    unit: str
    candidate: str
    decision: DEEPEN | MERGE | PARK
    merge_into: str | null
    reason: str
    research_focus: str
    ref: list[str]
```

unit 是所属 Unit canonical name，消除不同 Unit 的同名 candidate 歧义。MERGE 限定在同一 Unit 候选域内，target 必须存在、不能自指或成环，最终落到 DEEPEN 或 PARK 的实际取舍。合并后的主题也可以合理暂缓，不强制转为 DEEPEN。跨 Unit/Shell 覆盖采用 PARK 加理由，由相邻 Unit 承担；不额外创建跨 Shell 调度或研究依赖。

每个冻结 candidate 恰好一条 Selection；不能删除、改写原 Scan，也不能在 Selection 中偷偷新增 candidate。新发现走 late_additions。DEEPEN/PARK 的 merge_into 为 null。

### 4.3 统一研究结果 envelope

State/Realization/Gaps/Finalization 四轮全部使用同一个：

```text
ShellResearchTurnResultV21
  canonical_shell: ExpectationShellV21
  late_additions[]
    unit / name / discovered_during / change_hypothesis / reason / ref
  open_discovery_resolution[]
    unit / candidate / resolution / destination / reason
```

unit/candidate 按发现时的作用域定位；destination 是最终 Factor/Gap/Unit canonical name 或 null。Resolution 是自然语言，不新建 enum。前三轮可以返回空 resolution；Finalization 应返回全部 DEEPEN 与 late additions 的最终去向，先前 MERGE/PARK 的过程理由由 Selection 保留。

每轮返回完整 Shell，编排提取 canonical_shell 继续交接，并单独持久化过程字段。这避免额外字段被 `extra=ignore` 或 `ingest_model` 丢弃。不会把 envelope 原样作为正式 D2 发布。

late_additions 表示本轮新增或对同一候选的补充记录；编排按 `(unit,name)` 维护一个当前集合，保存每轮原始 envelope 作为完整审计。不同身份追加，相同身份内容相同则幂等保留，相同身份内容更新则采用该轮完整记录；不以文本相似度自动合并，不回写原 Scan。discovered_during 应与当前研究阶段一致。

## 5. 局部编排实现

### 5.1 新节点和阶段

`codex_runtime/schema.py` 的 `CodexD2Node` 只新增：

```python
O1_DISCOVERY_SCAN = "d2_o1_discovery_scan"
O1_DISCOVERY_SELECTION = "d2_o1_discovery_selection"
```

`data_runtime/policy.py` 的 `_ROLE_BY_NODE` 只将这两个节点映射到既有 O1，沿用 O1 research tool union，不修改其他 role 权限。这两个共享文件的 D2 增项属于 D2 自身登记，不是消费者适配或 Data MCP 重构。

`ShellResearchStage` 增加 DISCOVERY_SCAN、DISCOVERY_SELECTION。保留既有 stage 名以解码旧记录；failure stage mapping 同步加入两个节点。

### 5.2 一个编排器，静态选择契约

在 `orchestrator.py` 内增加一个私有、只读 D2 契约描述，按 request.document_schema_version 选出 O0 output models、Shell/Seed/Document models 和 O1 stage tuple。它是静态两版本映射，不是动态 DAG/插件注册系统。

v2 stage tuple 仍为原四项；v2.1 为新增两项加原四项。复用 `_construct_shells()` 的分支任务与 `_run_with_retry()`，仅用选中的类型替换 output_model，完成新版 candidate context 和 seed 初始化。

O1 循环的最小结构：

```python
shell, state = restore_shell_and_state(...)
for spec in selected_contract.o1_stages:
    if has_recoverable_success(state, spec):
        restore_stage_assets_if_needed(...)
        continue
    context = build_o1_context(shell, prepared, topology, state, spec)
    turn = await run_with_retry(output_model=spec.output_model, context=context, ...)
    # Runner 已做该 turn 的结构完整性校验
    shell = await apply_stage_result_and_save_assets(shell, state, spec, turn)
    await save_progress(...)
return await write_final_shell(...)
```

Scan/Selection 的 apply 不改 Shell。四个研究回合只从 envelope 提取完整 canonical_shell，处理过程 sidecar。checkpoint 的 stage 始终代表最后成功提交的阶段，失败保留该阶段和 error，不将恢复点重置为零。

### 5.3 O0 正常链路和 fallback

- Candidate/Synthesis/Review/Finalization 沿用原节点和原角色，契约按版本选择。
- `_candidate_sets_context()` 与 Pilot helper 复用同一个来源定位规则，V21 从 source+name 派生引用。
- `_restore_or_initialize_shell()` 的 V21 分支按 Seed 创建空 state/baseline/factors/gaps，保留 name/scope/boundary/ref/horizon；不构造 proposition。
- `recovery.py` 按 output_model 明确区分旧/新 fallback，不通过字段重命名猜测版本。
- V21 Synthesis fallback 可将已有 Candidate 分别保留为 provisional Shell：使用已有 name/scope/ref，boundary 为空表示未形成排他判断，记录 SYNTHESIS_UNAVAILABLE。不得把 why_material 当 boundary。
- V21 Finalization fallback 保留 provisional Shell/Units 的 name/scope/boundary/ref；未知 horizon 保持 UNRESOLVED，并记录降级 warning。过程 handle 不成为正式 name。
- fallback 只保留已存在业务文字，不创造因果模型或新的研究判断。Candidate 为空时维持现有零 Shell/PARTIAL 语义。

### 5.4 Context 的明确构造

O0 common 在 V21 路径增加实际 Event Library 与 entity_relations，复用已冻结 prepared inputs；原 Future Nodes/Horizontal 保留。每个 Candidate 仍只以 assigned primary_source 为主，不给全部分支重复塞三份报告。Synthesis/Finalization 继续使用候选/评审已形成的资产，不重新研究 D1。

O1 所有六轮的 base context 一致包含：

```text
ticker
document_schema_version
research_cutoff_at
source_global_research_published_at
canonical_shell
o0_finalization                     # 全部最终 topology
global_research                     # C1/C3/C5/Entity/Future/Horizontal
narrative_research                  # 包含 availability
event_library                      # 包含实际 payload/availability
turn
```

Selection 起追加完整 frozen `discovery_scan`；State 起追加完整 `discovery_selection` 和累积 `late_additions`；Finalization 再追加先前已有 resolution（若有）。不依赖上轮 thread 中的记忆，不只注入 candidate 名单或摘要。

prepared_inputs 仍 write-once，retry 不重新拉最新数据。可选资产不可用仍带状态继续；不新增 Narrative/Event Library 必须可用的门槛。

### 5.5 Asset 接口边界

新两个 Turn 预留现有 asset resolver 路径：

```text
agents/o1.md
skills/open-discovery-scan.md
skills/open-discovery-selection.md
```

本轮不创建这两个 production skill，不修改旧 skill，也不拿 Gap skill 冒充 Discovery。Runner 的 generic 调度文字只要求读文件、按 schema 返回；不承载研究方法。

离线 tests 使用临时 asset_root 中的占位测试文件及 fake Worker；文件仅用于验证注入/调度，不能作为生产方法交付。真实执行缺必要资产时沿用明确的文件/系统失败，不用空 Scan 或默认 PARK 伪造完成。普通 v2 路径和默认 asset resolver 保持原行为。

## 6. 冻结、sidecar 和恢复的具体落盘方式

### 6.1 每个 Shell 的四类过程文件

`key = sha256(shell.name)[:16]`，沿用当前 hash 目录策略。

```text
主 run/context/document2/discovery/<key>/open_discovery_scan.json
主 run/artifacts/document2/shells/<key>/open_discovery_selection.json
主 run/artifacts/document2/shells/<key>/open_discovery_late_additions.json
主 run/artifacts/document2/shells/<key>/open_discovery_resolution.json

Shell child workspace/artifacts/shell.json
Shell child workspace/context/document2/open_discovery_scan.json
```

Scan 主副本及 child context 副本使用现有 write-once context。保存成功 metadata 为 ArtifactRef；同内容重写幂等，不同内容重写会报 ImmutableWorkspacePath。Selection 的原始 attempt snapshot 一直保留；Late Additions 是独立文件，不覆写初始 Selection 的取舍记录。

可变 sidecar 写入时更新其当前 ArtifactRef/hash；每个 turn 的完整 result snapshot 都保留，提供修改前后审计。四个过程文件都登记主 run artifact，bundle 的 key 采用 `discovery:<shell-name>:scan/selection/late_additions/resolution`，不进入 Published whitelist。

### 6.2 复用 checkpoint，只加所需字段

`Document2Checkpoint` 加 `document_schema_version`，旧记录缺失时默认为 document2.v2；不更换已有 checkpoint schema identifier 或数据库结构。

`ShellRunState` 保留内部 shell_id/workspace/thread/stage 等字段，shell_id 的 V21 值取 name，追加：

```text
canonical_sha256: str | null
stage_outputs: dict[str, ArtifactRef]
discovery_scan_ref: ArtifactRef | null
discovery_selection_ref: ArtifactRef | null
late_additions_ref: ArtifactRef | null
discovery_resolution_ref: ArtifactRef | null
```

stage_outputs 指向每个成功 turn 的主 run 原始结果 artifact，包含 envelope，作为恢复真源；snapshot_paths 保留用于旧接口/审计。

### 6.3 成功提交顺序

```text
Runner 解析及结构校验成功
  → 保存带来源限定引用的原始 turn artifact
  → 编排保存 Scan/Selection 或研究 Shell/sidecars
  → 填入所有 ArtifactRef/hash
  → 标记该 stage 成功
  → 用现有 checkpoint lock 保存 bundle/checkpoint
```

持久化失败不标记该 stage 完成。Runner receipt 已成功而编排中断时，下一次通过现有 durable codec/该 turn artifact 重新提交相同结果，**不重新调用模型**。不要求跨 Workspace/SQLite 新建分布式事务。

Scan stage 不完成就不进入 Selection。Selection stage 不完成就不进入 State。Scan 冻结后即使 Selection/State 后续失败也不重新扫描。

### 6.4 恢复时只检验要用的工件

V21 路径读取对应 stage_outputs，校验 SHA256 并以该阶段 typed output 解析。Shell canonical 缺失、内容损坏或与 canonical_sha256 不符时，从最近成功研究 envelope 恢复完整 Shell；尚未进入研究则由 Seed 初始化。恢复 Scan/Selection/Late/Resolution 按 checkpoint refs 或对应成功 output 重建。

**不沿用“canonical 读坏就退回 Seed，但 stage 继续跳过”的路径。** 最后成功输出也确实丢失/损坏时，记录明确 artifact integrity/system failure，不静默回退、拼接或伪造研究成果；其他 Shell 的健康结果按既有错误分类处理。

不扫描全部历史工件，不在每次正常 turn 重验整个 run，不建立新 lease/lock。

### 6.5 durable 与历史记录

沿用 `@durable("d2")`，现有 codec 已按 output_model 解码，新的 V21 类型保持在仓库 module 内即可。Scan/Selection 有不同 node；artifact_key 再采用 `v21/shells/<key>/<stage>`，防止与旧阶段身份混用。

旧 Pydantic class 的 module/name 不改，旧 frozen invocation 可继续定位它们。新增类型不要求修改通用 invocation encoder、DurableWorker、repair agent 或初始化协调器。

同一 run_id 不允许将旧 v2 checkpoint 改成 v2.1。进入 `_run()` 时先核对 request 与已有 checkpoint/Published document 的版本，再决定是否复用；错版明确要求新 run。force_new 不等于允许覆写同一 run 的 immutable context。

内部新版测试/独立调用采用单独 `...-d2v21-...` run ID。`PinnedDocument2Runner.run_pinned()` 增加可选 `document_schema_version` 参数并传给 D2 request，默认仍 v2；仅 V21 run identity 增入 document schema version 与 research cutoff，v2 identity 算法保持原样。不修改 dashboard/初始化自动 run ID。

## 7. 仅做结构完整性校验

新增 D2 私有 `validation.py`，由 `Document2TurnRunner` 在解析 output 后、保存成功 receipt 前调用，使用当前 node、实际 output model 和冻结 context。V2 沿用原校验行为；V21 只做下表检查。

这比把 validator callback 当 runtime 参数传入 durable 更简单：无函数序列化，无通用验证插件。

| 输出 | 校验内容 | 明确不检查 |
| --- | --- | --- |
| O0 Candidate | 同一来源 name 唯一，必要字段类型正确 | 是否 bullish、禁词、经济重要性打分 |
| Synthesis | 输入 candidate_ref 有有效去向；引用存在，无同一候选重复归属 | 按数量强制拆 Shell、按文本自动归并 |
| Final Seeds | Shell/Unit name 唯一 | 每 Shell 必须几个 Unit、scope 经济语义优劣 |
| Full Scan | Shell/Unit 绑定输入 Seed，候选名在 Unit 内唯一 | 最低候选数、内外比例、现实依据充分程度 |
| Selection | 精确覆盖冻结候选，merge target/终点/环检查 | DEEPEN/PARK 是否经济上正确 |
| Research Shell | 名称作用域、Parameter 绑定、value_type/value 形状一致 | 每个对象必须带来源、每 Unit 必须有 Baseline/Factor/Gap |
| Late Additions | unit/name 作用域、stage 与本轮一致 | 候选必须预先在 Scan 中存在 |
| Finalization | 每个 DEEPEN 及 late addition 有 resolution；非空 destination 可在最终对象/已知邻接 topology 中定位 | 强制成为 Gap、resolution enum、自动编造取舍理由 |

格式或覆盖不完整沿用 FORMAT 和既有 bounded retry，previous_failure 记录具体缺失/冲突位置；达到现有重试上限仍不完整，则失败隔离该 Shell，不新增全局质量门槛。Full Scan 的 frozen input/hash 损坏属于真实系统完整性问题，不能被重试成另一份扫描。

O1 仍可返回真正必要的完整结构修正，不添加“必须逐字保留全部 Unit”的锁。发现时的候选 Unit 作用域保留为来源定位；最终若移到另一 Unit/Factor/Gap，用 resolution.destination 说明去向，不因 Unit 重组静默丢弃 DEEPEN。程序不自动重写候选身份。

## 8. Assembly、引用与本轮发布边界

### 8.1 正式 assembly

`assembler.py` 的 assembly 接受按版本选定的 Shell 和 document model。引用 lineage/resolution 复用当前 remapper，V21 增加一个明确的 ref 遍历函数，只访问：

```text
Shell.ref
Unit.ref
State.parameters[].ref
State.values[].ref
ExpectationBaseline[].ref
RealizationFactor[].ref
PotentialGap[].ref
```

不递归把任意字符串当来源，不处理不存在的 possibility ref，不把过程 candidate/ref 强行并入正式来源。当前 local O# 仍限定到 attempt，D1/DoxAtlas/URL 格式保持。

O0 turn 的 citation manifests 也通过现有 attempt_workspaces 收集，保障 Seed 上的 ref 可进入最终正式引用。过程 sidecars 保留 D1/D2REF/URL 原始 lineage；Published 的正式 refs 再统一成最终 citation aliases。引用失败仍非阻断。

Markdown 摘要按新版 Shell/Unit name、scope、boundary、horizon 和 State/Baseline/Factor/Gap 数量输出；不扩展为新的长研究报告产品。

### 8.2 失败与发布

沿用成功 Shell 入 shells、失败 Shell 入 outcomes 的语义。非空所有 Shell 成功才 COMPLETE；零 Shell 或存在失败是 PARTIAL。Finalization closure 未完成的 Shell 不记 completed。

保留既有 SYSTEM/TRANSIENT/FORMAT/SHELL 分类、lease/权限/请求错误边界、两轮默认 retry 和 initialization 显式 max_attempts 配置；不擅自提高重试次数。

正式 Publish whitelist 仍只有 document/citation/markdown/最终 Shell/Seeds。新过程资产可在 run 中保存和恢复，**不加入正式 Published D2 内容**。

V21 仍可以在隔离测试中形成 Published record/handoff，证明发布链路可工作；本轮 `bundle.current=False`。普通 v2 的 COMPLETE→current 行为保持。没有新的“业务 ready”状态 enum，也不创建推广服务；后续消费者/方法就绪后再调整新版 default/current，这属于明确另轮启用。

不要调用生产 write/publish。即便 current=false，现有消费者也可能枚举历史 Published runs，因此 staged V21 record 只能存在于隔离测试/开发 workspace。

## 9. Pilot 的 D2 内部同步

Pilot 不是消费者，属于 D2 编排验收通路，本轮同步：

- case/coordinator request 支持 document_schema_version，默认 v2；case manifest 记录该值。
- V21 stage dependency 增加 Scan→Selection→State；O0 stage 数量/节点不变。
- `_bootstrap_contract()` 选择 V21 output model，研究四轮选统一 envelope。
- 后续研究 context 从上游 envelope.canonical_shell 提取；同时读取 Scan、Selection、late additions，而非将 envelope 当 Shell。
- O0 finalization override 使用当前版本 Seed model；选 Shell 支持 name 或已有 hash，旧选择继续 shell_id/hash。
- Candidate 引用 helper 与主流程复用同一规则，不保留两套可能漂移的定位逻辑。
- Bootstrap 读取已冻结 prepared inputs 时带入实际 Event Library；没有可用 Published view 时沿用 availability 继续，不能固定伪装 AVAILABLE。
- 临时测试 assets 只用于离线调度；不运行真人模型 Pilot，不以 fake output 判断新版研究方法有效。

`Document2PilotCaseBuilder` 构造器增加可选 `event_library_provider` 注入，缺省采用现有 Unconfigured provider；Bootstrap 按 pinned D1 与该次 cutoff 调用既有 provider，形成 OptionalInput。有 frozen prepared_inputs 的 source-attempt 路径直接复用，不重新查询。复用现有 OptionalInput/InputManifest 类型和 D2 context 构造 helper，无新增数据服务。主流程与 bootstrap 不另写不同的 Discovery context。

## 11. 离线验收矩阵与执行命令

不做全库扫测。先复用已有 D2 基线，再补必要断点与新契约反例；本文件中的命令是后续实施命令，不是本轮已运行结果。

### 11.1 新增必要验证

1. **Schema/O0：** 新 Seed 无 proposition/core_question/boundary_rule；Candidate→Synthesis→Review→Final 的 scope/ref 保留；source+name 不串分支；新 fallback 不生成 thesis。旧 v2 schemas/fixtures 不变。
2. **阶段/context：** 一个 Shell 六轮、两个 Shell 可并行；Scan 含完整 topology 与可用 Event Library；Selection 精确读 frozen Scan；后续 context 包含累计 sidecars。
3. **冻结：** Scan 成功后 Selection 失败，恢复不调用 Scan；改原 Scan 被不可变存储/hash 检查拒绝；可选 Event Library 缺失不阻断。
4. **闭环：** 缺 Selection、MERGE cycle、缺 DEEPEN resolution、destination 不存在能定位 FORMAT；反例允许 PARK、吸收 Factor、并 Gap、相邻 Unit 和影响不足；不按对象数量 gate。
5. **提交中断：** Worker/receipt 成功后、canonical/sidecar 写失败再恢复，无新 Worker 调用；缺 canonical 能用上轮 envelope 恢复；真 artifact 丢失明确报错。
6. **Late additions：** State/Realization/Gaps 新候选可加入；重试不重复；Scan 不变；Finalization 覆盖新增方向。
7. **发布：** 正式 V21 只有新版业务字段，四类过程资产不进入正式 release；Shell/Unit/Parameter/Baseline 的 ref 被纳入 manifest；未解析 ref 仍可发布。
8. **局部失败：** 一 Shell Discovery 失败另一健康完成；零 Shell/PARTIAL 与系统请求错误保持原语义。
9. **版本：** 旧 request/缺版本 checkpoint 默认为 v2；旧 successful receipt 按旧 class 解码；错版相同 run 不复用；V21 staged 不替换 current。
10. **Pilot：** bootstrap/source-attempt 两路径读取正确 output models；研究 envelope 不被当成 Shell；Full Scan/Selection 的成功状态分别保留。
