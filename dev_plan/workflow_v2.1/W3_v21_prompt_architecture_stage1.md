# W3 v2.1 提示词层重构：架构与决策逻辑设计

**阶段：第一步——基础诊断、职责对齐与总体架构。**  
**后续用途：**为第二步的具体写作方案及 `AGENTS.md`、单一 `skill.md` 产出提供结构性依据。本稿不是最终提示词，不修改业务代码、运行合同或原始研究文件。

## 0. 核心设计结论

本次不是将旧 `agent.md` 改名为 `AGENTS.md`，再把两个旧 skill 拼接起来。需要同时改变三个相互关联的结构：

1. **决策对象：**从“某项新事实能否沿产业链影响公司”，转为“当前信息是否改变了市场对这个 ticker 的重要认识，以及这种改变此刻是否值得交易”。其中既包括经济现实的变化，也包括可信披露、纠正、解释和传播层级变化引起的市场认知变化。
2. **工作组织：**从“先完整恢复 NEW/OLD × Policy 状态，再进入未覆盖分析并统一交付”，转为“同一 Case 内先形成交易决策，再完成事实与运营；三种 case_type 使用不同的研究起点和复审尺度，共用机会核验及策略边界”。
3. **证据权限：**D1/D2负责研究框架，Policy负责预先研究过的边界，当前消息与针对性搜索负责本次关键变化，历史/PIN负责连续事件背景；价格只有一个权限——在识别到显著、与本次催化相对应的已完成重定价形态时，否定继续交易该机会，不能生成或强化任何交易方向。

最终只维护两个规范文件：

| 文件 | 主要职责 | 不承担什么 |
|---|---|---|
| `AGENTS.md` | 稳定身份、DoxAgent业务目标、W3节点价值、核心交易心智、证据与记忆边界、行为原则和策略硬边界 | 不铺开所有分支SOP，不重复完整输入/输出schema，不保存动态ticker观点 |
| `skill.md` | 两阶段任务调度、不同case_type及标签的处理、具体研究方法、固定机会核验、路径选择、事实与WATCH/PIN运营规范 | 不再定义另一套角色，不恢复旧四象限准入，不拆成多个独立skill或专家 |

**最关键的取舍是：对可信的Policy研究成果减少重复证明，对未预编译的开放事件加强市场重要性判断；对所有Case统一完成机会核验，但不让行情研究演变成技术交易。**

### 1.2 必须显式覆盖的旧规则

| 事项 | 旧文本或材料中的表述 | 本次设计采用的口径 |

| D1/D2 | 既有expectation baseline，容易被直接当成当前市场共识 | 可信研究框架，不全面重审；只对本次交易的关键变量及其比较基线做必要外部核验 |

| 任务交付 | 交易、事实和运营一次性完成 | Task 1先交易决策；Task 2继承并运营，不重发、不撤回、不改写交易 |

### 1.3 本轮不擅自改变的编排边界

保留三个结果 `NO_TRADE / POLICY_TRADE / EXPERT_TRADE`、两个连续Task、既有Router入口、Condition的OR关系、Policy方向消费规则、72h历史、48h子Thread期限、WATCH/PIN对象及容量。新提示词不自行创造第四种交易结果、第三个Task、动态Policy改写能力或外部消息收藏功能。

正常置信OLD且无有效WATCH的消息仍可能根本不进入W3。**“某条旧事实经重要媒体传播可能重新产生机会”只描述已进入W3后的判断空间，不暗中修改Router。**若未来要覆盖所有这类传播升级入口，需要单独改编排，而不是在W3中假装这些消息已经会被送入。（依据：S1 L58–76、L90、L296–304。）

## 2. 旧提示词为什么没有阻止已知错误

### 2.1 不是“没有写Surprise”，而是定义、决策条件与执行顺序没有形成约束

旧版已经写了不少正确原则：不能把新闻性当交易性、NEW可以NO_TRADE、研究缺失不等于市场未知、区分Forecast与Actual、关注Materiality、无需等到最终财务兑现。不能把这些已有内容重新写一遍就算完成重构。

问题主要集中在：**最终行动条件仍容易落在“非琐碎变化＋方向清楚”；流程先帮助模型找到一个受影响变量及合理传导，再要求它判断大小；而终止研究的条件没有覆盖当前传播阶段与实际交易机会。**

### 2.2 旧文本—错误表型—结构性修正

| 诊断 | 旧文本依据 | 容易形成的行为 | 本次结构性修正 |
|---|---|---|---|
| D1．角色仍在寻找未覆盖机会 | S3 L13、L33–38；S4 L3–13 | 把“未被Policy覆盖”当成需要主动补出交易逻辑的任务；面对HIT又只恢复状态而不处理当前机会 | 统一二轮研判身份；Case价值不以是否发现Expert交易衡量 |
| D2．交易门槛的正向定义过弱 | S3 L85–90：“非微不足道”；S5 L106–110：“非琐碎…方向性传导” | 温和/中等利好仍可TRADE；NO_TRADE主要发生在方向无法成立，而非机会没有足够分量 | 交易依据改为ticker级市场认知变化及其重要性；Policy已有校准可被继承，OPEN不能只证明方向 |
| D3．不确定性被统一折扣 | S3 L90；S5 L106 | “有局限但不否定方向”成为通用放行句；关键因果前提缺失也被当成普通后续风险 | 区分量级不精确、因果前提不成立、净方向不明及已知影响过小 |
| D4．先选局部变量，后补重要性 | S5 L19、L28–38、L70 | 容易被新闻标题或D2局部Unit带入长链推演，成熟业务常规更新也被包装成公司级Surprise | 在细读业务切片前形成简短的ticker定价主线框架，再判断本条信息改变了什么 |
| D5．研究基线与市场基线存在黏连 | S3 L44–46、L62；S5 L24、L61–84 | 虽然明文禁止“缺失=市场未知”，但实际仍从D2/KB未覆盖推导出独特新机会 | D1/D2仅提供框架；对交易关键变量单独建立可比的、外部可核查的基线 |
| D6．搜索只有条件性澄清，没有固定传播核验 | S5 L55–57、L70–72 | 正文看起来完整、D2基线看起来够用时，不必查最早公开源；因此转载可直接交易 | 每个Task 1均有固定来源时序与传播研究，以及IBKR完成态核验 |
| D7．四问结束规则允许过早完成论证 | S5 L112–123 | 知道发生了什么、以前预期、变化与传导，就认为研究结束；没回答“为什么此刻仍有机会” | 完成条件包含差异化价值判断、机会核验与历史关系，不增加完整投资报告要求 |
| D8．状态恢复成为前置长任务 | S4 L41、L70–107 | 先系统性复核Novelty及整个Policy universe，再重新进入另一skill研究；同一信息重复理解 | 必要疑点围绕当前交易一次解决；正式事实/coverage编排交付放Task 2 |
| D9．把业务状态冻结为输出前提 | S5 L129–135；S4四象限表 | 固定NEW、固定无Policy限制判断空间；事实OLD或有Policy便截断独立交易 | 入口类型是研究起点，不是最终结果；旧式mode和四象限彻底退出 |
| D10．交易与运营交付绑在一起 | S3 L94–103；S4 L109–137；S5 L125–148 | 交易已形成仍等待Fact、ID、coverage等整理 | 两阶段共享分析，第一阶段只提交交易，第二阶段才交运营 |
| D11．共享记忆与价格边界没有可执行闭环 | S3 L49的Thread原则；三份旧文件无固定历史审阅和价格用途隔离流程 | 新线程/旧Reference View下重复研究同催化；技术文章中的价格信号可能进入reasoning | 显式使用72h/PIN；价格单向否决权限；并发幂等仍由宿主负责 |

以上是文本诱导与实际表型之间的匹配，不是对具体模型内部过程的断言。尤其D4：旧文“研究面没有固定主次”不等于明确要求所有业务经济权重相等；它的问题在于**没有另外建立市场定价主次**，使输入组织原则容易被误用为交易权重原则。

### 2.3 必须保留、但重新放置的旧版优点

保留事实陈述状态、可比较的Prior、明确的Delta、净经济传导、事实与投资判断分离、Condition独立充分且OR、聚焦问题的搜索、无需终局确认等能力。

这些内容不再围绕旧模式分别复制，而要分别归入共同心智和单一skill的对应方法。**“无需终局确认”继续保留，但它不能再替“本次变化有没有足够分量”作答；“普通不确定性不否定机会”继续保留，但只适用于交易命题核心已经成立的情况。**

## 3. 新版W3的四个正交维度

新版最容易写乱的地方，是把阶段、case类型、标签和交易路径混成同一套模式。架构上必须分开。

### 3.1 阶段决定“本轮做什么、交什么”

- **Trade Decision：**完成本次必要判断与固定机会核验，提交三选一结果。
- **Post-Decision Operations：**继承前一阶段，提交novelty、实际Policy HIT、Fact与WATCH/PIN动作；不再交易。

这是同一Case的两次连续任务，不是先后两个独立专家。Task 2不能成为Task 1逃避关键事实核查的借口；只把**不改变当下选择的整理和运营工作**移到后面。（依据：S1 L129–153；S2需求六。）

### 3.2 case_type决定“从什么研究基础出发、采用什么复审尺度”

| 主类型 | 起点 | 主要任务 | 默认研究姿态 |
|---|---|---|---|
| `POLICY_HIT_REVIEW` | 上游认为已经达到预编译Condition | 验证当前机会仍有效；排查触发关系和Policy本身的明显问题 | **倾向接受已有研究，必要核验后迅速放行** |
| `POLICY_RELATED_EVALUATION` | 已经找到相关传导框架，但未HIT | 区分真正未达经济门槛、触发漏判、情景缺口和边界过严 | **主动寻找已有框架下仍可交易的合理变化，不以未HIT结束** |
| `OPEN_EVENT_EVALUATION` | 没有现成Policy关系 | 独立建立ticker级市场意义、有效变化和净方向 | **更完整论证，严格区分研究价值与交易价值** |

三种类型不应承受相同的从零举证负担。这既是时延设计，也是业务判断尺度的差别。HIT和RELATED的既有研究支撑，要真正改变W3的行为，不能仅在文档里写一句“优先级较高”。

### 3.3 additional_tags决定“哪处疑点或连续性值得注意”

标签只作叠加提示，不生成另一套SOP或第四类Case；其具体处理见第6节。LOW不等于保守拒绝，WATCH不等于必须等待，RECENT_TRADE不等于重复成交。

### 3.4 decision决定“本次选择哪种交易表达”

`NO_TRADE / POLICY_TRADE / EXPERT_TRADE` 是结果，不是主类型的一对一映射。Policy Trade与Expert Trade平行、互斥，不是系统自动降级链。HIT可以Expert，RELATED/Open复核发现真实Condition也可以Policy Trade。（依据：S1 L80–111、L253–304。）

**架构上的组合是：两个阶段 × 三种研究起点 × 可叠加提示；不是六套独立专家、三套交易许可证，或二十多种分支提示词。**

## 4. 核心交易心智：围绕市场的重要认识，而不是围绕公司全部业务

### 4.1 定价主线先于局部传导，但不成为新白名单

每个交易阶段先形成一个轻量判断框架：这家公司的价值重估当前主要围绕什么核心叙事，市场在该叙事上已经相信什么、仍在争论什么，本消息影响的是其中哪一项。

这不是要求额外写一份“市场叙事报告”，也不是每次全网调研ticker。它首先来自已给的D1/D2研究、Policy传导、PIN及近期相关事件；只有本次消息涉及该主线是否已改变的决定性疑点时，才聚焦搜索。

U给出的MU/HBM与INTC/Foundry例子，用来说明**业务收入占比不等于市场边际定价权重**，而非永久规定MU其他业务、Intel客户端一律不交易。次要业务也可能因为足够大的变化成为新主线；新事件可以改变原有叙事权重。提示词需要保留这种开放性。

主线识别不能成为价格权限的旁路：不因ticker近期上涨、下跌或跑赢同行而反推哪条叙事应被交易。主线来自研究解释、消息的讨论焦点和可验证业务背景；历史reasoning、PIN正文或研究资产中若含技术交易判断，也不能借上下文继承为当前的有效依据。

尤其要避免“提到核心叙事关键词就通过”。三星Foundry减亏同样含有Foundry，但这不建立Intel先进代工的实际损失；Googlebook含有18A，也不自动等同于外部代工商业务获得突破。主线负责**赋权**，因果检查负责**确保消息确实影响该主线**。（依据：S6 INTC-01-01/03/04、MU-03-01/03；U7。）

### 4.2 一个共同决策模型，容纳两种市场作用机制

**机制一：经济现实或关键判断发生改变。**例如重要技术采用、供应定价、旗舰项目风险、客户选择等，改变盈利路径、成功概率、价值获取或风险溢价。

**机制二：同一现实的市场认知、可信度或传播覆盖发生改变。**例如被市场采信的错误表述得到纠正、小众渠道的信息第一次进入重要财经受众、重要媒体为事件提供新的显著解读或验证。即使直接现金流变化并不巨大，也可能改变短期市场的定价与注意力配置。

两者共享一个判断中心：**市场关于目标ticker的什么认识受到怎样的影响，影响在当前情境下是否有交易分量。**它们不是新增case_type，也不形成一套独立“舆情交易系统”。

这意味着上一轮诊断中的“必须显著改变公司盈利”不能成为唯一许可条件。重构仍须纠正弱关联，但应允许通过可信信息扩散和核心叙事采信产生的消息alpha。反过来，重要媒体出现并不自动满足这一要求，仍须区分真正的覆盖升级与已经广泛传播后的重复汇总。（依据：U4；S6 MU-02-01与INTC-01-04。）

### 4.3 必须分开的四个判断

| 判断 | 作用 | 不能替代 |
|---|---|---|
| 相关性 | 决定沿哪个框架理解消息 | 不能代替方向和重要性 |
| 方向性 | 判定何种市场认识/经济变化可能支持LONG或SHORT | 不能代替交易门槛 |
| 交易分量 | 判断该变化是否足以形成当前有意义的市场作用；可借用Policy已校准的分量 | 不能由数字大、正文长、引用多或来源品牌单独证明 |
| 当前机会 | 判断传播、事件状态及唯一允许的价格完成态是否已使机会失效 | 不能反过来制造交易方向 |

不建议把它们做成机械相乘的打分表。来源很强不能弥补完全不存在的ticker关系；传导很直接不能弥补几乎没有增量；价格没有出现完成态也不能弥补缺乏交易依据。

### 4.4 对八类错误机制的统一认知修正

| 已知发生机制 | 新的思维任务 | 防止矫枉过正 |
|---|---|---|
| 正常经营/趋势延续被当惊喜 | 比较“原来会继续相信什么”与“本次必须修改什么”，并按当前定价主线权衡 | 不把正常进展一律排除；超预期的规模、时点或可信度仍可交易 |
| 技术测试升级为客户/盈利变化 | 将测试证明的层级与商业推断分开，关注是否改变关键商业可行性 | 不要求所有技术突破等到订单；真正的能力跃迁可以先被定价 |
| 上游总量被投射为ticker增量 | 识别新增与累计、规划与已采购、局部强度与总量、行业与本公司边际暴露 | 不强制精确财务模型；采用验证、期权价值和认知变化可以重要 |
| 变化维度被替换 | 保留原始变化维度；跨到另一维度时明确关键机制 | 不是禁止推演，而是不把推演结果写成同等确定的新事实 |
| 竞争默认零和 | 判断是否改变目标公司原本被预期能获得的价值，而非只看对手增长 | 收入仍增长也可能低于预期；不能反向规定供不应求时竞争永不利空 |
| 跨公司/业务连接不成立 | 区分行业邻近与真实因果连接，允许在缺失关键连接处结束交易论证 | 不能要求所有消息直接提到ticker；可靠的行业传导仍可成立 |
| 正式批准/风险解除自动利好 | 判断事前成功概率、成功/失败价值差与新增成本；不按状态名交易 | 高争议审批或重大风险解除仍可具有很强Surprise |
| 错误基线制造Delta | 核实核心对象、时间、指标与状态口径；区别Agent知识、客观事实和市场采信 | 不全面审计D1/D2，不要求唯一精确共识；市场误读纠正可真实产生机会 |

这些是单一skill中的**按问题启用的判断方法**，不是要求每个Case逐项填写的八关审计。HIT没有明显问题时无需重新跑完这些方法；RELATED只处理阻止其触发的关键差异；OPEN才承担更完整的自主构造与核查。

### 4.5 三个共同判断习惯需要改变

**第一，从“反方没有彻底否定方向”转向“交易有正面成立的依据”。**反证不足并不等于机会足够好。Policy HIT的正面依据可以来自已完成的校准研究，不要求每次另造一份；OPEN则不能只证明存在一条可能的因果链。

**第二，区分不确定性的作用。**量级不精确可以影响判断强度；关键因果前提不成立会破坏交易命题；净方向不明需要比较主导机制；影响已知很小则可能直接NO_TRADE。不能统一压缩为“降低信心但不消除方向”。

**第三，先形成净方向，再决定交易，而不是选好方向后附加风险。**同时考虑最可能改变结论的反向事件或经济机制，不必罗列所有风险。该净方向必须来自消息及研究，不得由行情上涨/下跌推导。

## 6. 三种Case的处理尺度及标签对齐

### 6.1 POLICY_HIT_REVIEW：审“现时可用性与明显缺陷”，不再审一次完整投资论证

对正常置信HIT，W3应将已提供的Policy及Condition视为有价值的预研究成果。需要做的是：理解本条消息实际触发了什么，识别是否有明显的对象、方向、状态、量级或时点错误，完成固定机会核验，并查看相关历史与主导事件。

**没有实质反例、没有明显不合理的Policy、也没有当前机会失效证据时，应当迅速放行。**不能再要求它像一个全无研究基础的OPEN Case一样，重新证明市场为何应对该变量重定价、重新寻找另一份独立共识、或等待正式订单才能确认价值。

“稍微放宽尺度”需要落实为三项变化：

- 接受Policy已经研究过的基本传导与价值基线，不重复提高证据终局性。
- 对合理范围内的量级和实现不确定性，保持已有校准的容忍，而不是叠加一套更苛刻的Open标准。
- 否决要基于具体问题，例如条件实际上未满足、Policy引用的对象已变、边界明显失真、当前事件已失效、重复经济机会或已完成重定价，而非泛泛的“仍存在不确定性”。

这并非盲信HIT。`W2_LOW_CONFIDENCE`、明显口径错配、可信反向消息、被消费的方向状态等，仍需针对性处理。关键是**异常触发更深入复核，而非每条HIT默认从零重做研究**。

### 6.2 POLICY_RELATED_EVALUATION：重点解释“差在哪里”，而不是把NO HIT再说一次

该类型的价值在于已经定位到有研究基础的传导路径。W3首先理解Policy的经济目的、reference_state与未触发理由，再判断当前信息属于哪种情况：

| 情况 | 判断工作 | 合理路径 |
|---|---|---|
| 上游漏判，当前实际已满足完整Condition | 核实具体触发关系，不扩大原条件 | 可选择真实、可执行的Policy Trade |
| 未HIT因为经济增量确实不足 | 说明当前信息为什么未改变足够重要的预期 | NO_TRADE；不因RELATED强行补一条Expert链 |
| 未HIT因为观察方式/情景不在条件表述中，但同一研究逻辑下已出现有价值变化 | 说明不同观察量为何确实改变该路径，而非只是主题相关 | 可Expert Trade；第二阶段保持真实的未HIT结果 |
| 未HIT因为边界过严、过晚或参考状态已不适用于当前情境 | 只研究本次所需差异，判断已有信息是否足以形成现在的机会 | 可Expert Trade；不修改原Policy，不假造HIT |
| 本次仍缺决定性事实，但已有具体且合理的短期跟进价值 | 判断缺失是否真正会改变选择，而不是默认要求终局确认 | 本次NO_TRADE；第二阶段再判断是否值得WATCH |

RELATED应得到积极、重点的研究待遇。不能用“上游未命中”作拒绝理由，也不能要求用一个完全无关的新宏大thesis才允许Expert。**在已有可信传导框架中，一个不同形式的早期有效观察，可能已经足够交易。**

但放宽不是“差一点就算HIT”。选择Expert时仍需建立当前有价值的独立判断；经济幅度不够，不能仅以“原Policy可能保守”补足。

### 6.3 OPEN_EVENT_EVALUATION：开放发现，但不以补出交易为成功标准

OPEN更完整地承担：识别当前ticker定价主线、本条事实或信息传播改变了什么、目标ticker为何会受到实质影响、净方向如何，以及是否具备当前交易价值。

相对于HIT/RELATED，OPEN没有可直接借用的已校准触发结论，因此需要更充分的正向依据。重点不是多查几个来源，而是避免把常规新品、一般景气佐证、上游总额或弱跨公司关系包装为强机会。

不要求每个OPEN Case重读完整PolicySet以证明“确实没有Policy”。若研究自然发现一个真实可执行Condition，可以选择Policy Trade；否则按Expert或NO_TRADE处理，不固守上游无关系的结论。（依据：S1 L90、L237、L296–304。）

### 6.4 附加标签不产生重复流程

| additional_tag | 应调整的工作重点 | 必须避免的误读 |
|---|---|---|
| `W1_LOW_CONFIDENCE` | 复核影响当前交易的事实身份、时间、证据与实际增量；只解决该疑点 | 不默认OLD/NEW错误，不恢复全库新旧重判阶段 |
| `W2_LOW_CONFIDENCE` | 优先核对具体Policy/Condition归因及其触发依据；保留主case_type | 不因LOW就对所有Policy重新打分或自动禁用Policy |
| `WATCH_FOLLOWUP` | 先读此前WATCH理由和相关判断，说明本次改变或未改变了什么 | 不必须交易、续期或继续等；OLD也不自动拒绝 |
| `BODY_MISSING` | 使用真实标题与来源，针对性获取影响判断的内容 | 不编造正文，不因缺正文自动拒绝；正文非空也可能只是尾页 |
| `RECENT_TRADE` | 检查具体历史意图、催化内容、方向及执行状态 | 不等于重复、同方向或已成交；无标签也必须留意重复经济催化 |

多个标签叠加时，合并处理相同疑点。例如WATCH+LOW+RECENT不应导致先做三次历史研究再做一次交易研究。标签对应的检查可以在同一批读取和搜索中完成。（依据：S1 L101–127。）

### 6.5 OLD、已消费Policy与Expert的空间

OLD描述事实库覆盖，不自动否定当前交易价值。已进入W3的OLD Case可能需要处理先前证据不足后的确认、重要传播升级、市场误解纠正或仍有效机会的重新评估。它也可能完全没有新的可交易意义，不能因为系统特别送入就强行交易。

Policy消费只约束Policy Trade的方向权限，不否定Expert资格。W3需要区分“同一Policy的另一个方向/Condition”“同一事件真实新增信息”“只是试图绕开消费状态重复表达同一意图”。Expert是自主判断，不是Policy不可执行后的自动重试按钮。

同一文章里旧内容和新内容可以共同参与理解，但旧内容不能被重新冒充本次事实增量；新的传播/采信作用则单独按信息作用判断。**这取代旧版“只有NEW部分才有交易价值、其余OLD全部忽略”的机械处理。**（依据：S1 L42–52、L222、L298–302。）

### 6.6 三种Case共用的Policy语义与路径选择

Condition在Policy内保持OR：任一完整独立充分条件成立即可，不把多个LONG/SHORT条件串成AND，也不要求达到整条研究路径的终局。背景与搜索结果可以解释和核实当前事件，但不能把没有完整触发依据的不同消息碎片累计成一个HIT。

Policy Trade仅选择冻结PolicySet中真实存在、当前可执行的Condition；方向由该Condition的`decision`确定。选择不局限于W2候选，但没有实际疑点就不为寻找“更合适的Policy”全库巡检。执行性查看`executable_directions`及实际消费状态，不能仅凭`consumed=false`或某一方向已消费推断另一方向。

当同一消息足以形成有价值的自主判断、却不真实满足原Condition或原Policy方向不可执行时，可以选择Expert，但应明确业务理由；不是先机械尝试Policy、遭拒后自动走Expert。对于实际HIT且可执行、经济论证又与该Condition相同的普通Case，使用Policy路径更自然，不必刻意改用Expert。路径选择本身不是额外提高交易门槛的理由，也不允许靠Expert规避重复催化判断。

若Policy选择被宿主拒绝，Task 2不补发Expert、不改原方向、不rearm或改写Policy。模型只作当前一次业务选择，实际授权由宿主负责。（依据：S1 L35、L198–212、L294–304。）

## 7. Task 1共同SOP：逻辑分层，执行不必低效串行

以下是执行架构，不是最终提示词文案。它不要求Agent输出各步中间报告。

### 7.1 入口：理解已有材料，不先制造重复读取任务

先识别当前阶段、ticker、信息边界及交易周期；读取当前消息、W1/W2完整理由、已定位的Policy/Condition、alignment、policy_usage，并快速查看PIN/WATCH和72h意图中与当前判断相关的内容。

当前payload已经包含的Event正文或完整Policy，不应再仅凭ID查一次。`alignment`缺失表示本次未提供该判断，不等于false。`case_type`是起点，历史W1/W2精简记录不能替代当前完整依据。（依据：S1 L177–212。）

### 7.2 建立一个不含价格的暂定交易命题

用当前市场定价主线和Case类型定位本次问题。HIT直接借用Policy已研究的命题；RELATED解释与边界的差异；OPEN判断是否存在足够的市场作用。

这个暂定命题可以是倾向交易，也可以是倾向NO_TRADE。其作用是防止看到K线后才倒找消息理由，**不是在核验完成之前提前提交决定**。

### 7.3 每个Case固定完成交易机会核验

每个Task 1都包含：

**公开信息核验：**通过Web Search核查本次关键催化的最早可识别来源、传播路径及重要媒体覆盖，并确认本次核心交易变量所需的现实和比较基线。

**价格完成态核验：**调用宿主实际开放的只读IBKR K线能力，查看覆盖本次催化传播阶段至当前有效判断时点的价格序列，仅用于识别显著已完成重定价。

HIT、RELATED、OPEN以及最终NO_TRADE都不因类型或预判结论而自动豁免这项流程。纯技术新闻和明显弱消息仍只需要低成本的必要核验，不能因为看了图就恢复交易资格；也不为一个已经明确的NO_TRADE追查整条全网传播链。

**固定的是核验义务，变化的是研究深度。**不得以“要快”跳过，也不要求每条消息做同样规模的取证。Task 2不重复这一流程。

### 7.4 必需研究尽可能合并或并行

知道核心消息与大致时间后，可将原始披露、较早报道和重大后续更新放进同一轮聚焦检索；可并行或合并读取多个可能相关的D2完整Unit及D1章节；先取覆盖适当区间的K线，再只针对完成态歧义增加一层时间粒度。

工具能否并行由实际运行环境决定，提示词不能虚构批量API。即使工具需要串行，仍可以一次合理组织问题，减少逐个试文件和反复搜索同一主题。

### 7.5 按case_type完成必要深度的判断

使用第6节的尺度处理本次关键疑点。K线只能在完成态被显著识别时对暂定交易命题产生否决，不能改变非价格研究得出的方向；来源传播、可信度和同期事件则可以改变市场认知作用的判断。

不把“价格没有否决”当成新的交易依据。也不要求所有不交易结论必须由价格证实：信息分量不足、关键因果连接不成立、相同催化无实质新增或当前主要信息被反向更新，都可独立支持NO_TRADE。

### 7.6 选择路径并立即提交

Policy Trade选择真实、可执行、与当前消息完整对应的Condition；Expert Trade表达独立方向及Prior/Delta；NO_TRADE说明决定性的原因。第一阶段只提交规定对象，不输出Fact、WATCH、PIN、完整coverage审计或新的自定义评价表。

研究停止条件应覆盖：**本类型需要的价值依据已形成；会改变当前决定的核心疑点已处理到合理程度；固定机会核验已执行且局限没有被掩盖；近期状态和交易路径已核对。**不要求达到绝对确定，也不继续为不影响选择的次要数字扩展研究。

## 8. 交易机会核验：来源、时间、传播与价格的精确边界

### 8.1 研究的是支持交易的核心催化，不是当前文章的标题时间

一篇文章可能同时含有数周前的份额数据、昨日研究、今日新条款和本时段媒体解读。追溯对象应是本次实际支持交易的内容，不能随便选择最早或最新的一条日期。

需要在概念上区分以下时间，不要求新增五个模型输出字段：

| 时间 | 用途 |
|---|---|
| 现实发生/签署/测量时间 | 说明事件本身；不自动代表公开时间 |
| 核心事实最早可识别公开时间 | 判断原始信息从何时开始可能进入市场 |
| 本次有效增量或重要传播升级时间 | 判断新条款、纠正、确认或财经受众首次覆盖形成了什么新的作用 |
| 当前接收/研究时点及允许的cutoff | 约束本Case可用证据，避免混入后来的信息 |
| 当前交易有效截止/周期边界 | 约束机会是否与本轮策略窗口一致，不要求基本面在同一窗口兑现 |

如果交易的是一条纠正或新的传播阶段，Prior应对应**该有效信息变化之前**的市场认识，而不是机械回到几周前原始事件发生时。旧事实的首次公开与新一轮受众认知变化可以是两个不同节点。

最早公开时间可能只能定位到日期、时间段或“至迟某时”。保留这种精度，不填零点、不虚构分钟、不声称证明全球绝对首发。搜索未找到更早报道，也不等于可以证明从未公开。（依据：S1 L247；U3、U4。）

### 8.2 信源层级不只是“是否可信”，也不只是“媒体越大越好”

对检索到的相关历史报道，统一理解三个方面：

**事实掌握能力。**原始公告、行业研究、专业记者、转述、聚合或评论，各自对本事件能够证明什么。

**投资者触达与采信。**本次渠道是否把消息送到更广泛、或对该ticker更关键的市场受众；小众行业源也可能已充分触达专业投资者，不能仅按网站规模排序。

**传播角色。**是原始披露、独立验证、新的定量细节、重要解释、第一次主流财经覆盖，还是已广泛报道后的市场回顾。

应综合本次检索范围内已发现的相关来源，而不是只评估当前进入管线的一个域名。无需穷尽全网所有复制页面，但要覆盖最早源、第一次重要财经传播以及会改变判断的重要后续节点。同一通讯社的多站转载说明覆盖扩大，不等于多份独立事实证明。

`source_name`是发布者/落地域名的规范元数据，不是底层采集渠道，也不保证已完成原始溯源；W3的研究正好补足这一点，但不擅改原消息快照。（依据：S1 L243–247；S2需求五。）

### 8.3 如何允许“消息不很强，但高层级传播仍产生机会”

本轮设计允许：直接基本面影响并不巨大，但本次重要媒体报道把一个与ticker核心叙事有关的事实或解释带入新的投资者受众，提高采信程度或重新聚焦一个此前未充分关注的问题，因而产生有依据的短期消息机会。

这里不能把经济分量门槛重新写死为“必须显著上修EPS”。真正要说明的是**本次信息作用改变了什么市场认识、为什么作用于该ticker、为什么这不是已经完成传播的重复消息**。

相应防线是：

- 报道来自Bloomberg不自动构成交易；必须看该条报道相对于之前完整传播过程增加了什么。
- 新来源不自动成为新Fact；OLD可以有新的市场作用，但不能为交易而伪造NEW。
- 媒体标题强化了语气，不等于有独立确认；评论制造的错误认识也应保持“市场可能采信的报道”与“客观事实”的区别。
- 大媒体传播更强，同样可能意味着初始反应更快结束，因此更应认真完成K线核验，而不是更少核验。

“报道多”与“还会继续发酵”不能循环证明；来源层级既可能提高当前影响力，也可能表明机会已被广泛传播。最终仍需结合本次作用、时段及唯一允许的完成态证据，而不是给媒体打一个固定分数。

### 8.4 新闻年龄不是交易资格；长期兑现也不是长期才定价

某条重要消息从亚洲行业源传出数小时后才进入美国市场，或者发生在夜盘、盘前，仍可能产生当时可交易的市场作用。更大的认知冲击也可能需要较长时间被消化。

因此，不设“超过X分钟就拒绝”，也不设“长期基本面必须等到短期订单”的规则。用户提到MRNA的例子在本稿仅作为“大催化的消化过程可以很长”的说明情景，不视为本轮已核实的历史医学或股价事实。

另一方面，没有更多媒体转述也不证明市场未知；专业投资者可能已经从原始渠道获得信息。时间、渠道、叙事重要性和完成态需要共同理解，不能用任何单一代理变量替代。

### 8.5 价格具有单向权限：只能识别完成态并否决当前机会

**价格不能生成方向，不能强化确信度，不能证明公司受益/受损，也不能决定买卖点、仓位、止损、目标价或预期收益。**涨跌幅、均线、突破、反弹、超买超卖、相对强弱、技术统计及期权价格指标均不能成为交易依据。

在Task 1中查看K线，是为回答一个非常窄的问题：**是否存在与本次已知催化传播相对应的一轮明显价格调整，随后已形成清楚的稳定化形态，足以判断该轮重定价机会已经结束。**

可理解的例子是：信息冲击后经历明显下移，随后在新的水平持续稳定，呈现清楚的L式完成态。这里对“支撑/横盘”的描述只是识别前一轮事件反应已稳定，不能用于买入反弹、反手LONG或预测再下跌。

该判断是基于可观察证据的交易工作判断，不是从K线证明“公司所有信息已完全有效定价”。图形需结合催化时间、传播阶段与后续新信息理解，不能脱离事件靠形状自动判定。

### 8.6 完成态与其他两种状态必须分开

| 内部判断状态 | 可以怎样影响最终选择 | 不允许怎样使用 |
|---|---|---|
| 有显著、与本次催化相对应的已完成重定价证据 | 否定继续交易该轮既有机会；若有新的实质增量，判断对象应改为那次增量 | 不据此反手，不预测接下来涨跌 |
| 已查看，但未识别出显著完成态 | 不施加价格否决；是否交易仍由消息、Policy和市场认知依据决定 | 不说“还没涨所以必涨”“趋势在继续所以追随”“仍有10%空间” |
| 数据不足、缺段、时段不适合判断或形态不清楚 | 明确保留未知，不假装完成核验结论；按实际工具/宿主合同处理能力限制 | 不将未知视为未完成，不自动给交易加分，也不把未知伪装成已完成并拒绝 |

这些是判断语义，不是新增output_schema枚举。

已经上涨10%，仍可能继续发生重要信息调整；这句话只用于否定涨幅阈值，不是允许模型预测还会再涨10%。反之，即使涨跌幅不大，也不能仅凭幅度小认定仍有机会。

**没有识别出完成态，不等于存在交易机会；识别出完成态，也不能产生相反方向的机会。**

### 8.7 完成态需要足够上下文，不能识别成普通技术信号

K线区间应覆盖相关披露前后及当前时点，包含适用的盘前/盘后数据，避免只截取一段横盘就判完成。夜间成交稀疏、缺少报价、临时停顿或不同事件造成的走势，都不能轻率解释为本事件已被消化。

重要新信息可以产生后续一轮重定价。若在旧事件走势已经稳定后出现新的重大条款、可信确认或实质传播升级，不能因为旧一轮已完成就永久否定整个Event。判断应针对本次交易实际依赖的增量。

同样，不能因为另一条消息使ticker已经上涨/下跌，就把它当成当前消息已被定价。若缺乏合理事件对应关系，完成态结论应保留不确定，而不是按图形硬归因。

### 8.8 对旧44条结论的使用须同步收窄

S6的时点过晚标签仍是重要的问题线索，但“已涨13%”“已跌4%”只能保留为历史描述，不能变成新版提示词的拒绝阈值。缺少当时K线序列时，本稿只能诊断**旧W3没有完成机会验证**，不能追认每条都满足新版“显著完成态”的严格条件。

S6中以SOXX、大盘或同行表现辅助历史收益归因的内容，可保留在离线复盘。不能直接迁入在线W3作为动量、相对强弱或方向判断。在线的同期事件对照主要使用新闻与业务信息；价格如被使用，仍只能处于上述完成态例外中。

## 9. 上游研究、历史上下文与时延控制

### 9.1 不同信息源各自回答不同问题

| 信息 | 主要回答 | 不应被误用为 |
|---|---|---|
| D1/D2 | 公司、产业与市场的研究框架；相关变量、传导与既有研究基线 | 每个数字都实时最新的数据库；当前市场共识的自动证明 |
| Policy/Condition | 已研究的情景、reference_state、触发边界和条件方向 | 无条件交易命令；所有开放事件的穷尽列表 |
| 当前消息与聚焦Web研究 | 本次真实发生了什么、核心变量和关键基线、传播与采信发生什么变化 | 全面更新整个公司研究的工作包 |
| 72h意图、PIN及WATCH | 最近已经做过什么判断、现时重要背景、仍需跟进什么 | 必须延续先前方向、已经持仓或已完成成交的证明 |
| IBKR K线 | 唯一允许的已完成重定价形态检查 | 股票方向、经济价值、动量或剩余涨跌幅的证据 |
| 当前schema/宿主状态 | 本轮合法动作、对象身份、权限和业务时间边界 | 模型可以任意覆盖的建议 |

上述“可信”是分工，不是同一个静态优先级。例如Policy是可信预研究，但本次核心变量出现了可核验的新状态时，应针对该变量调整判断；PIN是重要背景，但不是永远正确的市场解释。

### 9.2 D1/D2只刷新影响本次选择的关键点

不要求也不应让W3逐项怀疑D1/D2的公司收入、业务占比、产品信息、所有日期是否最新。这样既消耗时间，也会把W3重新变成D1/D2研究节点。

需要外部核实的是：**本次实际支持TRADE的核心变量，以及足以改变此次结论的必要比较基线。**例如：

- 交易SCA覆盖变化时，核对本次使用的覆盖口径和新旧关系，而非重建MU全部业务数据。
- 交易Oracle项目进度时，核对同一项目、同一兑现阶段的时间，而非审核全部Oracle/Bloom历史合作。
- 交易头部客户采用时，核对被采用的技术、客户与证据状态，而非要求全部Foundry财务模型重新更新。
- 交易媒体纠正时，核对原报道、修订内容及市场传播，而非把所有上游公司收入数据都查一遍。

关键核验可以与固定首发/传播搜索合并。同一可靠来源已清楚回答多个核心问题时，不为凑流程重复寻找第二、第三份相同证明。对是否需要进一步验证，应看疑点能否改变本次交易，而非“来源数量越多越好”。

### 9.3 切片是减少读取成本，不是缩小研究边界

D1按自然章节、D2按完整Unit、D3按完整Policy读取；保留原文语义，不把Unit中的State、Factor、Gap拆散。找不到相关D2时，先看索引，一次读取多个合理候选Unit，而不是每次猜一个文件、失败后再开下一个。

已在payload给足的Policy/Event不重复查询。必要时可以跨Unit、跨Shell阅读，尤其核心市场叙事可能跨越业务分区；文件位置或cross_shell/unassigned状态不能成为内容无效的理由。最终路径与工具参数由实际环境提供，不在提示词中猜测编号或新造Unit ID。（依据：S1 L226–239；S2需求二。）

### 9.4 每个Case具有轻量的持久运行意识

W3应先知道：自己不是第一次看到这个ticker的孤立研究者。即使是新Fork，也已经有显式注入的近期意图与重要背景；即使是Resume，也不能假定掌握其他Thread发生的一切。

72h历史需要先从题目、时点、方向和Policy/Event定位相关条目，再利用相关完整正文、Prior/Delta与执行状态。无需把72h全部历史再写一份摘要，也不能只看最近一笔或只看成交记录。

当前需要识别的关系包括：相同现实重复报道、补充细节、重要状态/规模/可信度变化、同一事件方向修正、不同事件对当前主线的竞争，以及历史意图失败但当前是否仍有真正的机会。

`RECENT_TRADE`只反映可确认对象的交集，不反映上述关系的最终结论。相同Policy不同Condition或方向可能是新机会；没有标签也可能是不同对象表达下的同一催化。跨日E编号不能自行当成稳定身份，正式映射由系统提供。（依据：S1 L113–127、L214–224。）

### 9.5 先前交易失败不等于现在应自动补单

执行失败与经济机会是否仍存在是两个不同问题。历史未成交可以影响当前Case的背景，但不自动提供新的Surprise，也不自动禁止在仍有真实机会时重新作出判断。

缺少回执、`UNKNOWN`或`EXECUTION_ACCEPTED`不能自行推成失败、零仓位或实际成交。W3不查询账户或替执行器补单，只根据明确提供的状态进行本次独立判断。对于已经提交并执行的同一经济机会，没有实质新变化或新的可说明市场作用时，不应重复消费；真正的消息增量、传播阶段变化或其他实质机会差异则可以重新评估。

### 9.6 时延控制以“问题价值”而不是“研究步数越少越好”为目标

每个额外操作都应能回答一项可能改变本次交易、方向、路径或机会有效性的疑点。以下工作优先级较高：关键事实与口径、重要反向更新、首发/传播、已完成重定价、Condition实际归因。以下工作通常不应拖延：不影响选择的小数字差异、全文背景扩写、重复source搜集、事实候选措辞打磨、WATCH/PIN排序。

速度主要从五处获得：**继承可信上游研究、批量读取、合并搜索、复用同Case已获得的证据、把运营后置。**不以跳过固定机会核验或把决定性疑点留给Task 2换速度。

停止研究不等于只有TRADE才能结束。NO_TRADE已经有明确决定性理由、固定核验也已按必要深度执行时，应直接提交，不为显得“研究充分”继续扩写。对HIT正常Case尤其不能无限寻找足以推翻上游的次要理由。

## 10. Task 2：真实运营，不重新交易

### 10.1 两阶段之间传递的是既有判断与证据，不是重新启动研究

Task 2在同一Case Thread紧接Task 1执行，读取已提交交易选择、宿主受理结果和刷新的WATCH/PIN状态，沿用原消息、已读资产、已有来源研究和核心判断。

Task 1负责解决会改变当前选择的事实疑点；Task 2负责把已经理解的现实整理成正式novelty、coverage、Fact与运营动作。确有必要时可以补足运营信息，但不得重新进行一整套Alpha研究，不再次读取全部资产或72h历史，不重复调用行情来决定是否改交易。（依据：S1 L139–153；S2 L74–85。）

### 10.2 两阶段schema职责必须保持清晰

| 阶段 | 合同输出 | 架构要求 |
|---|---|---|
| Task 1 | `decision`、`reason`、`policy_trade`、`expert_trade` | 只选一个结果；未使用分支为null；Expert保留direction、prior_expectation、expectation_delta；不加运营字段 |
| Task 2 | `novelty`、`policy`、`delta_candidates`、`watch_actions`、`pin_actions` | 只维护事实和运营，不输出另一份交易方向或交易对象 |

本稿不新增 `narrative_score`、`repricing_status`、`source_grade` 等必填输出。主线、传播与完成态是判断方法，必要结论压缩进入现有reason；交易关键核验的来源、区间等证据应有可追溯性，但具体如何由工具结果/宿主保留需与正式合同对齐，不要求保存完整会话或隐藏推理过程。

**特别注意同名字段：**输入 `w2.matched_condition_ids` 是RELATED归因；Task 2输出 `policy.matched_condition_ids` 是W3最终确认的实际HIT，不能照抄。`policy_usage`的已消费状态限制执行，不把事实上的HIT改成NO HIT。（依据：S1 L204–212、L249–318。）

### 10.3 Fact与novelty不为交易结果服务

NEW需要至少一个有效新增原子Fact；OLD需要真实覆盖引用，且Fact列表为空。事实只记录现实命题和恰当的陈述状态，不记录估值、利好/利空、Prior或因果链；最多12个，数量不是产出目标。计划期、报告期与发生日期分开，未知时间可保留null，不为补字段制造日期。

一条事实OLD的消息可以在Task 1因新的市场作用而交易，Task 2仍应真实记OLD；不能为了使两阶段看起来一致而捏造“新的报道”等原子事实。真正新增的确认、否认、计划或披露可以按其实际状态记录，但不能把观点预测改成经营结果。

若第二阶段发现的novelty/coverage与先前理解不同，应记录真实运营结果及必要说明；不能撤销、重发、改写第一阶段交易，也不能用虚假记录掩盖差异。这个不可改写边界由业务合同确定，不代表第一阶段可以有意推迟关键核验。（依据：S1 L348–362。）

### 10.4 WATCH：有目的的后续判断，不是给所有不确定消息留位置

WATCH应当有具体的业务理由：当前Policy相关方向值得继续观察，后续哪些可辨别的新信息可能改变研判，并且存在合理的短期跟进意义。不能因为“消息不够强、也不知道以后会出现什么”就设置WATCH，更不能把它作为不敢交易时的默认安慰性结果。

已经交易仍可WATCH；一个重要事件后续可能有规模变化、反向澄清或另一个Condition值得观察。已经NO_TRADE也可以WATCH，但NO_TRADE本身不证明需要继续关注。需要区分“目前信号本来就弱”和“有价值的具体问题正在展开”，不预设最终合同一定会出现。

合同边界：SET只限本Case W2明确HIT/RELATED，或本轮复核明确HIT的有效Policy；CANCEL可操作当前注入的本ticker有效WATCH。每ticker最多2个；采用D/D+1、D+2边界，不是固定48小时；重复SET不续期，同批CANCEL优先，READY不自动撤销，已消费方向不取消WATCH资格。（依据：S1 L364–371。）

### 10.5 PIN：共享短期主线，不是保存所有研究发现

PIN用于当前实际收到的消息：它是否会在未来短期持续改变对其他消息的理解，是否值得占用有限的全局上下文。NO_TRADE消息也可能是重要背景，已经交易的消息也可能应PIN。reason要解释持续性与后续研判意义，而不是简单复述利好/利空。

SET只绑定本次消息，`pin_id=null`；不能把搜索到的另一篇文章、之前的历史消息或一段自主研究替换为PIN对象。若旧PIN已经被新信息证伪或不再重要，可以取消；不能用PIN理由偷偷建立一个不受约束的外部文章库。

每ticker最多2个，与WATCH独立计数；有效期创建后24h，重复SET不续期；PIN不产生W3入口。第二轮使用刷新后的状态决定是否取消旧对象腾位置，不自行查询数据库、修改TTL或超容量保存。（依据：S1 L373–381；S2需求四。）

### 10.6 四类时间窗不能混淆

| 状态 | 时间含义 |
|---|---|
| 子Thread | 最近新Case接收后48h有效；同Case Task 2与重试不续期 |
| 交易历史 | 每个Case首收时冻结的过去72h意图快照 |
| PIN | 创建后24h |
| WATCH | 系统语义日D/D+1与D+2边界，不是创建后固定48h |

这些都是宿主状态，不应由Agent按本机时区或自然日期重新计算。（依据：S1 L119、L155–173、L369、L377。）

## 11. 提示词、宿主与工具的责任边界

### 11.1 本轮必须明确的能力缺口

S1和S2没有提供新增IBKR工具的实际名称、输入输出schema、可用历史范围或时间语义。本轮可以确定“W3需要只读K线完成态能力”，不能写成已经存在某个具体API调用，更不能沿用S1旧的“禁止行情查询”。

第二步正式写作前，需要将以下接口事项落到实际运行契约。这些是部署对齐点，不是要求本轮另做架构重构或增加一套任务。

| 对齐点 | 已确定的方向 | 尚需工程合同明确的部分 |
|---|---|---|
| 只读IBKR行情 | 只取当前ticker相关历史K线，支持完成态判断；不开放账户、交易和数据库写操作 | 实际工具名/参数、返回序列形式、错误处理、是否支持图形读取 |
| K线时间与时段 | 要有可识别的时间戳、时区、聚合周期、盘前盘后覆盖和缺失说明 | 返回bar起止语义、当前未完成bar、历史修复/复权等元数据 |
| 信息上界 | 当前 `cutoff_at` 是允许证据边界，Agent不得自行越过 | 实时“现在”与冻结cutoff如何一致；若只固定在首收时，后续新消息不能被Agent静默纳入 |
| 交易窗口 | 使用当前业务周期与交易有效时间，不把语义日当自然日 | 是否在payload明确给出本次有效截止/周期平仓时点，避免模型自己猜测 |
| 阶段与schema | 两阶段字段按S1合同分离 | 实际phase枚举、正式schema文件及合法拒绝/重试结果 |
| 最终幂等 | 宿主负责并发意图、重复提交、Policy消费与对象有效性 | 72h快照后出现的并发意图如何在创建时统一约束；提示词不能保证消除竞态 |

实时检索若发现截止之后的网页更新，历史回放若返回包含截止之后成交的完整bar，都不能用于本Case判断。对价格完成态尤其要防止用“该分钟最终高低点”或当天最终K线泄漏决策后的信息。

### 11.2 工具失败不能伪装成业务结论

需要区分：已经执行必需核验但证据精度有限，与为了加速根本未执行核验。前者可如实保留局限，后者是流程遗漏。

若首发只能定位到时间段，不应自动否决；若K线缺失，不能写“未完成重定价”或“已经完成”。本架构不额外发明“工具未知必然NO_TRADE”的业务门槛，也不默认所有失败都可无条件放行。应遵循正式工具/执行合同的硬约束，在非价格依据与已获得信息上形成诚实判断，并在关键核验缺口影响选择时清楚说明。

工具调用失败可针对决定性问题做合理、有限的重试或使用实际提供的等效结果，不能无限查询，也不能改用技术评论、搜索片段价格或猜测的实时走势冒充IBKR核验。**上线前必须真实提供该能力；不能靠提示词文字解决工具不存在的问题。**

### 11.3 不让Agent承担宿主已有职责

Thread路由与清理、Template Fork、身份映射、72h查询与注入、schema校验、Policy消费、并发幂等、实际下单及动作持久化均由宿主负责。

W3读取业务状态并产出合法结构，不操作上述系统。不为弥补上下文缺失而要求模型查询底层SQLite、Supabase或券商账户，不自行rearm，不因下游拒绝在Task 2补一笔Expert Trade。（依据：S1 L137–147、L164–173、L298–302、L381–422。）

### 11.4 历史路由样本不足以验证新增HIT复审能力

44条主要是旧版W3形成意图的样本，不能证明新HIT/RELATED复审的放行率、额外延迟和误拒率。它们适合验证已知认知缺陷与机会核验，新增case_type行为还需要专门设计输入对照。

同理，来源升级允许交易的新增业务要求，可能改变某些旧样本在不同传播背景下的判断。本稿不重新改写44条历史结论；回归测试需要固定当时可获得的来源与上下文，不能假定所有旧标签都是不随业务规则变化的绝对真值。

## 12. 为什么这套架构有望改善表现，以及可能怎样改错

### 12.1 每个结构变化必须对应一种行为变化

| 结构选择 | 预期改变的Agent行为 | 对应已知问题 |
|---|---|---|
| 定价主线先于局部传导 | 先权衡事件分量，再决定是否深入某个业务Unit | 普通DRAM/NAND更新、Googlebook、单一终端砍单被过度交易 |
| 三种case_type使用不同研究信任 | 已有校准不再从零证明，RELATED不被原边界机械堵住 | 新W3可能对Policy机会二次过严的问题 |
| 关键因果前提与普通不确定性分开 | 缺失核心连接时停止包装方向；量级不精确时保留重要早期信号 | Samsung→INTC的错位关联，与EMIB-T合理早期采用之间的区别 |
| 事实变化与信息作用共用判断中心 | OLD、纠正和有效传播升级能被识别，但不会伪造NEW | 公共新旧与KB新旧混同；强来源传播机制遗漏 |
| 机会核验成为公共必经模块 | 不因正文完整、HIT或消息标签而跳过首发与完成态 | Oracle、Ameren、UBS等时效性缺口 |
| 价格只具有完成态否决权限 | 价格不能证明利好、也不能把技术图形变成交易理由 | RKLB技术指标交易及涨跌幅阈值化 |
| 索引批量读取＋局部变量核验 | 不重建D1/D2，不重复读已有Policy，查询集中于决定性问题 | 高时延、材料截断和无关审计 |
| 显式使用72h/PIN | 新Fork仍知道最近交易和主导事件；旧Thread不成为事实权威 | Netlist/Iridium重复，以及忽略Oracle反向回应 |
| 两阶段复用同一判断 | 先交交易，Fact和运营随后；两阶段不重复研究 | 操作性工作延迟交易 |

这些是可验证的设计假设，不是单凭写入prompt就保证改善。验证重点应是行为是否改变，而不是新reasoning是否写得更长或更漂亮。

### 12.2 需要反身性约束的八种反向风险

**风险一：为修复OPEN的门槛过低，把所有HIT都重新卡严。**应在共同行为原则和具体SOP中都体现研究信任差异；不是仅缩短HIT研究时间却仍要求Open级独立证明。

**风险二：强调核心叙事后形成主题盲区。**主线是权重，不是白名单；新事件可以改变主线，重大非核心业务风险也可以直接影响整家公司价值。

**风险三：强调市场认知与传播后，变成“大媒体写了就交易”。**来源层级必须结合此前覆盖和本次新增作用；技术信号即使经大媒体转载也不能借传播渠道洗成消息催化。

**风险四：相信D1/D2导致核心基线继续陈旧，或核验基线变成全库审计。**边界是本次实际交易变量及必要比较面，其他研究仍可信继承；不把某个数字较旧扩大为整个资产失效。

**风险五：完成态判断变成隐蔽技术分析。**未见完成态不能支持交易，完成态只能否定该轮机会；涨幅、趋势和横盘本身都没有正向交易权限。

**风险六：双阶段被理解成“先交易，错了再查”。**影响选择的现实、基线和机会核验属于Task 1；Task 2只后置格式化与运营，不为第一阶段缺失研究兜底。

**风险七：WATCH/PIN重新制造无限等待与上下文膨胀。**弱消息不默认WATCH，普通利好不默认PIN；两者有不同目的与对象，且允许在交易后合理使用。

**风险八：近期历史成为结论锚定。**历史reasoning是已作出的判断，不是当前必须维护的正确答案。新证据可以反转方向；原意图未成交也不是自动补单理由。

### 12.3 不能把复盘分类写成一长串运行时黑名单

不建议把“分析师报告”“benchmark”“AI CapEx”“常规产品发布”“法律和解”等整体列为禁止类别。正确问题是当前信息的边际分量、市场采信与目标ticker作用；同一类别可能同时有弱消息与重大冲击。

也不建议把44条case全部塞进AGENTS/skill。一方面会拖慢每轮上下文并诱发记忆标签式判断，另一方面真实开放事件无法被旧样本穷尽。本稿保留全量映射供写作和验收使用；运行提示词只保留能迁移的判断方法及少量有必要的对照。

## 13. 第二步写作前应固定的验收情景

验收既要减少已知错误，也要防止误杀。以下是架构行为测试，不是要求本轮产出新的真实交易策略或预设收益结论。

| 测试情景 | 应观察到的行为 |
|---|---|
| 正常HIT、Policy合理、无实质矛盾、机会核验无失效依据 | 借用已有校准、快速放行；不另加订单/共识/财报终局门槛 |
| HIT附W2低置信，实际对象或口径明显不匹配 | 针对性核验并纠正，不因主类型而盲信，也不全库重跑 |
| RELATED未HIT只因条件要求最终交付，而当前已是有分量的早期采用 | 主动评估并允许Expert；不假造Policy HIT，不机械等最终交付 |
| RELATED消息的真实增量本就很弱 | NO_TRADE；不能只因有Policy关系就交易或默认WATCH |
| OPEN的明确客户采用/关键行业定价变化 | 能保留早期机会，不强制正式绑定订单或精确财务模型 |
| OPEN的成熟业务常规更新/错误跨公司传导 | 识别分量不足或关键连接缺失，不以“方向未被否定”放行 |
| OLD因WATCH/LOW进入，小众信息本次出现有意义的强来源传播升级 | 不因OLD硬拒绝；判断信息作用，Fact仍真实记录，不机械重复 |
| 同一通讯社的另一转载、正文或尾页无实质新增 | 不把新媒体域名、消息ID或空白补充当成新机会 |
| RECENT_TRADE同Policy但不同Condition/方向 | 读取实际内容再判断，不仅凭标签拦截 |
| 无RECENT_TRADE，但72h内容显示同一催化已反复交易 | 能识别业务重复，不能因无标签断言没交易过 |
| Policy某方向已消费，但当前有独立重要新变化 | 正确使用Expert空间；不rearm、不自动fallback、不重复旧意图 |
| 新闻方向成立且价格已涨10%，未识别显著完成态 | 不因涨幅否决，也不因趋势加分；由非价格依据决定 |
| 同一消息、同一非价格上下文，更换为相反方向但均无完成态的K线 | 交易方向、重要性不应随K线翻转；证明没有技术面泄漏 |
| 同一消息出现明确、事件对应的完成态 | 仅撤销本次机会，不生成反向交易 |
| 夜间K线稀疏或只出现短暂停顿 | 不轻率判定完成，不把数据不足当横盘完成态 |
| 旧一轮完成后出现真正新条款/新采信阶段 | 重新对准有效增量，不永久封锁整个事件 |
| D2中次要数字较旧，但与本次决定无关 | 不搜索全面更新；只核验核心交易变量 |
| BODY_MISSING但可靠标题提供足够核心事实 | 聚焦补证，不自动拒绝或编正文；完成必要核验 |
| 正文不为空但仅为联系人/免责声明 | 不受标签缺失迷惑，不补造新的事件内容 |
| Task 1已提交交易，Task 2发现事实OLD或coverage不同 | 真实维护运营记录，不重新输出交易，不篡改记录迎合先前结论 |
| Task 1 NO_TRADE但本消息是未来24h重要背景 | Task 2可合理PIN；NO_TRADE不等于无运营价值 |
| 并发导致Task 2的WATCH/PIN动作被宿主拒绝 | 不重新研判、不查数据库、不撤回交易，遵循现有动作处理 |

回放仅使用决策时点之前已可获得的信息和K线。材料S6中某些案例只有盈亏点和文字解释，没有完整当时K线，因此不能以事后涨跌为新完成态判断的金标准。两个高盛Case对分量评价的灰区、Bloom回应时刻的记录差异，也保留为验收资料限制，不擅自补齐。（依据：S6 L265–267。）

评估时至少分开看：OPEN错误交易是否减少；HIT/RELATED是否新增不必要拒绝或延迟；必要核验是否漏做；价格是否渗入方向；重复意图是否减少；两阶段是否重复研究；运营记录是否真实合法。不能只以“交易变少”或“已有样本盈利增加”作为成功标准。

## 14. 给第二步写作的结构性指引

第二步应在本架构上展开具体写作，而不是再重新发明节点身份。需要重点完成：

**首先，建立AGENTS中的稳定心智。**以ticker定价主线、分类型研究信任、重要市场认知变化、因果与边际权衡、价格单向权限、持续运行和时效为主。不要把诊断报告改写成冗长的错误禁令集。

**其次，建立单一skill中的选择性执行。**入口按阶段调度，Task 1按主类型聚焦，标签只调整问题重点；公共机会核验与工具/资产使用规则只定义一次；Task 2单独承担运营，不重跑交易研究。

**再次，明确模块之间的连接。**最容易遗失的是：市场叙事与局部D2如何连接；Policy预研究怎样实际降低复审负担；来源层级怎样影响认知而不改事实状态；价格完成态怎样只否决、不支持；历史意图怎样被比较而不是机械锁定方向。

**最后，对齐正式工具与schema。**不将本稿的内部判断概念直接变成新增字段，不虚构IBKR调用，不复制旧mode、四象限、policy_execution或expert evaluated/trade布尔。第二轮需要以实际提供的phase、output_schema及工具描述落地这些边界。

本阶段已经可以确定的总体方向是：

> **以市场重要认识为中心，以Policy研究作为可继承资产，以差异化复审控制研究成本；每次完成来源传播与严格受限的价格完成态核验，先提交交易，再维护事实与短期上下文。**

这同时针对了门槛过低、过度关联、知识基线错位、时效遗漏与重复处理，而不把W3改成只等正式订单、只交易当前热门业务、或借助技术形态预测涨跌的节点。
