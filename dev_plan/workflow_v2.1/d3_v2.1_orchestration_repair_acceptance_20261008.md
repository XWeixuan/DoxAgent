日期：2026-10-08。按本轮编排修复方案实施；本地代码及回归完成，新 MU SDK Pilot 已完成并留证；正式服务未部署/切换。

## 1. 已实施的业务边界

- Shell/OPEN 执行 Discovery、主 Build 和唯一补研 Build；GLOBAL 从 Planning 开始，只延续 Planning/Integration。槽位与限定别名保留；裸 GLOBAL Topic 降为 OPEN，旁路非法角色在文件物化前拒绝。
- 主 Review、post Review、final_write 均最多五个焦点/编辑归属目录一批，同目录不按正文大小拆分。空主池仍有一次全局审查，零补研对象零 post，零编辑请求零 final。
- 全主稿 B、已接纳补研稿及已完成 final 候选提供完整只读 JSON，catalog 保留 ref/local_path/ID/SHA/来源轮次/目录，同 ID 的不同版本按路径并存。跨 owner Discovery、两轮 Result/Agenda、最新 Review 和可取得上游材料均明确映射。
- Review 增加最小 edit_requests（policies、instruction）；relations/ref 只供参考，不扩张处理范围。主累计 research_requests 是唯一补研内容权威，兼容 Agenda 仅贡献 waves。post 只重点审查新补研稿，维护最终编辑清单；不发第二轮研究。final 和 Consolidation 使用同一最新健康 Review。
- 编辑-only 可直接走 final；健康补稿直接进入候选池；默认 retain B，只有显式 Consolidation 交易决定加入/替换/退休。无效目标/候选局部降级，不用旧稿 fallback 冒充新编辑成功；主/补 Build 同样要求本次接纳 ledger 的 raw_hash 匹配，避免无新稿收据却输出继承旧稿到新路径，随后引用不存在的 ledger 行。
- Result 的所有认可别名共同接纳，坏首份不遮蔽健康备用；声明 a.json 可合法接纳，波次只接纳一次。原始 task snapshot 与规范权威稿分离，恢复不会把 null-ID 原稿覆盖到参考池。
- 完整历史 PolicySet/B/补研稿用于身份继承；同 ID 多版本编辑优先目标 path，并保留已接纳 Condition 身份来源。新增身份仍由宿主分配。

## 2. 技术改造与兼容

`integration_v21.py` 集中五目录、累计 Review、显式编辑调度和版本继承；`materials_v21.py` 使用 ref+正文 SHA 稳定路径及每材料复用索引，任务只写轻量导航。公共 context_index/read_context 的语义未改。

State 使用定点 draft 查询，Condition 最大编号保持跨 run 边界；历史权威文件按 hash 只恢复缺失/改变对象。Workspace inventory 在 local/protocol/HTTP/app 一致增加可选 prefixes，无参保持原行为和 capability。输入冻结与所有已接纳历史输出仍受保护，不扫描无关旧 attempts/audit 来收集当前交付。

状态 view 不再复制全部上游正文；阶段结束后待编辑仅保留技术失败/无候选/局部接纳不完整批次的目标，待补研显示最终剩余 gaps，不把已经执行完的历史请求继续标为待办。这些状态不替代 agent 的经济覆盖判断。记录宿主 spans 的 monotonic 耗时和 UTC 边界、SDK 研究/复盘墙钟、物化复用/索引/枚举字节/接纳次数。不同 owner 并行与 Pilot 子区间不能直接求和当成流程总墙钟。

Pilot audit 保留原完整保护范围，使用 SHA 清单和工作区外磁盘恢复副本；复盘修改/删除受保护文件仍恢复，越界新文件仍移除。Planning 定向恢复保持单调编号、总预算最多四次、一次补救，只隔离失败派生上下文并保存 SHA 清单。MAINTAIN 研究/复盘逐请求显式刷新完整 MCP transport。

新 run 固定 orchestration_revision=2 和 Review schema hash；旧活跃 run 明示需要新 run，旧完成 run 保留原终态。正式 v2/legacy 默认和 MAINTAIN 单节点合同保持。本轮不修改 prompt/skill 或上游资产，没有 deployment。
