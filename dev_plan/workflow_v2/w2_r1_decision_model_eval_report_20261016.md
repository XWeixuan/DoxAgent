# W2 R1 决策模型评测：每 8 条 Policy 最多选 2 条

日期：2026-10-16。按用户最新指示，**本轮只完成百炼 decision-model-preview，JEV 暂缓**。qwen3.8-flash / medium 使用上一轮相同 20 条 Case 的全量回执，没有重新调用。

## 1. 结论

**本次“每组 8 条 Policy，编码为至多 37 个集合选项”的百炼 decision model 版本不适合直接替换 W2 R1。** API、分组覆盖与结果接收都成功，但模型表现出严重空选偏置，漏掉了多项 scope 明确覆盖的事实。

| 指标 | qwen3.8-flash / medium，旧全量基线 | decision-model-preview，本次分组 |
|---|---:|---:|
| Case 数 | 20 | 20 |
| API 成功／结果完整 | 20 条旧回执 | **407/407 分组成功，20/20 Case 完整** |
| 非空召回 Case | 11/20 | **1/20** |
| 召回 Case-Policy 对 | 17 | **1** |
| 与 qwen 集合完全一致 | — | **9/20，45.0%** |
| 空／非空判断一致 | — | **10/20，50.0%** |
| qwen 候选覆盖率 | — | **1/17，5.9%** |
| 输入 token | 632,007 | **1,648,538** |
| 输出 token，含推理 | 95,195 | 不生成输出文本 |
| 输入＋生成输出 token | 727,202 | **1,648,538，约 2.27 倍** |
| 按公开价估算本批费用 | **¥0.475554** | **¥0，当前限时免费** |
| Case P50 墙钟耗时 | 75.1 秒 | 37.1 秒，含分组及限速等待 |

分组选择分布为 **406 次 NONE、1 次单选 P3，没有一次双选**。唯一召回来自编号 16 的 AEP Wyoming 项目 Policy。其余 qwen 非空 Case 均被转为空集。这里的“成功”只表示接口及身份契约完整，不表示判断正确。

已对全部 **11 条不一致 Case、16 个分歧 Policy**进行语义复核：

- **11 项倾向于百炼漏召**：事实已明确落在 scope 或其明确纳入的相关线索内。
- **4 项倾向于 qwen 多召**：把交期、传闻撤回或接口规格扩展成 scope 要求的具名项目／正式配置事实。
- **1 项边界有歧义**：scope 把“相关观察”与“命中条件”混写，暂不强制选边。

因此既不能把 qwen 当作 Gold，也不能把本次大面积空选解释为模型纠正了 qwen。该结论只适用于本次提示词与 37 选项编码，**不能外推为所有 decision model 或所有编排均不适合召回**。

## 2. 数据集与基线

复用此前冻结的 20 条 Case：历史 R1 召回非空／为空各 10 条，BE 6、INTC 5、MU 5、RKLB 4。它们来自本周生产 Case，抽样规则、完整消息、原 Policy 投影和 qwen 回执均保留。

原 30 条样本中的编号 11 没有完整 qwen 全量 usage，故沿用上一轮已经选定的原编号 **1–10、12–21**，不因本轮模型结果重新抽样。每个 Case 的 Policy 数量 **45–264**，合计 **3,186 条 Case-Policy 输入，407 个分组**。本次编号与原编号都在 CSV 中。

只使用冻结消息与冻结 match_scope，没有查询新消息、修改 scope 或加入当前外部事实。旧回执只用于比较，不改写历史 Case。分歧复核也只依据这套输入和现行 R1 规则，不把外部常识或后来事实补入消息。

## 3. 编排与提示词设计

### 分组和选择

1. 按原 Policy 顺序连续切分，每组最多 8 条；最后不足 8 条不补齐。分组无遗漏、无重复。
2. 每组给 Policy 分配本地编号 P1…P8，保留 `policy_id`、`title`、完整 `match_scope`；完整 `source_message` 每组均注入。
3. 决策 API 的 `choice` 原生是单选，因此把合法召回集合编码为选项：NONE、所有单条、所有双条。8 条时共有 `1 + 8 + C(8,2) = 37` 项；最后小组按实际数量生成。
4. 每组只调用一个 `choice` 问题。NONE 映射为空；单选／双选映射回原 Policy ID。**没有概率阈值，没有按 confidence 拦截，没有 LLM 合并或排序。**
5. 全部组都得到有效 typed choice 后，Case 才形成去重并集。并集不全局截到 3 个，避免混入另一套排序规则。缺组或非法 ID 标记为结果不可用，不折叠成空召回。

接口契约参考[百炼决策模型 API](https://help.aliyun.com/zh/model-studio/decision-model-api)：`state + questions`，`choice` 返回固定选项及概率，不生成解释。37 个选项低于官方 255 项限制。

### 提示词如何对齐当前 W2 R1

完整评测提示词见 [decision_prompt.md](../../eval/w2_r1_decision_20261016/decision_prompt.md)，来源快照是 [原 W2 R1](../../eval/w2_r1_decision_20261016/source_w2_r1.md)和 [Core](../../eval/w2_r1_decision_20261016/source_core.md)。没有修改生产 prompt 文件。

保留的业务标准：

- 只问“消息中是否存在具体事实，本身属于 match_scope 描述的现实观察”。
- title 只辅助理解，不能扩大或缩小 scope；语义一致即可，不要求相同措辞。
- scope 明确纳入的前置状态、辅助观察、相关线索可以召回。
- 共享公司／产品／行业不够；需要推演“可能进一步影响”的不召回。
- 保持计划、否认、传闻等事实状态，不判断 NEW/OLD、Condition HIT 或交易。

改动仅用于评测任务适配：原每 Case 最多 3 个改成每组最多 2 个；无匹配选 NONE、1 条选单条、至少 2 条匹配时选与核心事实最直接的 2 条；不凑数。原自然语言 `reason` 改为 typed choice，**不伪造决策模型没有生成的理由**。这也说明它不是无需调整输出契约即可替换现有 LLM 的入口。

### 调用安排

使用隔离容器，镜像固定为与 qwen 基线相同的 `doxagent-v2:main-e929134d`，不挂载生产数据卷。百炼继续使用原 Scheduler 的 key，未使用此前 StepFun 专用 key。

每批 15 个 Case，余下 5 个一批；每个 Case 逐组调用，跨 Case 并发，最多 15 个 HTTP 在途，全局上限 **6 请求/秒**。请求限速用于控制官方 RPM/TPM 配额内的测试负载，因此 Case 耗时包含调度与限速等待，不能当作模型单次延迟。

百炼旧域名 `dashscope.aliyuncs.com/compatible-mode/v1/systemone` 实测 404；使用官方支持跨业务空间 key 的试用域名后成功：

`https://trial.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/systemone`

这是[官方试用域名](https://help.aliyun.com/zh/model-studio/base-url)，仅用于本次测试，没有修改生产 endpoint。正式生产部署仍应考虑业务空间专属域名。

每组最多允许 2 次 transport attempt，仅重试 429／5xx／传输错误，不修复或重跑不喜欢的判断。**本次实际所有 407 组一次成功，没有触发重试。** timeout 为 60 秒，所有成功请求均低于 1 秒。

运行时间为北京时间 **21:03:34–21:04:46，约 72.6 秒**。第一批 52.4 秒，第二批 20.2 秒。

## 4. 一致率与耗时的具体含义

历史非空组：集合一致 **1/10**、空/非空一致 **2/10**；历史空组：集合与空/非空一致均为 **8/10**。整体 45% 集合一致主要由空样本贡献。

qwen 的 11 个非空集合，没有一个被完整保留；17 个 qwen Case-Policy 对仅保留 1 个。与此同时，百炼没有新增 qwen 之外的候选，因此本次差异也不是“分组预算变大、多召回合理对象”造成的。

| 耗时指标 | qwen 全量 Case | 决策模型分组 Case | 决策模型单个请求 |
|---|---:|---:|---:|
| 平均 | 79.9 秒 | 33.3 秒 | 0.381 秒 |
| P50 | 75.1 秒 | 37.1 秒 | 0.384 秒 |
| P95 | 171.6 秒 | 49.5 秒 | 0.586 秒 |
| 最大 | 242.9 秒 | 52.3 秒 | 0.964 秒 |

接口报告的服务端 P50 为 **201.3 毫秒**，与客户端墙钟是不同指标。新模型的前向很快，但本编排每个 Case 需要 **6–33 次请求**，且受全局限速影响。qwen 基线来自当天较早时段，不能用这一轮结果隔离网络／服务时段的因果影响。

本次没有任何一组达到双选，故明确漏召不能归因于“选满两个后截断了第三个”。Intel 爆炸等漏召组的 NONE confidence 还高达 0.96；高 confidence 也不能替代语义正确性检查。

## 5. Token 与费用

按全部 20 条完整 Case 和全部 407 次请求统计，没有缺失 usage。

- 决策模型实际输入：**1,648,538 token**。模型不生成文本，官方也未提供生成输出计费项。
- qwen 旧基线输入：632,007；输出含推理：95,195；总计：727,202。
- 决策模型输入是 qwen 输入的 **2.61 倍**，计量总 token 是 qwen 输入＋输出的 **2.27 倍**。减少推理输出没有抵消完整消息、指令和集合选项在 407 个分组中的重复输入。

根据[百炼该模型当前价格页](https://help.aliyun.com/zh/model-studio/decision-model-preview/)，北京和新加坡均为**限时免费**，因此这批按当前公开价计算为 **¥0**。这不等于未来持续免费；官方没有公布活动结束后的单价，本报告不编造长期成本。

qwen 的旧基线按北京公开单价计算：普通输入 ¥0.8/M、缓存命中 ¥0.1/M、输出 ¥2.7/M，缓存命中为 410,112 token，总费用 **¥0.475554**。公式为：

`((632007 − 410112) × 0.8 + 410112 × 0.1 + 95195 × 2.7) / 1000000`

来源：[qwen 百炼模型价格](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)。上述为 usage × 公开价的估算，不是账户账单。探测请求独立保存，不混入正式 407 次样本；其中成功百炼探测同样处于限时免费。

仅作盈亏平衡计算：若将来按输入收费，本编排的每百万输入单价需低于约 **¥0.2885**，才能低于本批 qwen 实际缓存口径的 ¥0.475554。此数是基于本批 token 的计算，不是预测售价。

| 20 | AMD Verano LPDDR / 代理 CPU | **双方各有 1 项不合理** | CPU 代理用途与服务器 LPDDR 是前一 scope 的直接线索，百炼漏召；但 LPDDR 接口不等于每机已安装总内存／生产 BOM，qwen 对更窄“每机配置”scope 的召回偏宽。 |

这里最有业务意义的两类问题是：

1. **百炼本版本把明确相关事实大面积排除。** 特别是标题中的事实、scope 的显式辅助线索、重复但仍相关的事实和负向状态，不能被当作“不够 HIT”而拒绝。
2. **qwen 也会越过 scope 的限定条件。** 例如把未来发布时间的撤回推成正式产品生命周期决定，把接口能力推成实际内存配置，或者承认缺少具名项目仍用交期作召回依据。

上述是语义复核结论；决策模型没有生成解释，因此不能从结果反推它内部究竟采用了哪种错误理由。

## 7. 对方案的解释边界

本轮验证的是 **8 条一组、37 个集合选项、完整 scope 放在 state 中并由本地编号引用、原生 choice 直接取值**。同时改变了模型、提示词形式和候选预算，无法把结果变化单独归因于某一个因素。

37 选项会把单 Policy 判断转成集合选择，包含编号引用、多个条件同时成立以及“最直接的两个”的排序要求。这个编码在接口上合法，但本次严重 NONE 偏置说明它没有在当前任务上成功工作。不能据此断言“所有不生成文本的决策模型都无法理解 scope”。

后续更值得单独验证的是 **8 个独立 noul 问题，将每条 scope 直接绑定到对应问题，再由编排阈值／排序取最多 2 个**。它更接近现用 JEV 的独立判断方式，但会引入阈值与截断规则，是另一套实验。**本轮未擅自追加第二轮全量模型测试，也未给它宣称效果。**

当前没有上线或修改生产 W2 R1；建议保留 qwen 现行入口，先处理 scope 中召回／触发边界混写，并在后续独立实验中评估另一种 decision 编码。

## 8. JEV 状态及交付文件

代码确认消息总线现用 `typesafe/jev-1.13`，通过 `https://openrouter.ai/api/alpha/decisions` 调用。现有分发是每 ticker 一个独立 noul、阈值 0.5；本次原计划用相同模型和渠道测试集合 choice，并未升级到 1.14 或其他版本。

本地及远端消息总线 key 的探测均返回 **402 / Insufficient credits**；用户随后明确要求“先完成百炼，JEV 先不管”。因此 JEV **没有 20 条正式测试结果，不计算一致率、token 总量或费用，也不把 402 当空召回**。该余额异常也会影响现用 JEV 通道，但本轮没有调整生产分发。
