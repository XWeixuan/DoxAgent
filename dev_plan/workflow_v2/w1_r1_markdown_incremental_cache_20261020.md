# W1R1 Markdown 事实视图与 Haiku 增量显式缓存

日期：2026-10-20，北京时间。本轮完成本地实现、生产数据只读抽样、成本计算与串行真实调用；未提交、推送、部署或重启生产。

## 1. 已完成的业务变化

先将 W1R1 的 `today_provisional_facts` 从 JSON 数组改为确定性编译的三列 Markdown，每条事实一行，与 published known-event index 使用同一竖线分隔和单元格转义规则：

```text
E723 | 2026-10-19 | Intel计划在Proton兼容层支持XMX加速的XeSS。
E724 | UNKNOWN | 某事实的完整proposition。
```

只有 `provisional_event_id | 日期 | proposition`，没有新加字段、表格框架或重复元数据。日期来自 `candidate.occurrence_date`，为空时显示 `UNKNOWN`，不把入库日冒充事实发生日。保留每条 proposition 全文，仅按现有 `_wire_cell` 规则归一化空白、转义竖线；不摘要、不截断、不删行。

`w1_context.py` 负责编译，W1R1 输入直接注入原始 Markdown，而非再次包进 JSON 字符串。提示词只同步这一输入格式说明，召回业务判断规则不变。W1R2 继续读取选中 Event 的完整原始候选，assertion_state、subject_time、entities 等字段仍在后续细判输入中。

然后将新 Case 的 W1R1 配置为：

| 项目 | 配置 |
| --- | --- |
| 模型 | `anthropic/claude-haiku-5.5` |
| OpenRouter 端点 | `google-vertex/global`，禁用 fallback |
| 推理 | `high`，与已选定的 W2R1 Haiku 配置对齐 |
| 超时 | 保留 W1 的 120 秒，不套用 W2R1 的 180 秒 |
| 输出 | 原有严格 `W1Round1Result` Schema，最多 5 个 Event ID |
| 缓存 | 显式 `ephemeral`，默认 `ttl=1h` |
| 固定块 | **每 5 条事实一个不可变块** |
| 活动尾部 | 0～4 条，全部可见，但不设置缓存断点 |

W1R2/R3、W2R2/R3 保留原通道与配置；W2R1 的 Global/high/1h 配置不变。

## 2. 为何采用追加块，而不是反复整体重建

[OpenRouter 官方规则](https://openrouter.ai/docs/guides/best-practices/prompt-caching)支持 Claude 1h 显式断点：写入 2 倍普通输入价、读取 0.1 倍。最小可缓存长度适用于整个前缀；新增块不足 512 tokens 不妨碍在长前缀后追加缓存。

[Claude 官方说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)指出，缓存可回查每个断点之前最多 20 个块。旧块不变、后面新增块时，可以读取原有前缀，只写新增部分。

本轮输入按以下顺序组装：

1. 固定 core + W1R1 指令 + 输出 Schema，设置 1h 断点。
2. 固定 published reference/index，设置 1h 断点。
3. 已完成的 5 条事实块；不重新分组旧块，在最后一个完整块设置 1h 断点。
4. 活动事实尾部 + 当前消息，不设置断点。

完整块超过 20 个时，在倒数第 21 个块再设置一个 1h 断点，把旧缓存边界的发现范围扩展到约 40 个块；总数最多四个断点，不新增模型调用或状态管理服务。

例如，已有 200 条事实：固定部分为 200。第 201～204 条都在活动尾部；到第 205 条时，前 200 条字节不变，只追加一个含 5 条事实的新块。**活动转固定时不丢失事实，也不把全部 205 条重新收取写入费。**

参考库变化、既有事实修改/撤销/重排、别名变化时，前缀按真实内容改变；不为了命中率隐藏这些变化。没有进程内“已热”状态或跨 Case 共享可变快照：每个请求仍使用本 Case 冻结的全部事实，缓存只优化同样输入的处理。

## 3. 真实生产数据和 token 测量

只读抽取最近五天、每 ticker 最近至多 300 个有冻结 W1R1 输入的 Case，共 **965 个**，覆盖 BE、CEG、COHR、INTC、MU、NBIS、ONDS、RKLB、SNOW。包含 30 份不同的参考视图内容，1542 条去重后的输入事实记录；单个 Case 最多可见 **211 条** provisional。抽样有上限，不能当作这几天全生产吞吐统计。

时间范围为 UTC 2026-10-14 20:38:41 至 2026-10-19 18:56:28。证据是当时冻结的真实 Case 输入，不通过当前数据库事实倒灌重建历史上下文。

使用同一真实 INTC Case、同一参考库、同一指令和消息，仅改变 provisional 表达，读取 Haiku 原生 `usage.prompt_tokens`：

| 输入 | 原生输入 tokens |
| --- | ---: |
| 无 provisional 的相同基础上下文 | 39,578 |
| 加入 16 条 Markdown | 40,893 |
| 加入 64 条 Markdown | 44,900 |
| 加入全部 211 条 Markdown | 54,482 |
| 加入全部 211 条原 JSON 记录 | 76,351 |

因此 provisional 净增部分：JSON **36,773** → Markdown **14,904 tokens**，下降 **59.47%**；同一完整请求的输入下降 **28.64%**。

另用相同 64 条事实、按 1/4/16 条分块，三次原生输入均为 44,900 tokens：本次实测没有观察到文本块 JSON 包装计入模型输入的额外 token，不应人为假设每个块固定收费几个 tokens。

这些计数探针将输出上限设为 128，仅用于原生输入计数，部分输出正常因上限截断；不把它们计入完整研判成功率或质量比较。另行进行的完整研判保留 16384 上限并验证正常结束。

## 4. 阈值计算与默认值

用原生 token 差值校准本地 cl100k 计数：Markdown 比例约 **1.3660**，样本每条编译事实估计均值约 **71.48 Haiku tokens**。全体 965 Case 的回放用逐行 token 权重计算，非按统一字数估算。只有探针和真实调用是原生实测，其余大量历史输入为校准估计，不冒充逐条调用模型取得的精确 token 数。

顺序回放真实到达序列，区分 ticker/参考版本、已有固定前缀是否相容以及一小时闲置过期；扫描阈值 **1～256 条**。Case 创建时间作为调用时刻代理，因此队列延迟、服务端缓存驱逐和冷启动并发会影响实际费用。比较是样本回放的条件最优，不是全市场通用常数。

计费公式（以普通输入 token 单价为单位）：

```text
策略成本 = 0.1 × 读取token + 2 × 写入token + 1 × 未缓存活动token
```

同一参考内容持续使用时，按读取计价；一小时过期后按重新写入计价。整体重建策略每次推进边界都重写完整固定事实；追加策略优先读旧边界，只写新完整块，超过回查窗口则重新写入。

| 策略 | 每批条数 | 此样本的估算输入费用 USD |
| --- | ---: | ---: |
| 整体重建 | 1 | 0.860876 |
| 整体重建 | 8 | 0.682311 |
| 整体重建 | **27，扫描最低** | **0.625609** |
| 整体重建 | 64 | 0.669206 |
| 追加不可变块 | 1 | 0.577773 |
| 追加不可变块 | 2 | 0.569548 |
| 追加不可变块 | 3 | 0.567778 |
| 追加不可变块 | 4 | 0.568049 |
| 追加不可变块 | **5，扫描最低** | **0.566501** |
| 追加不可变块 | 8 | 0.573331 |
| 追加不可变块 | 32 | 0.606546 |

此表只比较参考/增量事实输入，未包含各策略共同的消息正文、固定指令和输出费用，不能称为全生产总账单。Global 当次普通输入价为 $0.10/M；所有真实测试输入均低于 100k 分档边界。

采用默认 **5 条**，相对样本内最佳整体重建约省 **9.45%** 的上述输入费用；比 4 条低约 0.27%，说明 3～5 条附近很平坦，重要收益是追加复用而非精确卡住某个条数。配置可通过 `DOXAGENT_PERSISTENT_RUNTIME_V2_W1_PROVISIONAL_CACHE_BATCH_SIZE` 调整，但不增加自动调参控制器。

## 5. 串行真实调用与缓存效果

先用 4 条配置探索 9 次，再使用最终 5 条配置回放同样 9 次；全为 OpenRouter Global、高推理、生产适配器。两轮完整研判共 **18/18 成功**，均通过输出 Schema、Event ID 所属输入集合、正常结束检查。

最终轮 9 次加权输入读取占比 **99.00%**；其中同一参考版本的 8 次为 **99.18%**。9 次费用 **$0.00706411**，按相同输入/输出 tokens 全部普通输入计价为 **$0.04952410**，节省 **85.74%**。这是已经热好的测试序列，不是长期生产必然收益。

包含真正冷写入和参考版本切换的首轮，9 次加权读取比例为 **79.08%**，费用 **$0.02526678**，同 token 无缓存重算节省 **49.14%**。两轮均逐条按接口返回单价核对，新增写入符合 **1h 的 2 倍价格**，不是默认 5m 写入价。

## 6. 召回差异复核

两轮各有 8 个唯一 Case，和已有 Qwen 基线对比，4 个 Case 候选集合完全相同、4 个不同；重复请求不冒充新的质量样本。不能报告“模型质量完全一致”。逐条复核发现：

- JPMorgan 上调 Intel 评级：双方均召回 E621/E623/E643/E626 等核心事实，第五个辅助候选不同。新模型在 E622/E630 等同一评级过程的附加候选间存在选择波动。
- DeepSeek/Huawei 芯片供应：新模型召回 E712（华为与 DeepSeek 合作设计新芯片）并保留 E443/E358/E1；原 Qwen 的 E529 实为 IMF 场景报告，与此消息较远。这里新结果更直接，不能把不一致自动判为退化。
- On3 球员招募消息：新模型保留准确重复事实 E736，没有加入原 Qwen 的特定球员 E733。当前消息没有该球员身份，精简候选合理。
- Intel 2027 展望：双方保留 E16/E310 等业绩与服务器产品主线；新模型加入 E153 需求缺口，附加 18A 相关候选有波动，原 Qwen 加入分析师目标价 E493。均有较宽的附加召回，核心事实未见明确丢失，但本轮不宣称已证明全量质量等价。

这些差异主要对应换模型后的候选取舍；本轮没有为追求与旧输出一致而修改事实内容或召回规则。更多长期质量评估可沿用保留的冻结样本。
