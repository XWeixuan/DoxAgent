# W3 内部时效优化：工程预算、实现与验收

本轮按专项方案实施。以下预算先按工作量确定，不以旧代码的实测作为合理标准。预算是正常负载下的工程目标，不是已经测得的结果，也不通过增加并发门槛、超时或常驻进程保障。

| 必要工作及典型工作量 | 预期P50 | 预期P95 | 超出时优先查什么 |
| --- | ---: | ---: | --- |
| 内存判断、Future完成回调、事件通知 | 1ms | 10ms | 锁内工作、事件循环阻塞、重复交接 |
| Effect领取与短线程派发，少量索引行 | 20ms | 100ms | 空领取写事务、后台领取挡路、重复读 |
| 冻结输入读取/准备，约1–3MB JSON及少量索引读 | 60ms | 200ms | 重复展开、重编码、编译公共资料 |
| 研究/context绑定与小文件原子发布 | 50ms | 200ms | 跨Case全局串行、无变化文件重复写 |
| Ready领取，现成兼容slot | 10ms | 50ms | 以逻辑状态代替物理resident、领取锁 |
| 无库存时必要fork/resume控制RPC | 150ms | 600ms | 本地SDK启动/恢复、重复配置；不当作推理 |
| 物理进程启动+必要模块与SDK初始化 | 300ms | 800ms | 编译/大量无关模型构建、CPU/磁盘争用 |
| Job受理→启动 | 10ms | 100ms | 人为容量门槛、共享执行器排队 |
| JSON/Schema/引用校验，数KB结果 | 2ms | 20ms | 每次重建Schema、同步读取整库 |
| 回执和业务提交，必要短事务 | 40ms | 200ms | 多次争锁、事务内编码/文件I/O、重复镜像保存 |
| 必要终态通知及释放 | 5ms | 50ms | 提交后再次串行读写 |

单阶段总预算：Trade P50≤0.8s/P95≤2.2s，Operations P50≤0.6s/P95≤1.8s；完整Case P50≤1.5s/P95≤4.5s，保留0.5s余量。各段分位数不可直接相加；最终按逐Case区间并集实测。冷路径单列但不豁免5s。明确的服务端等待单列，应用排队、锁、重试、退避全部计入内部。

既有生产基线是未达标下界：55例Trade/Operations/Case P95=13.96/7.38/21.05s。模块导入包含大量SDK生成模型，当前工作量超过上述预算，不能把它解释成“启动几秒正常”。优先消除重复字节码编译；仍有偏差则继续测量模型构建、SDK控制RPC等真正工作量。

## 已实施的实际路径优化

- READY模板读快路径、未变化公共marker不写；空Effect领取先读探测，实际领取仍在原事务重查并递增租约。已领取实时Effect先启动，不等待后台claim。
- Operations仍先保存不可变模型结果；随后在原业务提交中合并provisional分配、daily记录、事件关联、路由镜像及线程owner释放。大内容预编码在锁外，回滚不消耗E#或留下部分终态；Trade输出/Operations Effect的原子性不变。
- 镜像按最终实际导入图生成checked-hash字节码；不增加常驻预热进程或改SDK模型参数。
- 隔离Worker实际HTTP handler探针：无关inventory占用全局位置200ms时，旧小研究包请求231.13ms且被阻塞；仅删除其外层全局槽位、保留按pack/run锁和取消安全后，同一请求13.23ms、不再阻塞。这是因果机制探针，不冒充生产P95；snapshot/inventory原有串行保护保留。
- 已安装SDK表明`include_turns=False`只控制恢复响应历史，W3仅使用线程ID，因此只在W3 resume显式设置。只读生产线程查询：36轮线程带历史回包1,518,444字节/1.60秒，摘要30,458字节/首读36ms、热读3ms；6轮线程分别397,262字节/252ms与67,873字节/13ms、2ms。没有resume、Turn或模型调用；查询证明回包冗余，不将其全部归为先前5.437秒resume的已证实原因。[官方App Server契约](https://developers.openai.com/codex/app-server/)
- 完成边界复用原256项可丢诊断通道和现有Docker日志轮转，不再为Effect诊断争业务writer、不断新增平面文件；异步phase与owner独立终结。新增gate/SQLite-BEGIN、执行器排队、回执、Future交接标量。真实业务commit后才产生owner终结摘要，不把时间戳提前写入当作执行结束。

生产与最终完整回归尚未验收；原5秒硬指标保持。
