### 实测冷准备仍有明显长尾

该Case准备发生在02:37–02:38，**早于后续补修镜像构建，不能归咎于后续构建**。Python CPU不是整个Native子树CPU，墙钟差额也不能直接等同磁盘I/O。

补修后MU/INTC最慢两例的ready-claim仍约**11–13秒**；这是没有再重启Worker的自然窗口，说明余下问题不只发生在发布瞬间。它们的Future结果交接约0.01–0.02ms，没有证据支持再次把秒级残差归为Future交接队列。
