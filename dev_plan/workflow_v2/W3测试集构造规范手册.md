# W3测试集构造规范手册

版本：2026-10-30。适用于W3决策级历史情景回测。与[升级方案](w3_backtest_calibration_upgrade_plan_20261030.md)配套；本文件规范后续构造，不表示本轮已完成数据重建。

## 1. 构造目标与责任

构造者要回答：“如果我是身处Case时点的W3，面对这条消息，决策前会查什么，原文、Prior和传导中什么信息会改变选择？”准备的是让W3自主判断的事实材料，不是为某个Gold写一份论证。

可信与充分由构造侧负责。不能把采集器没找到原文、操作次数不足或权限问题，包装成消息本身不可靠并交给W3作为拒绝交易理由。也不能虚构原文、时间、订单、价格或“已验证完整”的标记。

本轮目标是有约定范围的历史情景，不要求证明全球信息零遗漏或完全零未来函数，不建设额外harness。标准SDK任务、现有采集脚本、现有研究读取模块和普通文件足够。

## 2. 选集、Gold与标记

1. 以case_key和原runtime Case ID绑定；标题仅校对，不靠模糊标题匹配覆盖身份。
2. 只解析正文主表的案例行，后面的11条runtime映射用于补ID，不再次计数。
3. 移除不是NO_TRADE；不得评分、不得复活旧NOISE，也不得按主题无关擅自删掉用户保留的反例。
4. 用户已经核实过时效性，Gold/Tag直接导入。不得再做时效性裁决、自动调标签、延期评分或以新模型输出改Gold。
5. Gold、Tag、入选理由、旧W3方向和收益只留宿主侧。Web构造Agent与被测W3都不读取它们。
6. 用于寻找消息的事件身份线索可以提供，例如New Street、该日期评级事件；不能附带“应该LONG”或“此条是漏交易”等答案线索。

## 3. Case时钟

每条有一个唯一as_of，作为模型假定当前时点、新闻截止及价格快照时点。

- 有真实时分：按该消息实例发布时间；内部保留原秒与时区，展示到分钟。
- 仅日期，或原始basis=DATE：不能使用数据库补入的00:00/16:00等占位时分。使用原发信源已确认的首发时刻加5分钟。
- 原消息、原接收时间、原Worker启动时间在原始档案中保留；后两者不再成为Agent看到的当前时间，也不因它们晚于as_of制造时效性暗示。
- 时间统一存带时区ISO8601，另给UTC/纽约显示值，处理夏令时；不要从本机时区推测业务时间。
- 用户时效性结论已确定。已有原发时间可复用，只做必要的时钟补全；不再安排独立的“这条是否其实新鲜”研究或淘汰流程。
- 模型/SDK超时用真实时间；Case业务时间不随推理耗时推进，也不自动读到as_of之后的后续消息或价格。

## 4. 恢复原始输入与研究

只读取得指定Case，不扫描全库抽样。远端payload可能是NativeContent引用，必须用现有load/decode恢复后再读body、版本和上游信息。

原始数据档案保持不变，Agent输入单独生成。D1/D2按原绑定版本恢复；如版本晚于as_of，再取当时已有的最近版本。保留原文与现有切片，不让采集模型重写一套“更适合Gold”的研究。

D2真实版本状态留档，不把未知状态硬写成COMPLETE，也不把缺口变成Agent拒绝交易提示。

本轮不交付D3/Policy、历史交易意图、WATCH、PIN及消费状态。不把空状态解释为“从未交易”或“没有任何市场背景”。原W1/W2可保留与消息有关的事实判断、理由、置信；不为缺少Policy另造OPEN或重判HIT。

特殊样本处理：

- New Street及CEG贷款原body为空，在模拟检索中补真实对应披露；原消息标题/空body状态不篡改。
- Snowflake/Evercore保持Barron’s多股票汇编原题，在来源中提供实际相关段落。
- NASA恢复其采购方式、预期受益对象、时间和限制性条款；不能把潜在受益写成已取得订单。
- NBIS Citi是DATE精度，必须先确定构造用时钟，不能把占位时分当事实。

## 5. 模拟Web Search构造流程

### 5.1 准备任务输入

继续使用 `gpt-6-luna/max` 的独立SDK准备任务。提供：Case原消息/ticker/as_of、同一版本AGENTS与Skill、D1/D2可读取入口，以及本规范。允许标准本地文件读取与真实Web Search，不连接生产MCP、IBKR、账户，不暴露Gold、Tag和旧W3结果。

不要只塞入按任意顺序截断的70,000字符研究片段。允许按核心问题读相关章节/Unit，保留可比较的业务背景。

### 5.2 先形成具体检索问题

至少思考以下维度对本Case是否有关；不要求每个维度强造来源或答案：

| 维度 | 应回答的问题 |
|---|---|
| 原发与内容 | 最初公开披露究竟说了什么？正文、作者、发布时间、事件时间和更新分别是什么？ |
| 可比Prior | 此前市场/公司在同一维度相信什么？本条是在新增、修订还是重复？ |
| 量级与传导 | 消息中的金额/规模/期间属于谁？目标ticker如何受影响，业务基数和实际联系是什么？ |
| 关键条款与状态 | 计划、谈判、批准、签约、附条件承诺与已实现结果的区别；累计/新增、单年/多年、份额/总量等口径 |
| 回应与反证 | 公司、对手方、监管、同业或可靠同期报道有什么会改变解释的事实？ |
| 传播与相关背景 | 本条之前已有何种公开信息？是否出现新的条款、纠正、确认或解释？只恢复事实，不替用户重判时效Gold |

检索问题是构造任务的工作笔记，不放入Agent材料作为“疑点清单”或拒绝交易建议。

### 5.3 检索范围与停止

取消最多6次search/open限制。普通Case可按12–20份实质来源的工作量准备，复杂事件20–30份或更多；不要把数量变成放行门槛，也不要拿大量同源转载凑数。

优先打开真正解决问题的正文：原始发布、核心财经报道、此前基线材料、必要财务/业务量级、回应或反证。不是只搜标题的近义词；同一事件的重复转载可以证明传播，但不算多份独立事实验证。

当W3合理会核查的主要事实、Prior、关键条件、经济联系及决定性反证已得到充分交付时停止。少量高质量原文能够完整解决问题时可以更少；不能因为碰到付费墙或用完几次调用，就交一份“原文不可得”的免责声明结束。

付费原文可用既有授权/可访问渠道、原发布者分发副本或能恢复相关内容的合法同篇转载。若某条真实已知但无法取得的关键正文仍会直接改变判断，构造侧继续补材料；不要编造，也不把“请无条件信任”当替代正文的方法。

### 5.4 交付资料

每个Source至少有标题、发布者、URL、可得时间与精度、正文或足够的连续相关原文、必要事件身份。来源文字保留原有“拟议/传闻/条件性/未披露”等事实限定，不能改成确定结果。

允许额外写中性导航或事实整理，但要与原文清楚分开，不能全部变成采集者的简短改写。除当前消息本身，还要交付Case需要的Prior、条款、传导和回应材料。

只排除明显的as_of后披露及后续价格/结果；网页更新晚于as_of时，整理当时已披露部分，剔除新增后文。无需为所有页面取得互联网存档证明，不默认“没有历史存档=不可用”。不伪造原始发布时间或已验证历史快照标志。

## 6. 三段行情准备

准备时在远端拉数据，回放只读文件。复用生产MarketProvider和编译/分时路由逻辑：

| 段 | 数据 |
|---|---|
| daily | 最近5个已完成XNYS RTH日线，直接请求日线 |
| hourly | as_of前24小时真实60分钟线 |
| fine | as_of前4小时真实5分钟线，SMART/OVERNIGHT按时段拼接 |
| supplement | 核心事件早于标准窗口时的必要事件段，终点不得晚于as_of |

不能将10分钟伪装成5分钟，也不以自然日聚合盘前盘后生成RTH日线。剔除跨as_of的完整历史bar，不能把未来OHLC藏进forming供模型读取。所有完成bar的结束时间不晚于as_of。

生成统一market_view文件，清楚标ticker、timezone、observed_at及各段实际粒度。准备侧保存原始请求和采集记录；Agent快照不携带今天的刷新健康、权限、provider未验证等警告。模型可以信任数据，不需要再次审计供应商。

数据不实或关键文件构造失败由准备侧修复，不能虚报完整、合成价格或当作NO_TRADE计分。正常休市及被剔除的形成中末条不是构造失败。

## 7. Agent视图与构造档案分开

推荐数据布局，沿用现有目录习惯：

```text
w3_curated_20261030/
  manifest.json                 # 版本、44条选集、模型/运行范围引用
  catalog.jsonl                 # 用户59条目录、移除信息与原Case映射；宿主侧
  cases.jsonl                   # 44条
  gold.jsonl                    # 44条Gold及Tag；宿主侧
  inputs/<case>/case.json        # 中性消息、上游事实与Case时钟
  inputs/<case>/evidence/
    index.json                  # 中性来源导航，不含web_gaps
    web_search.jsonl             # 可检索事实/来源索引
    sources/S*.md               # 有实质正文的资料
    market_view.json            # 真实三段行情及必要事件段
  research/<version>/           # 历史D1/D2
  preparation/                  # 原runtime、采集回执、审核记录与失败原因
```

只把本Case的中性输入、清洗后的证据、历史D1/D2放进可读workspace或Research MCP scope。不要把dataset根目录、catalog、Gold或preparation整体挂给模型。

不得注入：Gold/Tag、入选理由、旧W3结果/收益、web_gaps、历史状态缺口、采集者交易意见、counterpoint_or_limit、内容“UNVERIFIED/UNKNOWN”审计标签、已淘汰来源清单、would_enter_w3/direct_replay_only、旧宿主拒绝/过期和不支持的业务状态。**删除的是采集/评估侧结论，不是新闻事实里的负面内容。**

不把审计说明放在Source末尾，也不通过raw_document入口把它们重新开放。正文里的自然风险、未知条款、反证、传闻状态必须保留。

## 8. 交付复核与后续评测

构造者确认：选集和身份对应正确；Gold/Tag未交给研究任务；时钟符合约定；原消息未改题改义；主要研究问题已有材料；没有靠转载凑覆盖；没有明显未来内容；三段行情真实且结束时间正确；Agent可见资料无采集侧决策暗示。

这是普通的构造交付复核，不要求额外模型裁判、批准链或最低来源数校验器。失败只定位到实际不可运行的数据问题，不额外制造“风险待审核”状态。

运行前冻结AGENTS、Skill、backtest.md、contract、模型/effort、数据与Gold身份；每Case从公共规则母Thread独立Fork，只做第一阶段决策。拟交易才按生产Skill读取行情；不要求所有NO_TRADE都先看图，也不要求读完所有研究和Source。

结果报44条总集、32条非边缘、12条边缘、9条时效性，并单列7个交易正样本召回及37个负样本误交易。Tag仅用于评估解释，不能成为模型预知答案的输入。不同选集、Gold、时间或证据版本的准确率不可直接当作模型/提示词提升。
