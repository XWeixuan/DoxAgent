# W1R2 输入优化实现与 GLM high 对照结果

日期：2026-10-22。状态：本地实现与真实评估完成；未提交、未部署，未将四个节点一起切换模型。

## 1. 结论

已按照实施方案完成 W1R2 专用事实视图、消息清理、输入版本冻结与下游兼容。20 例优化隐式组首轮全部通过 Schema 与 Event/Fact 引用范围校验。保留全部 240 条 canonical Facts、34 条 provisional 的身份、命题、状态与时间，没有在线筛选或新增模型步骤。

GLM high 同模型配对中，实际输入 token **75,824 → 67,899，减少 10.45%**；按实际缓存命中和输出 token 计算的成功调用费用 **¥0.200827 → ¥0.170185，减少 15.26%**；平均耗时 **6.02s → 4.62s，减少 23.29%**。这些是本次小样本观测，输出推理长度与缓存状态也有波动，不能把全部降幅归因于输入压缩。

默认继续使用有官方支持且实测命中的**隐式缓存**。额外完成 20 例 `cache_control` 探测，端点接受请求但没有证实显式创建；不将该标记加入生产，也不承诺 FlashX 的 1 小时缓存。

质量未发现可确认由字段删除造成的事实遗漏，但仍有核心事实粒度及多股消息范围问题，不能宣称模型质量已经完全验收。尤其第 11 例把盘中报价和收盘结果视为同一次跌势，存在漏判风险；详见第 6 节及逐例审查。

## 2. 实现边界

### 展示副本

新增 `src/doxagent/persistent_runtime_v2/w1_r2_context.py`。新 Case 的视图版本为 `w1-r2-fact-view-v1`，正文规则版本为 `w1-r2-body-v1`。

模型可见 payload 只有 `known_fact_view` 与 `source_message`。后者固定保留 ticker/source_name/title/body；原消息快照不改。事实按 Event 和 Fact 原顺序编译，全部命题保留，空值/SAME/独立 Fact 日期不回填或改写。时间值已明确月份/季度/区间时原样表达；不自明的精度补在时间单元格。反斜杠、竖线及换行使用独立可逆转义，未复用会合并空白的旧 `_wire_cell`。

摘要和 entities 按统一版本规则删除；没有线上相似度判别或 LLM 摘要。人工审查没有发现本批必须通过 Context 才能识别的 Event；不声称所有摘要都逐字冗余，也不从摘要伪造 Fact。正文只清理精确重复标题、已观察 Tom's Hardware 分享栏/紧邻目录及精确 live-feed 导航，未知模板保留。实际样本中正文仅减少 76 个 cl100k 估算 tokens，主要收益来自事实结构。

### 冻结、恢复与消费者

- `factory.py` 发布的新 execution bundle 在 `runtime_models.json` 中冻结新视图标记；新建无 bundle Case 同样写标记。旧 bundle/旧 Case 没有该标记时仍用旧 JSON 分支。
- `service.py` 将完整 Event 对象及清理诊断放在内部 `reference_context`，不发送给模型；原 source snapshot 保留。Fact 允许集合仍来自完整加载对象，不解析 Markdown，也不追加额外数据库召回。
- `round_inputs` 冻结 payload、Prompt、视图/规则诊断、模型实际设置和 Schema hash。已经存在的冻结轮次原样使用；无 journal 的 Case 本地冻结重试也不覆盖原输入。成功/失败回执记录实际冻结模型设置。
- `w3.py` 的 citation scope 与 `w3_execution.py` 的 Event 证据读取新内部快照，兼容旧 `payload.event_details`。`transport.normalize_w1_attributions` 同步兼容内部快照；W3 原始对象内容未缩减。
- W1R3 的父上下文重放沿用统一 renderer，能读取新 user 视图；W1R1、W2 的输入布局及路由不改。
- `bailian_chat.py` 修正一个与本次 GLM R2 接入直接相关的协议冲突：`previous_response_id` 在 `inherit_context=false` 时仅是编排血缘，不应触发“缺少父上下文”。真正要求继承却无显式父消息的请求仍拒绝。
- W1R2 Prompt 只替换数据布局说明，保留既有 NEW/OLD、confidence、Fact 归因标准和本地已有一致性示例。缓存缺失不作为 Case 失败条件，missing cached_tokens 保持不可观测状态。

## 3. 测试方法与基线

数据集：`eval/w12_r2_model_low_20261017/dataset.json`，20 条原始 W1R2 输入。原文件未改，SHA-256 冻结在新 `cohort.json`。

此前已有的是 W2R2 GLM 测试，不能当作 W1R2 输入优化基线。本轮补齐以下调用，共 62 次请求：

1. 原输入 GLM high 20 次。
2. 优化输入、隐式缓存 GLM high 20 次。
3. 优化输入、system text block 增加 `cache_control:{type:ephemeral}` 的探测 20 次。
4. 原输入异常的第 2/5 例各补测一次，原首轮错误回执原样保留。

统一端点 `https://dashscope.aliyuncs.com/compatible-mode/v1`，沿用已授权的 GLM 专用 key，仅进程注入；统一 high、stream、include_usage、max_tokens=16,384、timeout=120s、无 SDK 自动重试。每组先串行 1/2/3/5/7/8 六例验证不同消息复用，再将其余 14 例以最多 15 并发执行；没有用同一消息反复调用来充当串行缓存验证。

原组 instructions/user 文本与历史请求 SHA 完全一致。优化组保留相同历史业务规则及历史 Exact Output Contract，只替换输入布局说明。历史 4/6 的 Prompt 与其余 18 例有一条 NEW reason 表述差异，分别保留；串行六例属于同一个完整 system hash。当前本地已有的“输出一致性示例”不是本轮新增，未混入冻结实验，故本评估是输入布局配对而非当前生产全链路上线验收。

第 2 例原组首轮输出 5 个 reference_ids，超过 Schema 的 3 个上限；第 5 例 120.13s 内没有收到任何 chunk，缺失 usage。补测同参数均成功。无法从一次异常断言原格式导致超时；第 5 例补测缓存几乎全命中，说明服务端缓存状态有变化。成功配对费用不能冒充含失败重试的总账单。

## 4. 实际 token、耗时和费用

### 20 条成功配对

原组 2/5 使用补测成功回执，保留其首轮失败在下一表。缓存率均为 sum(cached)/sum(input)。

| 组 | 输入 token | cached | 输出 token* | 缓存率 | 平均 / P50 / P95 / 最慢 | 费用估算 |
| --- | ---: | ---: | ---: | ---: | --- | ---: |
| 历史 Qwen3.8 Flash medium，仅读旧回执 | 81,064 | 30,976 | 34,527 | 38.21% | 31.74 / 30.01 / 53.62 / 95.45s | ¥0.136391 |
| GLM high 原输入，含2例补测 | 75,824 | 27,136 | 12,569 | 35.79% | 6.02 / 5.17 / 12.81 / 20.07s | ¥0.200827 |
| GLM high 优化、隐式 | 67,899 | 21,120 | 9,227 | 31.11% | 4.62 / 4.58 / 7.04 / 8.12s | ¥0.170185 |
| GLM high 优化、cache_control探测 | 67,899 | 38,464 | 11,775 | 56.65% | 5.81 / 5.27 / 10.15 / 11.34s | ¥0.163219** |

`*` 输出已含推理，不重复加计 reasoning_tokens。`**` 按已公布隐式价折算，不是可证实的显式缓存账单。

与历史 Qwen 相比，优化 GLM 平均耗时低约 85.44%，费用仍高约 **24.78%**。这包含模型变化与跨时段差异，不作为输入压缩收益。原组到优化隐式组的实际输入费用为 ¥0.112844 → ¥0.105596，下降约 **6.42%**；其余总费用改善来自本轮输出长度降低，不能承诺长期同幅下降。

### 首轮和严格同批成功子集

| 组 | 首轮有效结果 | 含失败平均耗时 | 可观测费用 |
| --- | ---: | ---: | ---: |
| 原输入 | 18/20 | 11.55s | ¥0.188953 + 第5例未知费用 |
| 优化隐式 | 20/20 | 4.62s | ¥0.170185 |
| cache_control探测 | 20/20 | 5.81s | ¥0.163219（隐式价折算） |

只取原组首轮成功的相同 18 例：原/优化输入为 58,423/55,278 tokens，平均 5.93/4.48s，费用 ¥0.175166/¥0.138556。这个子集未混入补测，但仍受缓存调度和输出波动影响。

价格采用本次核验的北京公开单价，元/百万 tokens：GLM 输入/隐式缓存/输出 **2/0.57/7**；历史 Qwen **0.8/0.1/2.7**。公式 `((input-cached)*输入价 + cached*缓存价 + output*输出价)/1e6`。不扣优惠、免费额度，不冒充实扣；超时缺失用量不算零。历史 W2R2 的速度/费用不混入本表。

### 输入分项估算

统一使用 `cl100k_base`，与 GLM 原生计费 tokenizer 不同；表内依次为合计 / 中位数 / 最大值，均为 tokens。

| 项目 | 原 | 优化 |
| --- | --- | --- |
| 完整 system，含输出契约 | 56,956 / 2,852 / 2,852 | 61,036 / 3,056 / 3,056 |
| 输出契约分项 | 5,060 / 253 / 253 | 同原，未精简契约 |
| user 实际发送文本 | 38,418 / 1,320 / 9,912 | 27,799 / 882 / 6,198 |
| 历史事实分项 | 24,836 / 612 / 9,209 | 15,088 / 495 / 5,558 |
| 消息正文分项 | 11,533 / 363 / 3,627 | 11,457 / 363 / 3,597 |

user 缩减 27.64%，事实结构缩减 39.25%；新增格式说明增加 system 固定开销，因此 system+user 估算总缩减 **6.86%**，没有把 39.25% 宣称为总输入降幅。原业务 JSON payload 的计划口径为 37,578 tokens，与本表真实传输 user 含包装的 38,418 不同。完整逐 Case 分项及平均值在 `cohort.json`、`analysis.json`。

## 5. 缓存及大 Event

串行六例优化隐式命中 **8,448/24,763 = 34.12%**；首次之后五例为 **39.52%**。后四例稳定命中 2,112 tokens，系统不含 Case 动态字段，已验证不同消息能复用前缀。原输入本来已有固定系统前缀，不把这次优化包装成新增必然命中机制。

显式标记组前六例与隐式完全相同；全量更高命中包含前一轮加热的相同业务输入。没有写入字段/创建凭据，官方显式支持列表未列 FlashX，因此不能认定创建成功或标记提高命中率。本地生产代码维持隐式，探测参数仅存在 eval 脚本。[完整缓存报告](../../eval/w1_r2_input_cost_20261022/CACHE.md)。

E4 的独立 BM25 16/32/64/141 对照，事实视图估算分别 913/1,516/2,718/5,558 tokens，但子集遗漏多项价格时序及反向背景证据。无法用“检索子集没找到 $450”证明全量没有，因此**生产继续发送全部 Facts**。[离线评估](../../eval/w1_r2_input_cost_20261022/BM25.md)。

## 6. 质量与验收边界

- 原输入成功回执与优化组 NEW/OLD 一致 **16/20**；原组首轮成功的 18 例中一致 **15/18**。四个成功配对翻转为 2/8/9/11。
- 优化隐式与同输入标记组一致 **19/20**，第 13 例再次翻转。与历史 Qwen 一致 **19/20**。这些数字是 verdict 一致率，不能当准确率。
- 2 的 Roth/F243、8 的延期/F329/F330、9 的负荷/合同规模，优化结论有更合理的解释；11 的盘中/收盘状态则有漏判风险，不能只说“与历史 Qwen 一样所以正确”。
- 8/15 对多股消息过度聚焦 ticker、13 的新增归因识别、20 的 reason 引用未完整进入 reference_ids，仍是提示词/模型回归点。业务输出 Schema 和路由没有为这些问题放宽。
- 本批没发现由删去 Fact、状态、日期、主体或有效正文造成的可确认误判；无法从 20 例断言所有未来摘要都冗余，也没有把这轮宣布为 GLM 全节点生产业务验收。

[逐例判断、摘要/实体审查及引用变化](../../eval/w1_r2_input_cost_20261022/SEMANTIC_REVIEW.md)。本轮不自主改 gold，不扩大改写业务 Prompt，不重新设计事实判定。
