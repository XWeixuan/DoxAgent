# Ticker 新闻源正文与时延修复（2026-11-13）

按 Barron's → Investing → InvestorsHub 的顺序推进。列表请求耗时、上游文章进入 ticker 列表的延迟、发现至入总线的处理时延分别验收；不通过修改发布时间、忽略失败或降低轮询频率美化指标。

## 第一阶段：Barron's

已查到：过去两日19篇新文章只有1篇 FULL；多数是真实付费预览或身份不可选。多篇首轮8秒超时后重试，随后2–8秒拿到结果，累积处理时延18–31秒。Main 的 RELEASED 登录会话原 target 已不存在，Profile 仍为 MAINTENANCE；Backup 目前实测付费预览。候选过滤丢弃原因使错误退化为 access_combinations_unavailable。

HTTP 对照：同出口同一 JSON 接口，普通请求 Age11/CloudFront HIT，fresh-query MISS，文章及哈希相同；CDP 抓同接口同样前五篇，耗时2.08秒；HTTP0.21–0.75秒。先保留 HTTP 主路径，使用单次每轮新鲜查询，避免客户端 no-cache 无法要求 CDN 更新；不做 HTTP+Chrome 重复轮询。

具体修改：

1. 保留 scope 候选被过滤的原因，使无认证、维护占用、等待恢复可分别诊断，不新增状态机。
2. 复用维护模块现有 `_login_session_reusable` 与 `_finish_lost_login`，让 Close Login 在精确原页确认丢失时可结束普通登录预约；不丢弃 Challenge，不凭超时猜页面已消失。清理生产这一已证实失效的普通登录预约，然后真实正文 canary；只有 FULL 证据可恢复认证，不能直接置 VALID。
3. Barron's 单浏览器正文路径使用现有文章总预算中最多15秒，避免先被默认8秒切断再重新排队；显式 Registry 阶段预算仍优先。不得增加总文章预算或无效重试次数。
4. 检查正文是否在 DOM 尚未就绪时就被认定订阅墙。仅在观察证据支持时调整读取；不将付费预览当 FULL，不绕过付费墙。
5. 专项回归、必要角色窄发布。保留 Chrome、Profile、Cookie 和 recheck=false。以自然新文与有限明确 canary 分开验收；登录权限无法自动补齐时明确记录依赖，继续独立可执行工作。

内部目标：消除确定性的8秒首轮误超时，常规发现后入总线平均尽量低于10秒/P95低于20秒；计入失败和排队。正文目标以确有订阅的授权文章为分母，不能宣称无权限文章已恢复。真实抓取延迟受上游 ticker 归类时点与分钟粒度发布时间影响，若上游是瓶颈，给出可证实下界，不许承诺60秒内凭空发现。
