# W1 Round 1 — Event Candidate Recall

你正在执行 W1 的第一轮：为后续事实新旧判断寻找最值得展开的已知 Event。

W1 的目标是维护一份准确、连续的现实记忆：已经知道的现实不应被重复当成新消息，真正改变现实状态的新事实也不能因为主题相似而被历史事件吞掉。

本轮只负责 **candidate recall**。`published_known_event_index` 是紧凑索引，只能帮助定位可能相关的 Event，并不包含完整 Facts；下一轮会读取你选中的 Event Detail 后再判断 NEW / OLD。因此，本轮不要提前进行新旧判定。

## 你要寻找什么

候选 Event 不是“主题相似的新闻”，而是有合理可能：

- 与当前消息属于同一个现实 occurrence；
- 属于同一现实过程的直接延续；
- 或已经记录了当前消息核心事实的 Event。

先理解当前消息实际上在报道什么，再找候选。重点关注能够识别现实身份的要素，例如：

- 主体；
- 发生的动作或状态变化；
- 对象、产品、项目、客户；
- 当前阶段；
- 消息正文明确给出的时间或关键数值。

文本措辞相似、属于同一行业主题、涉及同一家公司，本身都不足以说明是同一个 Event。

## Published 与 Provisional

`published_known_event_index` 是已经由 Event Library 发布的已知 Event。

`today_provisional_facts` 是今天 Runtime 已经暂时记录、但尚未经过 Event Library 正式整理的事实。对本轮而言，它们同样属于“当前已经知道的现实”，也可以作为候选。

每条 Provisional record 只提供 `provisional_event_id` 和事实候选 `candidate`；使用其中的现实命题、事实状态、时间与实体判断是否值得展开。

## 召回与排序

召回应适度偏向不漏掉真正可能相关的 Event，但不要退化成按主题搜索。

当一个 Event 有合理可能承载当前消息对应的已知事实时，可以选入；如果只是共享宽泛主题，则不要占用候选位置。

按以下优先级排序：

1. 最可能属于同一现实 occurrence；
2. 最可能属于同一现实过程的直接延续；
3. 最可能已经包含当前消息核心事实。

最多返回 **5 个** Event ID，并把最值得展开的放在最前面。

如果当前已知现实中没有值得展开的候选，返回空列表是正常结果。即使列表为空，下一轮仍会负责最终的新旧判断。

本轮只完成 Event ID 召回，不解释新旧结论。
