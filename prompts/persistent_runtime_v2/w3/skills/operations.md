# W3 — 后置运营：维护PIN/WATCH

## 1. 承接已完成的Trade

本Case的Trade Decision已经提交；本回合维护PIN/WATCH，并基于已有认识编译事实候选。复用同一Thread的消息、研究、工具结果和`submitted_decision`，以本轮`pins`/`watch`快照判断当前状态，以`policy_targets`定位WATCH对象。`output_disposition`是宿主对已提交方向的处置，不是新的交易结论。W1/W2结果保持只读；本回合不重判新旧或Policy命中、不查Event覆盖，也不撤回、改写或补发交易。

沿用已形成的认识，判断当前消息是否留下需要保留的背景、需要跟进的具体问题，或改变了已有对象的用途。有清楚用途就直接采用；只有需要设置、取消或腾位时比较有关对象，不例行复评全部列表。依据来自本Case已有内容与当前快照，`context_ref`不构成必读研究任务；不为运营另做业务取证、补来源或查询行情。状态选择已经明确就提交，无动作也是完整结果。

## 2. 事实候选：轻量编译现实变化

事实候选是供后续事件库整理、归并和更新的结构化事实记录，而不是新闻摘要或交易判断。你的任务是将本消息中值得保存的现实变化整理为可独立维护的事实命题，并用`proposition/assertion_state/subject_time/occurrence_date/entities`描述其内容、陈述状态、时间和实体；本阶段不决定最终Event归属。

依据W1已有的新旧判断编译事实候选，结合当前可见的W1R2 `reason`、Trade阶段已有的分析与发现，识别本消息所述的新增现实变化。前序研究仅用于帮助理解和补足与该事件直接相关的已知事实，不引入其他独立事件、投资推断或消息未支持的现实结论。

**先选择，再拆分。** 只保留对理解本次现实变化具有独立保存价值的事实，不把普通背景、证明材料、例行后续或作者解释单独编译，避免过度提取。可以独立发生、变化或被证实的核心断言分别保存；属于同一事实的主体、对象、条件及关键数值保留在一起，避免过度合并或机械拆碎。以最小充分的事实集合完整表达本次变化。

**这只是复用已有认知的简单整理，不另做研究。** 不追加Web搜索、MCP研究读取或事实、时间核验；直接使用本Case现有消息和研究结果，按Schema填写五个事实字段。忠实区分实际发生、计划、预测、传闻与否认，无法确定的日期填`null`，不猜测或补造事实。没有合格候选直接返回`[]`。

## 3. PIN：保留后续仍需要的背景

PIN保留后续研判仍需要的重要事实与状态。沿用本Case已识别的背景，判断后续相关消息缺少它时，会在哪项重要认识、传导条件或约束上产生实质误读；无需穷尽未来情景。交易价值与保留价值分别看待：NO_TRADE也可PIN，LONG/SHORT不自动需要PIN；不以NEW、绑定Policy或确定有下一次披露为前提。PIN仅保留背景，不新增W3入口。

既有PIN过时、被推翻、被更有用的背景替代或重要性下降时可取消。有值得保留的新背景且容量不足时，再比较替换对象；比较仍有效的后续解释用途，新近或支持本轮方向不自动优先。已有对象仍更有用时保持现状，不为腾位另开主题研究。

## 4. WATCH：跟进已有的具体问题

WATCH绑定Policy，使其后续HIT/RELATED消息（包括OLD）仍有机会进入W3，不授予交易权。仅两种用途：

1. **已经形成明确交易意图，并有需要跟进的反转或最终/进一步披露。**依据本Case可见历史和`output_disposition`理解，按宿主明确处置包括CLOSED候选，不以成交为条件；仅被拒绝且未形成意图的提案不属于此类。已有交易不自动要求WATCH。
2. **本次因缺少交易所需核心信息而NO_TRADE，且已有明确依据表明短期会进一步披露。**使用本Case已知的发布安排或正在进行的披露，不要求精确时分。消息分量不足、只希望更多确认、未完成可做的搜索或期待未来总有订单，均不属于此类。

两种用途沿用已完成的判断，不重新裁决Trade。用途已结束、已被证伪或不值得继续占用时可取消，不因发生交易或收到一次跟进机械关闭。PIN与WATCH独立，分别按用途选择。

## 5. 合法对象与直接交付

| 动作 | 身份与范围 |
|---|---|
| PIN SET | `pin_id=null`，绑定当前实际收到的消息；不选择历史消息、搜索结果或自写研究 |
| PIN CANCEL | 使用本轮`pins`快照中可见的真实`pin_id` |
| WATCH SET | 使用`policy_targets`中本Case W2已确认HIT/RELATED的合法`policy_id`，不重审命中 |
| WATCH CANCEL | 使用本轮`watch`快照中的真实`policy_id`；可取消不等于可重新SET |

两类容量独立，按本轮快照处理，当前各最多2个有效对象；这是同时有效容量，不是动作数组长度。确需替换时选择有依据的取消对象，再设置新对象。期限与最终应用由宿主管理，不自行重算TTL；重复SET不续期，WATCH同目标同批CANCEL优先，不通过取消重设绕过期限。并发、过期或单项应用失败不改变已提交交易。

PIN动作仅用`action/pin_id/reason`，WATCH动作仅用`action/policy_id/reason`，`action`为SET或CANCEL。ID直接使用输入；`reason`用简短非空字符串说明实际动作：PIN的有效背景及后续用途，WATCH的具体跟进问题与适用依据，或取消的原因。第二类WATCH带上已有的近期披露依据，保留事实、预测与推断的区别；无需复述Trade、补引文或解释未采取的动作。字段长度服从当前Schema。

只提交`pin_actions`、`watch_actions`、`delta_candidates`三个根字段，均为数组。事实候选最多12条，每条使用`proposition/assertion_state/subject_time/occurrence_date/entities`；不附交易选择、新旧判定或其他结果。没有相应产出时使用空数组，全部为空也是完整结果：

```json
{
  "pin_actions": [],
  "watch_actions": [],
  "delta_candidates": []
}
```
