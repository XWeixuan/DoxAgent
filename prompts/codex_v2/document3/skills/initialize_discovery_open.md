# O3 OPEN Discovery — 双视角补充发现

本文件用于 `OPEN_RESEARCH`、`OPEN_EVENT` 的 Discovery，与 `initialize_discovery.md` 一起使用。通用 Skill 规定发现方法、Lead 成熟度与交付；本文件明确两路 OPEN 的材料责任、补充视角及同一轮内部覆盖回看的用法，不增加节点或输出对象。

你在 Shell Discovery 之后，以不同的核心材料补出已有 Lead 尚未提出的重要事件或关键问题。不是重写一份 D1、逐条编译 Atlas，也不是提前判定交易方向。发现更外侧的可能性与保留核心业务自身的独立变化，都服务于这项任务。

## 1. 按本次任务承担材料责任

先确认真实 owner、`owner_profile` 中的核心材料及其可读映射，按对应分支工作：

| owner | 必须完整理解的核心材料 | 主要补充视角 |
|---|---|---|
| `OPEN_RESEARCH` | C1、C3、C5、`c4f_future_nodes.json` | 公司整体图景、跨域关键变量、近期可能出现的新信息 |
| `OPEN_EVENT` | `c4e_formal_scan.json`、`c4e_network_build` 网络正文、General 与 L1-01 两份 Open Event Atlas | 行动者选择、关系变化与尚未想到的开放事件 |

这不是两种互斥的研究职业。两路都面向公司整体，都能发现内外部问题；区别是由哪些材料承担独立发现责任。核心材料与完整 Shell Lead 包必须通读，其余共享 D1/D2、实体、事件等按问题读取相应完整语境，不要求两路重复扫描所有共享资料。Atlas 的实际入口由任务提供，不从本地文件名猜路径或要求未提供的材料。

Shell 发现已经结束，`prior_shell_discovery` 提供本轮冻结结果；另一 OPEN 的当轮发现不是你的输入，不等待或猜测它会补什么。GLOBAL 汇总各路后完成 Planning、Integration。后续 Build 按分配的 Topic 执行，不因 OPEN 身份重新运行本次发现方法。

## 2. 读全材料，再判断已有发现的实际范围

先从责任材料形成自己的整体或网络认识，再对照 Shell Lead，避免用原有候选的关键词筛选你应该读什么。可以分批阅读、暂记想法，但最终取舍前要完整读完可用核心正文，以及 Shell 包中全部已接纳的主、late Lead 的 `name / lead / ref`；同时理解索引所给的 Shell 范围与缺件情况。标题和条数不能代替正文，宽泛的 Shell 名称也不能证明某项具体变化已经被发现。

Future Nodes 的主要内容在 `future_nodes[]`，formal-scan 在 `entity_relations[]`；空 `report_markdown` 不表示这两个产品为空。network-build 则应读 `report_markdown` 中的完整网络正文，不能因其关系数组为空就略过。同源 `.md` 与 JSON 正文选择一个完整入口即可，不作为两份独立依据。长内容按共同说明无损分页，截断后继续补读；共享 D2 以完整 Unit、共享报告以相关完整章节理解，不删去机制、分量与限定。

区分材料的用途：D1 与关系研究提供有来源和时点的事实、计划及解释；Shell Lead 表示前序已经提出的研究问题，其影响假设不是已证实结论；Atlas 是静态灵感，不是当前事实或已成立的交易规则。保留实际来源与状态差别，不把计划写成已实现。缺失、失败与已接纳的空列表不同；无法取得的部分如实说明，使用可读内容继续，不把缺件当作没有关系或没有机会。

## 3. OPEN_RESEARCH：从整体图景寻找跨域变量与近期信息

把 C1/C3/C5 放在一起理解：公司靠哪些业务形成价值，行业资源与外部需求怎样影响它，当前市场判断依赖哪些未来安排。不要将三份报告分别压成候选清单；要看局部结论之间的联系，尤其是多个 Shell 都可能当作背景、却没有单独研究其变化的共同条件。整体性也包括估值、资金与风险的联系，不只是宏观经济数据，更不是重做完整 D2。

问自己：即使热门需求故事没有变化，什么因素仍能同时改写公司的可交付能力、收益、资金或竞争位置？这个因素是否太宽，落在多个章节之间，因而没有成为实际 Lead？找到后继续落实到谁可能改变什么安排、普通新闻会公开什么。不能停在“资本周期”“供需改善”等抽象标题，也不能因为外层驱动已有人写，就忽略核心业务自身可独立发生的变化。

例如，假设 Shell Lead 已分别关注客户需求与工厂进度，整体研究又显示客户付款安排、供给承诺和扩产资金相互联系。可以进一步构想“对手方改变预付款或履约保障安排，进而改变扩产可融资性与风险承担”的研究问题。是否适用于本 ticker 取决于实际材料；它不要求未来新闻同时确认项目完工、订单和利润，也不只是把原来的需求 Lead 换个名称。

完整阅读每个 Future Node 的时间、未来事项、与目标公司的关系、来源及来源发布日期。先分清已经公布的计划与仍未确定的部分，再考虑节点前后可能出现的提前、延误、条件修改、替代或风险澄清。事项时间与信息公开时间不同；优先发现近期可能改变判断的消息，而不是只筛近期最终完成的项目。远期投产也可能在现在附近出现重要的许可、资金或安排变化；来源只有年份或目标窗口时，不编造具体日期。

Future Nodes 是线索，不是封闭日历，更不是一条事项对应一个 Lead。将不同节点与整体图景连接，寻找尚未被 Shell Lead 承接的共同约束和独立变量；“初产不等于交付”等说明用于理解状态，不自动要求等更晚结果。财报节点只作背景，不生成等待财报发布或经营兑现的交易线索；其背后的业务机制有独立非财报消息入口时，仍应研究。

沿这些整体问题和未决安排主动做必要的 Web 探索，而不是只核对已列出的产品新闻。来源清楚、联系足以说明值得研究时，就可以形成 Lead；净方向、精确比较锚和最低交易边界仍由 Build 解决。

## 4. OPEN_EVENT：让行动者网络与事件原型相互启发

### 先理解连接，再理解参与者为何可能改变它

formal-scan 的关系主体、关系对象、关系类型、关系说明和关联业务或产品，共同说明当前知道哪些连接及其状态。完整阅读关系说明和来源限定，不把平台适配、演示、合作意向、供货承诺与实际采购混为一类。未具名的客户或供应者群体也可以提供有效线索，不为使事件看起来具体而补造名单。

network-build 进一步解释参与者自己的任务、选择权、约束、替代路径和未证连接。沿正文追问：谁为完成自己的目标可能改变安排？谁控制采购、认证、接口、资金或接入条件？外部主体之间的变化怎样先改变共同约束，再传回 ticker？既看直接关系，也看外部—外部联系，不只围绕目标公司的一跳邻居搜索。

网络里提到的每个条件，不都是未来消息必须同时证明的事实。它帮助你识别哪些变化值得继续研究、哪些联系尚未知；不必在 Discovery 证明最终订单，也不能仅凭图上有路径就预定 LONG/SHORT。材料间有阶段或口径差别时，保留来源身份，针对影响线索选择的疑点核实，不静默拼成更强结论。

### 把 Atlas 当作打开问题的原型库

完整阅读 `Open_Event_Atlas_General.md` 与 `Open_Event_Atlas_L1-01.md`。General 打开信息、资本、治理、规则、技术和社会行为等跨行业入口；L1-01 深化计算基础设施中的不同参与者与变化方式，不能只跳读最像本 ticker 产品的小节。全文理解不等于逐项生成：选择确有现实作用点的原型，其余不强行适配，也不设类别或条数配额。

Atlas 的预筛只说明某类事件值得想到，不证明它已发生、适用于本 ticker 或足以交易。原型中的“显著、大规模、正式部署、生产验证”等描述，不直接成为当前 Lead 的硬门槛；还应探索这类变化会以什么具体消息出现，哪些先行决定本身值得研究。既不机械照抄原型，也不因为尚未证明全部经济后果就排除合理线索。

### 在关系与原型之间往返，而不穷举组合

从一项真实关系出发，问相关参与者还能作出什么选择，再借 Atlas 打开未想到的事件形态；也从一个原型出发，回到网络寻找可能推动、承受或披露它的主体。这两种方向可以交替使用，不逐实体、逐关系地遍历所有原型。图谱和 Atlas 都不是白名单：发现新的重要主体或连接，可以通过共享研究与 Web 延伸，分清已有事实和未来设想。

例如，假设 Shell 已有工厂建设 Lead，网络说明工程方与公用设施的作用，Atlas 又提示接入、限载或成本承担变化。可以研究“供电接入条款改变，怎样影响项目成本与可用性”，而不只再写一次开工或延期；也不要求先发生停产。这是材料组合的假设示例，不代表当前已发生该事件。

搜索既用于查清真实参与者和正常披露，也用于发现材料尚未列出的选择。新事实可能只更新背景，也可能打开后续事件问题；不把重述已知事实当新增 Lead，也不因事实已经发生就连同它提出的未来问题一并忽略。

## 5. 用实质差异判断补充，不按标题判定覆盖

将候选与已有 Shell Lead 的现实变化、主要联系和待研问题比较。主题相同但新增了未考虑的选择、不同作用机制或关键结果，可以补充；只是换主体名字、增加同一事实的重复来源，或把原问题拆成更小术语，不构成新的研究任务。这个比较不提前决定最终 Policy 分组。

一个较宽的 Lead 不自动覆盖其主题下所有事件，但也不需要你替它展开所有研究细节。问：后续沿原 Lead 的问题正常研究，是否已经会回答本条想解决的事？以它实际提出的内容为准，不替它想象尚未写出的研究任务。若不会，明确缺少的事件或问题；若只是可复用背景，就不重交。同一外部故事已存在，不能据此删除核心变量的独立变化；一个核心变量已有 Lead，也不意味着所有新的外部入口都已被发现。

对原线索的实质补充，写成本 owner 自己的完整 Lead，保留必要背景并说清多出的研究内容；`ref` 指向相关 Shell Lead 和实际研究依据，不覆写冻结原件。Atlas 可保留为构思出处，但不能替代事实来源；不同 D1 产品的原引用保留各自出处，不因编号相似就互相代替。Planning 可以将新增问题并入已有 Topic，也可以另行研究，不要求它最终成为独立 OPEN Topic 或 Policy。

## 6. 探索后换参照系回看，再交回自己的 Lead

形成补充线索后，执行通用 Skill 的那一轮内部覆盖回看，不额外叠一轮审计。此时看的是“已有 Shell Lead＋本路新增 Lead”的联合内容；重新从责任材料中的业务问题出发，不能只在已经选出的候选之间去重。

`OPEN_RESEARCH` 再看整体图景中的共同变量、跨域联系和近期未决事项，是否仍有重要变化只作为背景、无人提出研究；`OPEN_EVENT` 再看网络的外部—外部联系、共同依赖和两份 Atlas 打开的其他方向，是否仍被第一次搜索的热门题目遮蔽。回看是为了找到尚未成为候选的问题，不是要求每个节点、关系或原型都有输出，也不推测另一 OPEN 会自动补齐缺口。

出现实质遗漏，就回到相关原文或继续必要搜索，再补入有内容的 Lead。核心材料和已有发现已完整理解，重要新增问题已得到表达，继续主要只是重复或缺乏实际联系时，再结束本轮；不以首稿能解析为完成，也不靠凑运行时间或无限穷举证明投入。真实未读材料及重要未决处在既有允许的交接中说明，不伪称已排除。

仍按当前任务写本 owner 的 `name / lead / ref` Lead JSONL 及允许的 late 文件，不复制 Shell 全集，不另交全局议程、Policy 或覆盖台账。完成上述比较与探索后确无实质新增，可以按合同交空集合并简短说明；不为证明双 OPEN 有价值制造重复条目。
