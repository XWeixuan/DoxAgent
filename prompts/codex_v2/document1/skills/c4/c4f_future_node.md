# C4f · Future Nodes 研究技能

## 本阶段要发现什么

Future Nodes 是 D1 为下游提供的**有现实依据的未来信息入口**：从研究截止时点看，现实中的某项活动、决定或进程下一步可能在什么时候产生可观察的新事实，以及它为什么值得目标 ticker 的研究者关注。它不是对全部可能催化事件的预测，也不要求预先确定事件结果、交易方向或 Policy 触发边界。

公司内部路线图只是其中一种来源。好的研究还应发现竞争者、客户、供应商、替代技术、行业规则、项目开发与资本安排中的重要未来节点，即使发布消息的主体从未提及目标公司。真正要交付的是**下一次可能改变我们对相关经济变量认识的观察点**，而非尽可能长的活动日历。

## 从 C1/C3 的研究问题寻找下一次观察点

先实际阅读本轮提供的 C1、C3 完整研究正文：弄清目标公司的主要业务暴露，以及行业如何通过客户选择、供需、技术、竞争、项目和制度条件运作。再参考 C5 识别市场当前关注与仍有分歧的变量；利用 pre-scan Entity Map、横向材料和其他上游资产定位参与者。C5 已覆盖的市场主题不是白名单，未被市场广泛讨论的具体外部进程也可能重要。

阅读这些材料，是为了提出下一步要调查的问题，而不只是摘出其中的未来日期。沿着这样的思路研究：**哪一项经济条件还存在未决信息？哪个外部主体或现实程序能够决定、验证或公开它？接下来可能出现哪个具体决议、进展、里程碑或披露？这份信息又怎样传回 ticker？**

例如，读到行业交付受瓶颈限制，不应只把“瓶颈未来有望改善”写成节点；应进一步找决定瓶颈的设备、产能、标准、许可或客户选择，以及其中已有公开线索的下一次变化或披露。研究也可以从新发现的对象继续向外拓展，不受 C1/C3 既有实体名单限制。

## 主动向外搜索，而不是等待公司公告

本阶段应主动使用可用的 **web search** 扩展候选事件，而不能满足于已有研究摘要、公司投资者关系页面或公司活动日历。从上述研究问题出发，分别检索实际负责选择、制定规则、建设项目、供应关键资源或掌握信息的对象；很多检索并不需要带 ticker 名称。关注它们自己的时间表、公开程序、后续计划、可信报道及近期变化。

同时进行反向发现：在可信新闻媒体、专业行业媒体和外部参与者的信息世界里寻找已经进入日程或有明确后续程序的重要事件，再研究其可能通过需求、成本、供应、竞争选择、技术可行性或行业证据影响 ticker。前一条路径由已知研究问题寻找未来事件；后一条路径允许外部事件带来**上游尚未提出的新研究入口**。二者相互补充，公司自身的重要事件也继续纳入。

搜索的下一步应由信息缺口决定：仍可能发现独立的重要观察点、校正事件时间、辨明事件性质或经济关联，就继续研究；若结果只重复已有事项或增加普通宣传活动，不必为了搜索量继续堆砌。不要以固定来源类别、搜索次数或时间跨度代替研究判断。

## 判断什么才是一个可记录的 Future Node

应有可信的现实基础，支持一项**尚未发生、可辨认的后续事项**：例如已安排的表决或听证、已进入程序的许可决定、具体产品或项目里程碑、技术标准的下一次发布、可信报道中的明确后续客户决策。结果不确定并不影响“下一次有机会观察到结果”成立；但必须分清已经确定的程序与尚无法确定的结果。

研究时要弄清三件事：下一次究竟观察什么、为何有理由认为它会在未来发生、这项观察能够帮助理解 ticker 哪个具体经济条件。这是思考方法，不是新增的输出字段。**事件本身有日期，不等于它有重要信息价值；产业趋势本身重要，也不等于已经形成可定位的未来事件。**

“双方将持续推进多年合作”“技术未来可能普及”通常只是已有状态或研究主题，除非已找到下一次可辨认的评估、披露、交付或决策节点。同理，普通参展、展位展示或泛泛演讲可能只有品牌曝光；若会议的真实议程涉及关键规则表决、产品规格公布、行业重要数据或具体商业决策，则应研究并记录那个有信息意义的事项，而不是一概排除会议。

相反，行业监管方预计公布针对某项规则的审议结果，即使未能预判结果内容，也可能是优质节点。注意信息边界：意见征集截止日是一个程序节点，**不是**监管最终批准日；消息称某企业探索合作，也不等于合作会在某日正式签约。

## 时间：近中期优先，重大远期仍保留

所有时间均相对于任务给出的统一研究 **cutoff** 判定，不以当前系统日期替换。优先研究截止后较近、具备明确观察意义的重要节点，以免一份长远路线图掩盖下一阶段真正值得关注的外部信息；但若重要技术、竞争或产业制度节点在更远的未来有可靠时间依据，仍可保留。时间远近不是机械纳入或剔除标准。

`时间` 按来源精度写出具体日、月、季度、区间、目标年份或明确待公布的下一步排期，并在必要时注明时区与“预计/计划”。如果事件已经开始或部分完成，只记录 cutoff 之后仍待发生的明确阶段。若来源没给出精确日，不要补造精确日；但“待定”也不是把没有下一步的持续经营活动写进清单的理由。

## 来源：核验现实依据，而非寻找官方背书

为每个候选节点核对：所引资料到底支持什么未来事项，谁对这项事实具有知情或披露能力，资料是什么时候发布的。相关主体的公告、政府/监管/标准组织文件、行业会议的真实议程、客户/供应商材料、可信新闻媒体和专业行业报道都可以作为依据；**普通且可靠的媒体报道不需要先取得目标公司官方确认才能使用。**

来源的身份要进入表述精度：已经正式安排的写“定于”，企业宣布的目标写“计划/目标”，媒体有信源的未来安排写“据报道预计”，未决定的结果保持未决定。新闻评论对“可能出现某件事”的自由猜测，不能直接转写为已存在的未来日程；如果报道存在重要冲突或时间不清，再围绕这些具体问题继续核实，而不要求每项机械寻找两种来源。

`来源` 保留可追溯的标题、链接或当前 attempt 可解析的引用；`来源发布日期` 指证据材料的发布日期，不能拿未来事件日期替代，也不能在网页未显示日期时猜造。仅使用截止时点之前可获得的信息；引用沿用本轮可用作用域，不将旧 thread 的 O 别名无依据复用。

## 把研究写成对下游有用的独立节点

一条节点应表明实际的行动者、待发生的动作或结果，以及其已知时间精度。`与目标公司的关系` 需要解释可追溯的经济传导：这件事可能改变哪一类需求、资源、成本、竞争选择、项目条件或行业预期证据，影响成立还依赖什么。不要只写“行业重要会议”“有利于公司发展”；也不要求此时把影响方向确定为 LONG 或 SHORT。

同一事项被多家媒体报道，通常合并为一个节点并保留最有支持力的来源；但若一个流程中的不同决定、公布结果或里程碑会分别提供新的信息，就可以分别记录。拆合依据是**未来会否出现独立的可观察信息变化**，不是要凑节点数量。事件可能影响 ticker，并不意味着可以把外部实体的决定直接写成目标公司已经拿到订单或实现收入。

## 结束与交付

提交前回看 C1/C3 的主要业务及外部研究问题：是否真正检索过它们对应的外部主体与未来程序，是否有重要独立的观察窗口被公司日历挤掉。检查节点是否具体、来源能支持其未来性和时间、经济联系可解释；不因数量少而加入无意义活动，也不为达到确定性无限延后交付。

本节点沿用现有结构化输出合同，仅在 `future_nodes` 中交付五个字段：`时间`、`未来事项`、`与目标公司的关系`、`来源`、`来源发布日期`。`report_markdown` 保持空字符串 `""`，其他公共 envelope 字段按本轮 wire schema 填写；**不输出 Entity Relation，也不产出网络研究正文**。用简体中文，保留必要的专有名称和来源原貌。重要的不确定时间或资料限制可在现有说明位置如实标注，不另增类型、优先级或置信度字段。
