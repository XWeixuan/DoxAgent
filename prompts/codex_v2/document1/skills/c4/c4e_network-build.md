# C4e · Network-build

## 本阶段的建模任务

承接 formal-scan 的关系基础及同 thread 中已经形成的研究，构造一份可供下游直接使用的外部行动者网络正文。关系表交代哪些对象有关；本阶段要解释它们怎样共同使一项经济活动成立、改变或受阻，以及局部变化为什么可能传回目标公司。

你要构造的是可复用的现实模型：外部某处发生变化时，读者知道它会先影响谁的选择、经过什么联系，以及哪些条件决定影响能否继续传导。不是逐行扩写关系说明，也不是把 C1/C3/C5 摘要拼成另一份行业综述。

formal-scan 是研究起点，不是对象白名单或已经完成的因果论证。随着理解加深，可以重新组合关系、继续检索、新增对象、修正旧判断，必要时重新组织整组网络。前一阶段负责发现，并不减少你在本阶段继续发现和核实的责任。

## 围绕现实活动组织研究

先问“这组对象共同让什么事情成为可能”，再决定怎样组织正文。一项活动可能涉及获得可交付的资源、形成能够被采用的方案、完成生产与交付，或使资本愿意承担某类风险。研究主题来自实际运作的问题，而不是预先规定的客户、供应商、竞争者等章节分类。

将 formal-scan 中的关系放回这些活动，理解哪些选择必须相互协调、哪些联系解释的是同一个运作问题。共享一套关键安排的关系可以一起研究；同一主体参与不同机制时，可以在不同章节出现。某项直接关系本身具有独立研究价值，也可以单独展开，无须为了体现“网络”而凑齐多类参与者。

章节范围应足以解释机制，又能保留具体差异。过宽的“行业增长”“技术竞争”会把不同对象和状态压在一起；一行关系单独一章又会切断共同运作。用是否需要另一套现实事实、选择条件和回传解释来决定展开或合并，而不是用主体数量决定。

同时留意跨活动联系。看似分属不同公司的业务，可能使用同一设施、依赖同一资本安排，或受同一技术条件影响。看得更宏观，是解释这种共同安排怎样作用于多个活动；写得更具体，是说明它通过谁、什么资源和什么条件产生作用，而不是给具体关系套一个宏观主题。

## 站到外部对象的位置理解网络

暂时不问“它如何影响 ticker”，先问“它怎样把自己的事情做成”。对关键外部参与者，理解它实际提供或需要什么、为何采用当前安排、有哪些可行选择，以及哪些条件由它控制、哪些由其他对象决定。回传分析应建立在这些答案上，而不是用目标公司的叙事替它决定动机。

上游已经讲清楚的事实可以直接使用。若关键参与者只被写成“客户”“竞争者”或“资本方”，还不足以解释其选择，就转向该对象自己的材料继续研究。搜索可以不含 ticker；外部对象独立披露的活动、技术资料、交易安排和实施条件，可能比目标公司的关系公告更能解释网络。推测的目标或选择逻辑应作为有依据的解释，不冒充主体已公开表达的意图。

例如，研究项目资本方时，先理解它承接哪类风险、通过什么安排获得偿付、何种条件会使它改变投入，而不是先搜索它是否继续支持目标公司。由此发现的使用方信用、合同结构或交付依赖，可能构成原关系列表没有展开的新入口。

把联系写成实际作用，而不只是两个名字相邻。研究谁需要结果、谁作出选择、谁支付或提供资源、谁承担风险，以及哪些安排使各方能够协同。不同角色可能由同一主体承担，也可能分离；只有这种区别影响机制时才展开，不把角色清单变成逐对象填写的表格。

技术、设施、契约与规则同样可能是关键对象。它们的作用在于改变可用资源、兼容性、可承担风险或可行选择，不在于具有人的意图。与其写“某标准有关”，不如查明它在什么使用场景下改变了谁的选择；与其写“融资影响需求”，不如理解怎样的支付与风险安排使一项活动能够获得资本。

寻找真正的共同依赖及其替代方式。若一个关键对象失去可用性，谁的选择会改变？若出现另一条可行路线，原有依赖是否仍成立？约束解除以后，活动能否推进，还是会受另一环节限制？这些反事实帮助你识别真正起作用的联系。一个醒目的短缺或合作标签本身并不说明其经济作用。

把决定这些判断的当前事实研究具体：例如实际采用与技术可适配是否不同、可用能力与宣布计划是否不同、替代方案是否服务同一种用途。涉及规模、能力或时间时使用可获得的对应口径；没有精确数字时，也可以用明确的业务状态解释。需要的是足以区分现实选择的事实，不是让所有对象都填满一套数值指标。

## 从局部变化推演回传路径

在当前网络上主动构想可能改变行为的局部变化，再沿具体联系推演，不只复述已经发生的事件。变化可以来自参与者的选择、资源可用性、需求实现方式、技术条件或相互承诺；从实际机制中寻找可能性，而不是为每章套用同一张催化类型清单。

推演时先讲清楚原来怎样运作，以及什么变化会先影响哪个对象的选择。然后追踪这种变化能否经过既有联系，影响目标公司的需求、供给、成本、竞争位置、项目实现条件或市场理解。关键不是把箭头画回 ticker，而是解释每个必要连接为什么成立，以及在哪些条件下影响会减弱、停止或反转。

网络相连不自动意味着经济因果相连。两个主体同时变化，可能源于共同条件，而不是一方造成另一方的变化；竞争者受限可能促使客户转向其他方案，也可能暴露目标公司同样面对的约束。研究实际的适用范围和替代能力，不把“竞争者受损”默认写成目标公司受益，也不机械为每条路径补一组相反方向。

区分改变经营条件与提供新证据这两种作用。外部事件可以直接改变资源或选择，也可以只是为判断行业状态、技术路线或商业模式提供证据。后一种作用同样值得研究，但需要解释可比性和代表性：为什么这个外部对象的情况能帮助理解目标公司，又有哪些差异限制这种推断。其他公司的结果不能未经论证就代替目标公司的经营结果。

例如，假设目标公司提供现场供电方案。某开发商面对接电延迟，可能转向替代供电，也可能推迟整个项目。网络研究应解释开发商的交付目标、可用技术、资金与实施条件怎样区分这两条路径。资金方、替代设备或使用方自己的变化，因此都可能成为研究入口。这里既不需要等目标公司订单出现才承认相关性，也不能只凭“电力紧张”认定其受益。这个例子用于说明推演方法，不是固定行业模板。

传导不清时，优先补研究具体的 exposure、选择条件或相互依赖。缺少客户身份、技术适用性或替代能力，分别对应不同研究问题；不能用等待目标公司后续收入或利润来代替这些问题。与此同时，有了理论上可能的路线，也不意味着关键连接已经得到证实。

完整网络中的既有支撑事实、可能的新变化和后续经营结果，应当在叙述中分清。它们共同解释机制，但不是需要在一条消息中同时出现的条件包。你可以指出哪里发生变化会产生新的研究意义；是否相对于市场预期达到最低交易充分性，留给后续校准。规模资料用于解释经济作用，不在这里转换为固定触发阈值。

## 识别事实怎样进入消息世界

把有用的网络位置连接到现实信息来源。改变现实的对象、掌握某个事实的主体，以及公开该事实的来源，可能不是同一个。技术安排本身不会发布新闻，它的变化可能由使用者、制定者、实施者或相关研究资料体现；不同来源也可能只看到网络的一部分。

对重要外部研究入口，解释从哪个对象出发可以观察什么变化、谁通常知道这件事，以及可能通过什么实际资料公开。优先使用已经识别的具体主体、文件或来源；只能确认来源类别时，如实保留这一粒度。以信息能力判断来源价值，不统一要求目标公司公告，也不凭想象制造披露渠道或时间安排。

可观察性依照正常的信息生产方式理解。某种内部配置或客户采购粒度未必公开，另一种可见事实也未必保留同样的经济含义。使用可观察线索时，要说明它支持网络解释的哪一部分、不能证明什么；寻找更容易看到的线索，不等于降低对事实含义的辨别。

这些入口帮助 O2 继续发现现实事件，也帮助 O3 理解外部事实可能承载什么变化。它们不是监控词表或交易条件，不需要每条关系都配一条规则，更不需要一篇报道讲完全部传导过程。没有现成事件日程，也不妨碍一个持续存在的现实网络具有研究价值。

## 在研究中修正、延伸与保留不确定性

把研究投入用于真正会改变模型的缺口：一个关键对象究竟承担什么作用，一项依赖是否真实成立，替代是否可行，某项外部事实能说明什么。清楚的上游结论直接作为起点；需要更细状态、出现实质冲突或发现新连接时，再查相应材料。不要把深度研究等同于为每条已知事实追加更多来源。

当检索发现另一种重要安排或参与者，沿它继续研究，并调整网络组织。formal-scan 未列出、既有叙事未讨论，都不是排除理由。也不要因已经形成一条通顺的回传解释，就停止考虑现实中可能改变该解释的替代路径。

将不确定性放在具体连接上。说明现有依据支持到哪里，剩余未知会改变哪个解释，以及什么信息能够区分合理的不同路径。“尚未知道某客户会选谁”不等于“无法研究客户选择机制”；但只知道两家公司属于同一行业，也不足以支持一条有用的回传路径。

缺少完美证据不妨碍交付已经研究清楚的网络部分。有依据但仍待验证的联系，可以保留为条件性推演或具体研究问题；对只靠连续假设才能成立的长链，应缩回实际有支持的部分，而不是用更多条件句掩盖缺口。事实引用贴近所支持的主张，自己推演的结论不冒充来源已经作出的结论。

## 形成完整但不封闭的研究正文

一组网络可以定稿的依据，是下游已经能够理解它所组织的活动、关键对象的现实作用、局部变化的回传机制，以及有用的信息入口。会改变这些判断的关键缺口值得继续研究；不会改变判断的细节可以保留为已说明的未知，不追求全链条兑现或无限增加确认。

定稿前横向回看本轮 formal-scan 的关系基础和上游的重要业务活动：是否还有独立外部入口或共同安排尚未得到解释？一行可以被吸收到一组网络，也可以因缺乏实质关联不进入正文；但不能因为已有几个完整的大主题，就压掉机制不同、需要独立研究的有效入口。对确有新机制的内容增加研究与篇幅，不用固定章节数控制覆盖。

让读者看见跨章节的联系。同一主体或共同约束若影响多项活动，应说明其不同作用，避免把同一外部变化的多条传导误读成彼此独立的证据。保持对象名称一致，必要时用自然交叉引用连接相关章节，不另造节点编号体系。

最后从消费者位置读正文：一条不提 ticker 的新消息到来时，能否找到具体的外部对象，理解现有机制支持怎样的解释，并知道哪一个问题仍需继续研究？这检验的是研究是否可用，不是要求本阶段已经完成命中或交易判断。保留开放研究空间，不把本次未发现的联系宣称为不存在。

## 输出合同

最终交付一个非空白的 Markdown 研究正文，不加新的 JSON 业务外壳，不另交节点／边数组或五字段增量。基础 schema 仅将正文定义为非空白字符串；输出承载与写入位置服从本轮运行合同。

正文采用以下最小结构，章节按实际研究组织，不固定数量：

```markdown
# {ticker}｜外部行动者网络研究

研究截止：{任务给定的 cutoff 与时区}

{简述哪些现实活动组织了这张网络，以及重要的跨活动联系。}

## {一个具体经济活动或现实决策问题}

{连贯的网络研究正文。}

## {另一个需要独立解释的现实问题}

{按实际研究继续展开。}
```

章节正文自然交代关键对象与当前状态、共同运作方式、可能变化与回传、信息入口和影响解释的重要未知。这些是研究内容，不是每章固定填写的字段或必须重复的三级标题。事实与条件性推演保持可辨，引用放在相关论断处；确有帮助时可以辅以小表或简短关系示意。

写出实际研究结果，不复述本 skill 的方法、搜索过程或工作日志。正文应自足地保留解释所需的事实和背景，让下游能从外部对象继续推导，而不需要先重新拼装那张关系表。
